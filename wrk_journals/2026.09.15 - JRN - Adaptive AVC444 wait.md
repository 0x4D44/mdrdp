# Adaptive AVC444 wait

Arthur reports that 0.1.248 improves chroma flicker but still shows occasional
high-frequency flickering. He requested the adaptive wait and integration as
work becomes green. No client process was started, disconnected or replaced.

## Design and initial regression

The fixed wait clears presentation coverage on timeout. An estimator trained
only by presentation completion would therefore never see its slowest samples.
The new design separates bounded timing probes from pending/ready presentation
state; detailed decisions and limitations are in the companion adaptive-wait HLD.

Read-only Fable consultation session `2f1ce994-674b-4d1a-ba9b-c7273f6fecde`
completed successfully. The lead accepted conservative overlap refusal and
combined-update sampling exclusion, but chose a recent high-water mark and no
training from missing observations. Copy completion cannot prove on-glass flicker,
so the proposed copy-based flicker counter was not adopted.

On the initial 0.1.248 tree, surface tests passed 73/73, window 71/71, graphics
65/65. The added `adaptive_wait_learns_chroma_arriving_after_timeout_and_ack`
test then failed at its intended assertion: after timeout/ack at 50 ms and
chroma at 80 ms, the next wait was still only 50 ms. This is an observed
assertion failure, not a compile failure or an empty test selection.

## Implementation and validation

Added a small child module under `src/surface/` and coupled it only to mapped
metadata observation, new deadline selection and probe invalidation. The ready
token, copying, acknowledgements and decoder paths are unchanged. Existing
diagnostic defaults and their two 8 MiB file limits are unchanged.

The attempted worker lane produced no usable measurement or code handoff and
was stopped; the lead implemented the settled contract. No new live timing
distribution is claimed. Constants are bounded policy choices for a live retest,
not a measured optimum for Temper.

Observed mutation failures for all nine added tests: zeroing accepted samples,
disabling overlap invalidation and allowing a ninth probe failed all six learner
tests. Removing lifecycle invalidation and replacing the combined-update minimum
with a maximum failed the two corresponding integration tests. Removing only
non-AVC invalidation also failed specifically on that branch after timeout/ack.
All mutations were restored. The original late-after-ack regression had already
failed against unmodified 0.1.248.

After restoration, focused tests passed: 82 surface (including six learner tests),
71 window and 65 graphics, 218 total. `cargo fmt --all -- --check`,
`git diff --check`, and `cargo clippy --locked --all-targets -- -D warnings`
passed. The lead's code-review pass found no required changes. No vendor source
or platform-facing window code changed; no full suite, live visual test or
soak claim is made.
