## The fork, and Arthur's answer

Two independent reviews found the same blocker before a line was written: **the
native transport had no client→server message channel at all.** The video socket
is server→client by construction (`win/send.rs`'s `poll_client_eof` peeks and
never consumes) and the input channel is frameless, where an unknown record kind
is terminal — which the client reads as session death. So clipboard sent
upstream to a 0.4.0 host would have killed keyboard, mouse and the session, and
the parent HLD §6's "old peers stay safe" held server→client only.

Arthur chose the dedicated auxiliary channel, **and extended it to audio**:
video latency is critical; audio, and even more so clipboard, are lower-priority
traffic that must not back up the video. That is now a settled input for the
rest of the build-out, not just this tranche. Parent HLD §6 amended.

## Done, committed, green

1. **`tools/latency-spike/server/src/aux_proto.rs`** — the channel's dialect.
   Type bytes start at 0x20, deliberately disjoint from `input_proto`'s kinds
   1..=7: a stray byte on the input channel is a valid `MouseMove`, so a
   cross-wiring mistake there injects mouse motion instead of erroring, and
   nothing here may share that hazard. 256 KiB ceiling enforced on send *and*
   receive. LF canonical on the wire. Hand-written `Debug`. 11 tests.

2. **The capability gate** — `stats::Header.clipboard` (SCHEMA 5→6,
   `wire_version` unchanged at 3), `ForwardPorts.aux` + the 9503 forward
   (`src/native/ssh.rs`), and probe step 5 (`src/native/probe.rs`), which opens
   the socket only if the host advertises it and treats every failure as "no
   clipboard, working session". 6 tests. The oracle for "never opened it" is the
   *listener's* accept counter, because a client-side assertion cannot tell
   "never opened" from "opened and closed".

3. **`src/native/clipboard.rs`** — the decision layer. Single-slot suppression,
   canonical-form fingerprinting, `note_applied` read-back, the size gate and
   the direction gates. 17 tests.

4. **`src/native/auxchan.rs`** — the channel's client-side I/O: reader loop,
   writer loop, and the depth-1 keep-latest `Slot` between the clipboard poller
   and the writer. Written against `Read`/`Write`, so it is tested against
   in-memory pipes with no socket. 15 tests.

5. **`clipboard::poll_local` / `apply_remote`** — everything the poll thread and
   the wire reader *decide*, as functions over an `OsClipboard` trait object,
   tested against a fake pasteboard that can fail reads, fail writes, or mangle
   what it stores. 9 tests.

6. **The session wiring** (`session.rs`, `main.rs`) — three threads per session
   (read, write, poll), the bridge seeded at connect, and the direction gate
   hoisted so **both transports read the same Settings choice**. 1 test, on the
   only thing here that can hurt a user: a teardown that hangs.

7. **`auxchan` moved into rhydra** — a pure move. The reader loop, writer loop
   and outbound slot are wire plumbing, not client policy: the host serves the
   same channel with the same loops, and a second copy would be two chances to
   get the teardown ordering or the skip-unknown rule subtly different. It now
   sits beside `framing`, `aux_proto` and `input_proto`, and its 15 tests still
   run on macOS.

**Integrated: v0.1.80** (units 1–4), **v0.1.81** (units 5–6), **v0.1.82** (unit
7). The client half of tranche 5 is complete.

### Five tests that proved nothing, and what the shapes were

The mutation pass earned its keep five times, and it is worth reading as a list
because the shapes recur. **Four were the same shape — a test name claiming a
property the assertions never checked:**

- `closing_wakes_a_parked_taker` passed with the condvar `notify_all` deleted.
  A taker that is never woken simply times out and re-checks, so it reaches the
  right answer a park interval late; only an **elapsed-time** assertion, against
  a park interval far longer than the bound, can tell the two apart. `Slot`'s
  interval became a constructor parameter to make that possible.
- The teardown test asserted the channel eventually stops. A hang is not a
  failure — it is a stall — so it now runs the teardown on its own thread
  against a deadline. Same lesson as the condvar one, one level up.
- The clipboard read-back test used a CRLF mangle. **Canonical-form
  fingerprinting already undoes that**, so the request and the read-back hash
  identically and the test passed whether or not the read-back was used at all.
  It needed a mangle canonicalisation does *not* undo. That one also exposed
  dead code: the failed-read-back fallback set the slot to exactly what
  accepting the payload had already set it to.
- The failed-read-back test never failed a read.

**One was a different shape — a fixture that removed the thing under test:**

- A test queued an oversize and a small payload together to prove the writer
  refuses the first and carries on. The slot is keep-latest, so the second `put`
  replaced the first before the writer ever saw it: the refusal was never
  exercised and the assertion passed on an empty path.

## Two design departures from the HLD, both recorded in it

- **The last-sent fingerprint slot is not implemented.** As a suppression key it
  reintroduces the exact counterexample §5 was written to fix. Canonical-form
  hashing plus `note_applied` close the loop properly instead.
- **A test caught a real ordering bug**: the size gate ran before the
  suppression check, so an oversize clipboard would have re-reported on every
  250 ms poll. Suppression now runs first.

## Getting quench back, and the defect it exposed

quench was unusable when the cycle was authorised — `device`, `pool`,
`display-mode` and `server` all FAIL. **Two stacked faults, and only one of them
was what the ladder said.**

The pool stranding was real and `cycle-device` cleared it. The device rung was
lying: the IDD driver was present and healthy the whole time
(`SWD\MDRDP_IDD\MDRDP_IDD`, status OK). The real fault was session topology —
the console had moved to an empty session 4 while `rhydra-agent` sat in ano's
**disconnected** session 2, and a disconnected session enumerates no displays.
The rig's existing `mdrdp-tocon` task took every rung to `ok` in one step.

Raised as **MDR-BUG-FLUX-00017**. The remedies are opposites — `cycle-device`
drops every session on the host; `tscon` disturbs nothing — and the ladder names
the destructive one. Worse, the correct diagnosis was already in the report,
under `input-desktop` ("or simply that the agent is not in the console
session"), two rungs *below* the symptom the operator reads first. I acted on
the ladder and fired a cycle on evidence that did not support it.

### A decision the server side forces, reasoned through but not yet made

The host needs echo suppression too, and it needs it *before* the listener can
work at all — without it the two ends ping-pong on the first copy. So the
"decide it when the Windows owner lands" plan does not survive contact: the
listener is the thing that needs it.

Three options, and the third looks right:

1. **Duplicate `Bridge` on the server.** Rejected: two implementations of
   subtle, security-relevant logic is exactly the duplication the rules warn
   about.
2. **Move `Bridge` into rhydra as it stands.** Needs `sha2` added to rhydra,
   which today depends only on serde. A new dependency needs Arthur's word.
3. **Move `Bridge` into rhydra, storing the canonical text instead of a
   hash.** No new dependency, one implementation, and *simpler*.

Option 3 is not a workaround — it is better on the merits, and the reason is
that a constraint changed. The prefix-capped fingerprint was inherited from the
RDP bridge, where it exists to bound hashing cost on unbounded payloads polled
four times a second. **The 256 KiB wire ceiling removes that problem**, and with
it the two costs the hash carries: collisions, and the documented blind spot
where a same-length edit past the prefix cap is invisible. Exact comparison has
neither, and at 256 KiB a memcmp four times a second is nothing — the unchanged
case short-circuits on length first.

What it costs: the slot holds content rather than a digest, bounded at 256 KiB
per end per session. That content is already on that machine's clipboard, so it
is not a new disclosure — but the hand-written `Debug` stays, and `log_tag`
(which genuinely needs a salted hash) stays client-side in mdrdp, where `sha2`
already is.

**Next iteration does this, then the listener.** It is a data-representation
change inside one struct, reversible, and breaks no interface outside the crate
— a routine implementation call rather than a fork — but it touches
freshly-integrated code, so it gets its own commit and its own mutation pass.
