## Goal

Stand up the repo and write the build charter for mdrdp: a portable Rust RDP client
replacing Microsoft's Windows App on macOS.

## Decisions taken (before any code)

These are recorded here because they were settled in discussion and should not be
relitigated by a later design pass without raising it as an architectural fork.

- **Protocol from IronRDP, not hand-rolled.** Every one of Arthur's five pain points
  (clipboard death, window geometry after display sleep, latency drift, no visibility,
  performance) lives in the *client* layer, not the wire protocol. Writing X.224/MCS/
  CredSSP from scratch spends months in the one area that is not the problem.
- **One OS process per session.** Matches "each invocation connects to a single server",
  and buys crash isolation and independent clipboard state for free.
- **Portable macOS + Windows, all Rust.** This reversed an earlier recommendation to use
  `objc2`/AppKit and Metal directly — that was macOS-only. Platform code is now confined
  behind traits for the three things that genuinely differ: window policy, credential
  store, hardware video decode. Crate choices deliberately left to the design phase.
- **Session resolution decoupled from window size by default.** This kills the
  window-geometry bug class outright rather than papering over it: if the remote session
  never resizes, a monitor powering off cannot reflow it. Dynamic resize is opt-in and
  fires only on user-initiated resize.
- **Scope:** audio output in; drive redirection, multi-monitor, RAIL, smart-card out.

## The build charter

`wrk_docs/2026.08.14 - PROMPT - mdrdp gauntlet build loop.md` fuses Matt Shumer's
Gauntlet Loop with the fleet's 2L "Light - full flow": 2L is the method *inside* a part,
the Gauntlet is the loop *over* parts and the bar that decides when a part is done.

Two adaptations were needed, and both are load-bearing:

1. **The bar is measured, not aesthetic.** Shumer's original judged a game, where a critic
   can eyeball a screenshot against a reference. An RDP client cannot be graded that way —
   its requirements are about behaviour over hours. So the reference is Microsoft's Windows
   App on the same Mac to the same Win11 Pro host, and critics must produce numbers, not
   opinions. No evidence, no pass; a measurement that did not run is UNVERIFIED, never PASS.
2. **The scoreboard is therefore Part 0.** You cannot run a Gauntlet without a metric. The
   instrumentation and A/B harness are built first and proven by measuring the *reference
   client*. This turns Arthur's "stats" requirement from a nice-to-have into the thing the
   whole loop depends on.

Part 1 is a protocol spike, not a shippable part: what actually negotiates against
Windows 11 Pro over LAN, and whether IronRDP's client-side H.264 path is needed at all at
WiFi-6 bandwidth. It is the largest genuine unknown and it de-risks every architectural
choice after it.
