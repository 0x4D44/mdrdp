## Parallelisation

Four workers on disjoint files (clipboard, favourites, ui, audio), with `Cargo.toml` and
`lib.rs` claimed by me up front so nobody collided on them. That worked well — the only
friction was workers hitting transient compile errors from *my* in-flight edits to
`session.rs`/`window.rs`. The audio worker handled this best: it copied its module into
an isolated crate, validated there, and diffed back. Worth remembering as the pattern for
a worker whose validation is blocked by a shared worktree.

One worker noted, correctly, that my checkpoint commit swept up its in-progress file. No
harm (the blob was byte-identical to its final version) but the lesson is that a commit
in a shared worktree is not a private act.

## Decisions worth recording

**One event loop, two screens.** The launcher was originally written to build its own
`EventLoop`. Reading winit's source before wiring `main` caught that
`EventLoopBuilder::build` sets a process-global flag, so the second build would have
failed with `RecreationAttempt` — at the exact moment the user picked a favourite, which
is the worst place for it. Restructured so `main` owns the one loop and the launcher
borrows it via `run_app_on_demand`. This is the kind of bug that "it compiles and the
tests pass" would have shipped.

**Latency is measured as a proxy, and labelled as one.** Input-out to next-paint is the
only round trip observable from the client alone, and it reads short whenever the remote
repaints for its own reasons. Rather than pretend otherwise, the baseline is frozen from
the first 100 samples and the overlay reports *drift* — which is what the requirement is
actually about, and which survives the noise.

**Cache effectiveness is reported in bytes, not just hits.** A hit rate flatters a cache
that hits often on tiny regions. The test that pins this deliberately constructs 90% hits
saving under 1% of pixels, so the two numbers disagree and the byte measure earns its
place.

**Audio is not advertised when it cannot be played.** If no output device opens, we do
not join RDPSND. Joining and discarding every wave would give the server every reason to
believe audio works while the user hears nothing — the failure that looks most like
success.

## Verification, and its limits

268 tests. Mutation checks on every load-bearing guard: the geometry policy's three
(occlusion, restore bound, in-flight suspicion), the cache accounting's three
(double-count, clipped bytes, per-destination hits), the overlay's clamp, and the README
example. Each produced a real assertion failure, not a compile error.

Two oracles were rewritten after they turned out to prove nothing:

- the overlay overflow test originally asserted `buf.len()` was unchanged, which a `Vec`
  guarantees anyway. Replaced with "the left margin of every lower row is untouched",
  which catches a row wrapping onto the start of the next — and the mutation confirmed
  it, at pixel (0,13).
- the launcher render test counted non-black pixels, but every row paints a background,
  so it passed on a full buffer. Replaced with a text-colour match. The ASCII dump then
  showed "Temper" over "martin @ temper.local", legibly — which is the first actual
  visual confirmation the UI renders anything.

The binary was run: `--help`, `--list`, and the launcher (12s under a timeout, no
panic). **No audio has been heard and no clipboard round trip observed.** The first real
session against `temper` is the test.
