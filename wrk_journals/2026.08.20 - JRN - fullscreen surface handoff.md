# Fullscreen surface handoff

Date: 2026-08-20
Bug: MDR-BUG-FLUX-00008

Kiln, the only target with a physical display, still blacked out after the 0.1.102
surface-switch fix. Arthur also saw a new black flash, while `mdrdp -S` reached 533 decode
errors in 5m21s. Temper and Crucible were clean, but they are headless and cannot exercise
the same display lifecycle.

The aggregate error count refuted the previous fix but did not identify one exact wire
sequence. Code and history exposed two decoder failures with the same repair: alternating
live surfaces reset one shared decoder on every switch, while same-id surface recreation
retained references from the old incarnation. H.264 state therefore moved to one lazy
decoder per live surface, preserved across `ResetGraphics` and dropped on deletion or id
reuse. AVC444's main and auxiliary views still share that surface's decoder sequentially.

The flash had a separate, deterministic cause. `CreateSurface` installs a zero-filled
buffer, mapping exposes it immediately, and the window presented it before any decode
succeeded. Presentation now retains a clone of the last painted output only during that
handoff. Protocol surfaces remain untouched, and the fallback disappears on the new
surface's first successful paint.

The presentation regression first returned transparent black. The decoder regression
first failed after deliberately collapsing the decoder map to one active chain. Both pass
with the fix. A live physical-panel transition remains the final field check; the fleet's
headless Windows boxes cannot provide it.
