# ISO 102nd key recovered from winit's Backquote collapse

**Date:** 2026-08-17 · **Branch:** `task/20260817-TSK-HUM-keyboard-iso-102nd-key-sends-intlbacksla`

## The report

Arthur: the key right of left Shift types `` ` `` in mdrdp; in Microsoft's Windows App
(11.3.8) the same key types `\`. `/?` was fine. First suspicion fell on layout
negotiation or IronRDP; neither was involved.

## Root cause

winit 0.30.13's macOS backend maps **both** corner keycodes — `kVK_ISO_Section` (0x0A)
and `kVK_ANSI_Grave` (0x32) — to `KeyCode::Backquote`, and contains no path that emits
`IntlBackslash` at all (`platform_impl/macos/event.rs`, incl. the deliberate
`0xa => Backquote` arm). So on an ISO keyboard the 102nd key and the top-left section
key are indistinguishable by `physical_key`, our `IntlBackslash => 0x56` arm was dead
code on macOS, and both keys went to the wire as scancode 0x29 (`` ` `` on UK Windows).
The Windows App maps the 102nd key to scancode 0x56 (`\|` on UK Windows) — that is the
parity target.

## The fix

`input::from_key_event` now routes `Backquote` through `macos_backquote_scancode`:
winit's `key_without_modifiers` is derived from the **raw** native keycode via
UCKeyTranslate *before* the collapse, so the two keys still carry distinct unmodified
characters. `input::backquote_scancode` classifies: on ISO hardware
(`KBGetLayoutType(LMGetKbdType())`, same Carbon calls winit links) the 102nd-key
characters `` ` ~ \ | < > `` → 0x56, everything else (`§ ± ^ @` …) → 0x29; ANSI/JIS
hardware always 0x29. Documented trade-off: a PC-emulating Mac layout ("British – PC")
puts `` ` `` top-left, which now arrives as `\`; accepted until the Mac-faithful Unicode
input mode (tracked as a requirement) exists.

## Validation

- Live against quench (UK Windows layout): injected macOS keycodes 50/10/44/42 into the
  session window, Notepad received `\` / `` ` `` / `/` / `#` — exactly Windows App
  behaviour. Screenshot evidence in the session scratchpad (`kbd-check4.bmp`).

## Injection lessons (cost three extra quench sessions)

1. `pgrep -f` matches the backgrounded shell wrapper too — use `pgrep -x mdrdp`.
2. osascript `key code` posts to the *frontmost* app; with the operator at the machine
   the keystrokes silently go elsewhere. Same failure the glass probe hit (board,
   2026-08-17).
3. `CGEventPostToPid` with a **null** event source is silently dropped by the receiving
   app; create the event from a `kCGEventSourceStateHIDSystemState` source (what
   `probe/glass/inject.rs` does) and it delivers.
