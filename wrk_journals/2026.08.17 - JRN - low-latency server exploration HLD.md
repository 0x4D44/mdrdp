# 2026.08.17 — JRN — Low-latency server exploration HLD

Origin: design discussion with Arthur. He raised the Hydra comparison (GDI order
interception made TermServer fast on 1997 hardware; modern WDM/DWM compositing is
prettier and slower) and floated a custom server: H.264 base layer + optimized text
path, with remote terminal use (Windows Terminal / WezTerm) as his hot path.

Key framing that survived the discussion:

- Our own measurements already localize the ~34 ms typing floor on the server
  (client share ~4 ms; LAN 3.3 ms) — the DWMFRAMEINTERVAL journal is the evidence.
- GDI order interception is dead (DX swapchains, DWM composites pixels), but the
  same insight lives at the VT/ConPTY layer for terminals; WezTerm mux ships it.
- Moonlight/Sunshine (both open source, GPL — read, don't lift) demonstrate
  ~5–10 ms LAN glass-to-glass via high-refresh virtual display + low-latency hw
  encode; that brackets what a custom video path can reach.

Wrote `wrk_docs/2026.08.17 - HLD - low-latency server exploration.md`: an
exploration HLD (numbers + go/no-go, not a product design) — P0 `probe glass`
keypress-to-photon probe, P1 four-way baseline (mdrdp / Windows App / ssh+local
terminal / wezterm mux), P2 throwaway DXGI+MF-encode spike outside the workspace,
then a hard decision gate. Server product stays out of scope unless the gate says
otherwise.

Process: lean HLD flow in worktree `task/20260817-TSK-HUM-low-latency-server-hld`;
