# JRN — tranche 6 audio unpark via VB-Cable

## Goal

Make real Windows desktop audio audible through mdrdp by giving each rhydra host a
VB-CABLE render endpoint, hardening the existing WASAPI loopback path, adding deploy
and doctor support, and proving the result on quench before temper.

## Scope

- In: VB-CABLE provisioning, endpoint detection and format pinning, loopback capture
  lifecycle, default-device policy, doctor guidance, real two-tone evidence, and soak.
- Out: a custom audio driver, RDP protocol-provider work, per-session isolation, Opus,
  and wire-format changes.

## Evidence and decisions

- Arthur selected the base VB-CABLE product. Premium cables and a custom driver are
  outside this tranche.
- The landed transport already carries PCM16 audio over the auxiliary channel and has
  a non-gating `audio` health rung.
- The existing Windows loopback implementation was written against the WASAPI contract
  but has not yet run against a live render endpoint.
- The official Pack45 archive downloaded on 2026-08-20 is 1,318,877 bytes with SHA-256
  `b950e39f01af1d04ea623c8f6d8eb9b6ea5c477c637295fabf20631c85116bfb`.
- The base package contains `vbMmeCable64_win10.inf`, its catalog/sys pair, and the x64
  setup program. Its readme requires an administrator install and a reboot to finalise.
- Quench is currently claimed by another fleet task. No mutating host work will start
  until that owner releases it.
- Three independent native reviewers completed critique and mutual refutation. No
  critical issue survived. The HLD now installs before agent quiesce, uses stable PnP
  identity and a crash-safe default-device lease, routes policy through the interactive
  agent, constructs capture lazily, bounds packet/ring behavior, and gives live claims
  numerical oracles.
- Rejected review items: a multi-client reference counter conflicts with the existing
  serialized-session invariant; the red-before-green rule was already explicit.
- The one-pass Claude/Fable review found two critical design errors. `pnputil` cannot
  create VB-CABLE's root device, and a shared 200 ms trim would cut through normal
  RDPSND lead. The HLD now uses the official silent setup and scopes trimming to the
  native ring. It also narrows underrun/gap oracles to continuous render windows,
  preserves the existing source setting, adds latency measurement, strengthens the
  signature bar, defines the video workload, and clarifies loss restoration.
- The single targeted native re-review passed both critical corrections. It confirmed
  the official setup resolves root-device creation while preserving pre-quiesce safety,
  and that native-only ring construction can leave RDPSND behavior unchanged.
