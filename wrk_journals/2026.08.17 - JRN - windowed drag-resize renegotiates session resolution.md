# 2026.08.17 — Windowed drag-resize renegotiates the session resolution

Arthur approved flipping the windowed default from letterbox-only to follow-the-window:
a *user* resize of a windowed session now renegotiates the remote resolution to match,
after a 500 ms settle so a drag costs one Deactivate All round, not a stream of them.
CLAUDE.md's decided-architecture bullet is updated accordingly.

## Shape of the change

- `window_policy::on_resize` now returns a `ResizeVerdict` — `UserResize` /
  `Restore(Geometry)` / `Ignore` — instead of `Option<Geometry>`. The policy was already
  the only component able to tell the user dragging from the system rearranging; it just
  had no way to say "this was the user". Classification logic is unchanged.
- `window.rs` arms a debounce deadline (`RESIZE_FOLLOW_SETTLE`, 500 ms) on `UserResize`
  and cancels it on every other verdict, on display events, occlusion, and fullscreen
  transitions. `new_events` services the deadline and folds it into the existing
  `ControlFlow::WaitUntil` bookkeeping (and now explicitly restores `Wait` when idle,
  where before a stale `WaitUntil` could linger).
- The follow request sends `scale_percent: None` — resolution only; a mid-session scale
  change DWM-blurs non-DPI-aware remote apps (lessons_learnt).
- `follow_request` (pure) skips degenerate sizes and a window already matching the
  session. Encoder ceiling / MS-RDPEDISP bounds stay in `session::service_resize`.
- Explicit `--size` pins: `keeping_stated_resolution()` now also disables the follow, so
  a stated resolution letterboxes under drags. Settings ▸ Graphics ▸ Dynamic resolution
  off disables it too. `windowed_session` tracks the followed size, so a fullscreen
  round trip returns to the user's latest windowed resolution.

## Validation

- Full suite green (554 lib + 13 bin + 5 integration), `clippy -D warnings`, fmt,
  `scripts/check-windows.sh` green.
- New tests failed under deliberate mutations (equality-skip dropped, `--size` pin
  dropped, `UserResize` misclassified as `Ignore`) — six red, then green on restore.
- Live against quench (debug build, windowed 1920x1080): two System-Events-driven window
  resizes each produced exactly one `resolution: requested WxH (scale None)` ~500 ms
  after settling; the session reactivated live at 1600x1200 then 2200x1320, still
  AVC444v2 (decoder survived the surface teardown). Both sessions ended `Graceful`.

## Surprises

- A `quench.lan.example` session opens *fullscreen* from remembered state
  (`state.toml`) while bare `quench` is remembered windowed — the first smoke run
  tested nothing until relaunched against the bare name.
- System Events reports zero `AXWindows` for a borderless-fullscreen mdrdp process, so
  scripted window manipulation only works on windowed sessions.
- The smoke connect kicked a live 19-minute `mdrdp quench` session (one session per
  host); the fleet board was unreachable (403 on every channel) so it could not be
  checked first.
