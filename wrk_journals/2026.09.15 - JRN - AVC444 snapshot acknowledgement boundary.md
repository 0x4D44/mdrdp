# AVC444 snapshot acknowledgement boundary

Arthur reports continued chroma flicker in 0.1.247 on Temper and authorizes a
fix and integration. The existing bug MDR-BUG-FLU-00130 was reopened; no live
connection was opened or interrupted during this investigation.

## Confirmed defect

The producer and presenter share a store mutex only for snapshot copying, not
rendering or platform submission. This is intentional. The 0.1.247 policy,
however, clears its ready latch only when a successful submission acknowledges
the latest producer stamp while the decoder is idle. Continuous traffic can
prevent that condition indefinitely. New luma metadata is ignored while the
latch remains set, so later updates bypass the 50 ms wait.

Local metadata trace, 2026-09-14 UTC, one illustrative sequence (not a latency
distribution): deadline released at 23:07:49.287913; successful generation 5600
submission at .302131, acknowledgement ignored as active; new luma applied at
.302300 and generation 5601 marked ready with zero wait at .302389; generation
5601 submitted at .316290, acknowledgement again ignored as active. Chroma for
the same rectangle was applied at .364112. The window became occluded at
.316828, so this is evidence of bypass, not a recorded on-glass luma/chroma
alternation. Genuine 50 ms deadline expiry also appears in the trace.

The normal startup log identifies 0.1.247, Temper, 2560x1440 and IOSurface.
Rotating diagnostics have no per-line PID, limiting attribution when clients
overlap. No pixel, terminal, clipboard or credential data is retained here.

## Scope

Correct the snapshot/pending-batch boundary without changing ordered decoding,
frame atomicity, bounded region tracking, compositor backpressure or the 50 ms
first-luma deadline. Arthur asked about adaptation: the current policy is fixed,
not adaptive. Adaptive timing remains a separate measured policy change; it
cannot compensate for a completely bypassed wait.

Baseline: `cargo test --locked -p mdrdp --lib surface::tests` passed all 73 tests.
Those tests cover the previous idle/current-stamp contract, not the producer
race found in the live trace.

Regression-before-fix: added
`window::tests::submitted_snapshot_does_not_lose_the_next_active_frames_luma_wait`.
It copies frame A at its 50 ms deadline, starts frame B at 51 ms, acknowledges
A while B's AVC callbacks are active, then commits B. The unmodified policy
fails the assertion: B inherits A's expired 50 ms deadline instead of B's
101 ms deadline. One test selected, one assertion failure, no compile failure.

## Design check

Fable's read-only cross-family consult recommended separate ready tokens and
pending coverage. The lead accepted it after checking coherent-copy gating,
timer-only expiry, non-AVC mutation and surface lifecycle call sites. The
implementation worker owns the surface/window changes; the lead updated the
graphics callback test's acknowledgement argument and owns final validation.

An obsolete token can legitimately be ignored if newer work has already
released another token. The acceptance criterion is not zero ignored acks:
it is that new pending work remains tracked, and a matching submitted batch
retires without producer quiescence. Ready work remains immediately retryable.

## Lead review

Summary: separate ready tokens from pending coverage, preserving coherent copy
and successful-submit-only acknowledgement.

Required changes: **Issue** — `src/surface.rs:touch_presentation` initially logged
the raw pending deadline as the effective wait even when ready work overrides
it. Agree and fix: compute scheduling fields from the effective deadline and
retain the pending deadline as a separate field.

Suggestions: **Nit** — the active-update comment still prohibited acknowledgements;
update it to prohibit copying partial pixels, not acknowledging older snapshots.
Use the existing wrapping-counter convention rather than saturating token reuse.

Questions: none. No deferred defects or speculative refactors were identified.

| # | Item | Type | Action | Notes |
|---|---|---|---|---|
| 1 | Effective versus pending diagnostic deadline | Issue | Fixed | Ready override now governs logged scheduling fields. |
| 2 | Active-update comment and token counter convention | Nit | Fixed | Older snapshot acks are allowed; lifecycle does not rewind the counter. |
| 3 | Busy versus successful test's displayed stamp | Issue | Fixed | Only the successful-submit fixture advances its displayed stamp. |

Three review items fixed; zero skipped or disagreed. The lessons file is past
its curation threshold; no unrelated pruning was performed.

## Focused validation

The lead independently ran 73 surface, 71 window and 65 graphics tests: all
209 passed. The graphics test exercises the actual decoder/handler callback
chain with deterministic decoded input; no protocol implementation changed.

Lead-observed mutation evidence (mutations restored afterward):

- Before implementation, the new active-frame submission regression failed
  because the new frame inherited the expired deadline (one executed test).
- Add pending-deadline/region clearing to a matching acknowledgement:
  `busy_submit_without_ack_retries_ready_snapshot_and_preserves_new_luma_wait`
  fails with `None` instead of the newer 51 ms deadline (one executed test).
- Remove ready-token equality from acknowledgement:
  `stale_completed_snapshot_ack_cannot_clear_a_newer_or_reset_wait` fails with
  `None` instead of ready token `Some(2)` (one executed test).

The worker additionally reports observed red assertions for ready-state early
return, Pending/Retained snapshot-token overwrites and disabled timer settlement,
then restored those mutations. The lead inspected the final branches and reran
the affected modules after its own mutations. No temporary mutation is shipped.

Live visual improvement, adaptive timing, a full-suite run and vendored-crate
suite reruns are not claimed. Vendor source is untouched. The running Temper
session was left alone.
