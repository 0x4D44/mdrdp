# Rhydra metadata-first inferred moves — journal

## 2026-08-24 — intent and architectural fork

Goal: make moves metadata-first, encode only the non-reproducible remainder, and remove the
client's full move-sized staging copy for the common single-scroll case.

The current IDD driver calls `IddCxSwapChainGetMoveRegions` but folds only destinations into its
accumulated final-pixel coverage. It also does not set
`IDDCX_ADAPTER_FLAGS_CAN_USE_MOVE_REGIONS`, so even an old runtime would convert moves to dirty
rects. The current wire-v8 path then rejects moves when their raw remainder exceeds 96 KiB and
carries the accepted move plus all remainder pixels together on the bulk channel. The macOS
client stages every move source into a fresh `Vec`, which is roughly 59 MiB for a full 5K canvas.

The premise changed on inspection: Microsoft deprecated move regions in IddCx 1.7 and guarantees
`MoveRegionCount == 0` on modern Windows. Merely preserving the discarded fields would therefore
have no effect on Quench. This was a genuine architectural fork under the requested process.
Arthur selected bounded, exact vertical move inference using the server's retained previous frame,
while preserving native metadata where older IDD or DXGI still supplies it.

The client canvas is CPU-authoritative. The selected client implementation is overlap-safe
in-place row copying for one move, not GPU-only copying; a GPU-only mutation would diverge from the
pixels used by every later sparse/video composite. Multi-move batches retain staged pre-update
source semantics.

Native helper seats are quota-blocked until 2026-08-27, so the requested adversarial design roles
will run sequentially under the prompt's explicit fallback. A separate Claude/Fable review will
still be attempted once the draft is ready.

## 2026-08-24 — adversarial design review

Three sequential roles reviewed the draft and then challenged the other roles' findings.

- Correctness preserved an exact-adjacent scheduled-baseline requirement across IDD, DXGI, and
  inferred moves. Transport ordering cannot make a skipped source frame replayable.
- Latency reduced complete inference from the best few sampled shifts to one. Missing an
  optimization is safe; multiplying full mapped-region comparisons is not cheap enough.
- Protocol review replaced an underspecified mixed raw/video remainder with one declared completion
  lane per move and required an active timeout check from both socket pumps. An idle missing video
  remainder otherwise had no waiter to wake.
- The early provisional wake survived. It may cause another full presentation snapshot, but waiting
  for the remainder defeats the feature; exactness stays uncommitted and later pixels stay gated.

No surviving finding was critical or unresolved.

## 2026-08-24 — IDD layout v2 and native metadata

The layout regression was observed compile-red before the new current metadata types and selector
existed. A separate move-clamping regression was also observed compile-red before its source/dest
aligned clamp existed.

Layout v2 uses 3632 bytes of each 4096-byte slot page: the original 64 accumulated coverage rects,
then independent current dirty/move counts, 64 current dirty rects, and 64 packed 24-byte moves.
The driver opts into move regions for pre-1.7 runtimes, publishes both current lists under the slot
seqlock, and still folds every move destination into accumulated fallback coverage. Query failure,
input/output overflow, a skipped frame, or unusable visible move geometry selects final pixels.

All 20 focused layout tests pass. The x64 IDD DLL and creator cross-build and link cleanly against
the repository's IddCx 1.6 headers; the produced DLL retains the expected `FxDriverEntryUm` export.

## 2026-08-24 — bounded vertical inference

Four focused regressions were observed compile-red before the inference API existed: upward and
downward scrolls, a moved region containing a small changed tile, and unrelated pixels which must
reject the optimization. The implementation samples bounded vertical shifts across at most eight
large damage regions, exact-scans only the best candidate, and accepts it only when at least 75%
of the destination is reproduced. Its remainder contains every exact mismatch, the newly exposed
strip, and original damage outside the inferred move.

All 18 focused diff tests pass. The Windows server release cross-build also passes with the new
GPU readback entry point, confirming the D3D staging path and inference code compile together.
