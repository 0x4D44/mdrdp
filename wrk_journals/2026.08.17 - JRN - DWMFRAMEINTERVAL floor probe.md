# 2026.08.17 — DWMFRAMEINTERVAL below 15 buys nothing: 60 Hz display is the ceiling

Question (Arthur): can we set DWMFRAMEINTERVAL even lower than 15?

Probe: set it to 5 on quench (sudo session, verified "DWMFI now: 5" by
screenshot), reconnected, reran the drag workload.

| | DWMFI=15 | DWMFI=5 |
|---|---|---|
| drag frame-gap p25/p50/p75 | 15.5 / 16.0 / 18.8 ms | 15.1 / 16.0 / 17.7 ms |
| drag RTT p50 | 12.3 ms | 13.6 ms |

Identical cadence: the session's virtual display runs at 60 Hz (66 Hz on the
second controller — `Win32_VideoController.CurrentRefreshRate` read in-session),
and DWM cannot compose faster than the display it composes for. 16 ms is the
floor; registry values below ~15 are dead weight.

**Value restored to 15** (verified "DWMFI now: 15") so quench stays on the
documented setting; the journal and memory baselines remain true.

Going past 60 fps would need a higher-refresh virtual display (IddCx-class
virtual monitor driver territory) — far into diminishing returns for a client
whose remaining latency sits in the server's input→composite path, so parked.

Conditions: quench LAN, 1920x1080, AVC444v2, mdrdp 0.1.44 trunk build, 75 s
scripted runs, 2026-08-17.
