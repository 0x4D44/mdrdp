# Journal — 5K IDD zero-frame diagnosis

## 2026-08-20

- Arthur's 5120×2880 native session showed only tartan. The live session remained at `0 frames / 0 B` despite a healthy display mode and generation-3 IDD pool.
- Pool creation proves the driver acquired at least one swap-chain surface. `SharedFramePool::ProcessFrame` invalidates a slot when the GPU-copy event query misses its fixed 2 ms deadline.
- A standalone D3D11 probe on quench measured 100 warm 5K BGRA copies: min 2.001 ms, median 2.095 ms, p95 6.815 ms, max 6.848 ms; 100/100 exceeded 2 ms. This confirms MDR-BUG-FLU-00025's root cause.
- Chosen fix: a pixel-scaled deadline, 2 ms at 1080p and capped at 16 ms. This keeps the wait bounded while giving 5K 14.223 ms, more than twice the measured tail.
- Two adversarial reviewers and Claude/Fable found no critical issue. Surviving findings tightened overflow assertions, runtime wiring, elapsed timing, mutex comments, package identity, and the live acceptance oracle.
- Red proof: with the new assertions and the old fixed 2 ms rule, `idd/build.sh` failed the 1440p (`2000 != 3556`), 5K (`2000 != 14223`), and extreme-size (`2000 != 16000`) assertions.
- Green proof: the implemented helper, stored runtime deadline, and pre-submission QPC sample passed `idd/build.sh`, including both PE sanity checks. Server library tests passed 299/299 and workspace formatting was clean.
- Independent code review found no Blocker, Issue, Nit, or Optional item. The simplicity pass retained the one pure helper and one per-pool value; no abstraction or dead code was added.
