# Clipboard file copy

- Started a separate worktree from `origin/main` for bidirectional files and folders over CLIPRDR.
- Implemented local file snapshots and remote staged downloads for files and folders, with a 512 MiB transfer limit, path validation, stream correlation, direction policy, and epoch cancellation.
- Review found that local folder snapshots initially missed descendants, publication and cleanup did not share the staging lock, cleanup could treat clipboard read errors as an empty list, and a replaced source path was not checked against the opened handle. Corrected each issue with focused tests.
- A targeted re-review found that ordinary non-file clipboard content reports `ContentNotAvailable`; startup cleanup now treats that case as an empty file list while failing closed on actual read errors.
- Focused clipboard tests passed (50). Clippy and the Windows compile script passed; the script reports the pre-existing missing icon warning.
- The final acceptance check exposed that transfer-limit failures only reached the log. Added one coalesced danger toast for oversized local snapshots, remote advertised totals, and remote observed totals. Three new tests were observed red with the classifier disabled, then green. Re-ran the clipboard, session, and window test modules, clippy, fmt, and Windows cross-check on the final tree; all passed.
- A live Windows clipboard exchange remains unverified: the saved Quench connection stalled before opening a session while macOS Keychain access was pending. No clipboard data was sent in that attempt.
