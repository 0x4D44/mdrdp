## MDR-BUG-FLU-00126 — ACK failure notification

The source diagnosis is an ordering error: ACK write failure sets stop before any worker sends a terminal window notification. Sibling workers consequently treat the failure as an intentional shutdown. The fix must preserve both the close notification and the failure reason, while keeping intentional shutdown quiet.

Implemented one atomic terminal claim shared by ACK/video/input workers. The ACK thread now returns its failure through its join handle; native shutdown retains that reason as `TransportFailed`. Socket shutdown and the window notification occur only for the winning terminal failure.

Regression evidence: the worker restored the old ACK stop-without-notification behavior and observed the ACK result assertion fail (`WindowClosed` instead of `TransportFailed`). The lead additionally replaced the atomic claim with an unconditional successful claim: intentional ACK shutdown failed its `WindowClosed` assertion and the competing-failure test observed three notifications instead of one. Both mutations were removed. Every new regression was observed failing on an assertion.

Windows type-check passed for both mdrdp and Rhydra host; it retains unrelated warnings about the missing cross-build icon tool and unused dimensions in `~/language/mdrdp/src/present.rs:95`. Formatting and diff whitespace checks passed. The worker also ran warning-denying library/test clippy and repeated the contention test 20 times successfully. This is focused failure-path validation, not a live GUI disconnect or a full test-suite run.

## MDR-BUG-FLU-00127 — control response bounds

Started a fresh claimed worktree after the ACK landing. Both control client helpers currently use unrestricted reply lines and renewable per-read timeouts. The intended correction shares a bounded exchange helper while retaining existing JSON and caller compatibility. Native calls use literal loopback addresses, so no DNS lookup is required on this path.

Baseline: 15 native-probe tests and the Windows guard passed. Read-only live smoke attempts could not reach a control agent: `mdrdp quench --doctor` reported SSH unreachable; `mdrdp temper --doctor` reported key authentication refused. Neither opened a desktop session. No credentials or host configuration changed. Live host compatibility therefore remains unverified; the wire format is unchanged and local loopback tests exercise the exchange itself.

Implemented a shared control exchange with a 64 KiB reply ceiling and one absolute connect/write/read deadline. Every partial socket operation receives only the remaining budget. Interrupted calls retry; newline scanning is linear and TCP_NODELAY avoids delaying the split request terminator. Synchronous hostname resolution remains a documented compatibility caveat; native numeric loopback calls avoid it.

The worker observed assertion failures under four restored mutations: renewing the read timeout made both dripping-peer tests return malformed JSON instead of timing out; removing the extra probe-byte allowance defeated both oversized-reply assertions; removing write timeouts made the blocked-write test take 754.9 ms, beyond its 500 ms bound; disabling expiry rejection let the expired-write test transfer a byte. All six new tests therefore demonstrated a red assertion before the final green run.

On the restored final tree the lead ran `deltic timeout 180 cargo test --manifest-path tools/latency-spike/server/Cargo.toml --lib control </dev/null` (43 selected tests passed), `deltic timeout 180 cargo test --lib native::probe </dev/null` (15 passed), and the Windows guard (mdrdp and Rhydra host passed). Rustfmt and diff whitespace checks passed. Existing standalone-host dead-code warnings in visual_flow.rs and the previously noted Windows warnings remain; no touched-code warnings appeared. No full suite or live GUI test was run.

Final CLI smoke `deltic timeout 180 cargo run --quiet --bin mdrdp -- --help </dev/null` passed. A fresh fetch showed no intervening trunk commits before final validation and commit.

The control fix landed as `aff1e45` with integration-owned version 0.1.242. `deltic bugs land` marked 00127 Fixed and cleared the claim.

## MDR-BUG-FLU-00128 — partial auxiliary startup cleanup

Started a fresh claimed worktree after the control fix landed. The claim tool noted that Fixed bug 00126 shares the native session file; it is a distinct failure path and its ACK correction must remain intact.

The missing owner exists only during startup: fallible socket clones and thread creation follow already-started workers, but the AuxChannel teardown owner is constructed last. The fix must establish rollback ownership before those workers start, close its outbox and socket on failure, and keep the main video/input stop flag clear. Cooperative workers must exit; genuinely blocked OS clipboard calls retain the existing bounded-detach policy.

Implemented an AuxStartup rollback owner before worker creation, with socket, outbox, local cancellation and join ownership. Successful startup transfers these resources to AuxChannel. Cleanup is shared with normal shutdown and retains the 100 ms join deadline. Audio/clipboard cancellation watches both the main stop flag and auxiliary-local stop; failed optional startup changes only the latter.

Four regressions inject both socket-clone failures, writer/poll spawn failures, audio-present first-clone failure, and direct owner drop. Assertions cover worker completion, socket EOF, outbox closure and preserving main stop. The lead disabled the AuxStartup Drop cleanup and ran `deltic timeout 180 cargo test --lib native::session::tests::auxiliary_startup -- --nocapture </dev/null`: all four selected tests failed on assertions. Guard cancellation stayed false; spawn failure left 1 worker started and 0 finished; the clone case returned before its expected worker started (0 instead of 1); audio rollback returned with 1 worker started and 0 finished. Cleanup was restored immediately. This supplies the complete red proof; the worker's earlier individual cleanup mutations had not made every test fail.

The worker ran 64 native-session tests, formatting and warning-denying library/test clippy successfully. Windows baseline also passed with the same unrelated warnings as earlier. These are local injected failures with inert clipboard/audio fixtures, not OS resource exhaustion or a live desktop test.

After restoring the mutation and rebasing onto the completed bugs' docs-only evidence commit, the lead reran all 64 native-session tests, `cargo clippy --lib --tests -- -D warnings`, both Windows type-checks and `cargo run --quiet --bin mdrdp -- --help`. All passed; the Windows guard retains the existing unused-dimensions/icon-tool warnings. Final formatting and whitespace checks passed. No full test suite, release build or deployment was performed.
