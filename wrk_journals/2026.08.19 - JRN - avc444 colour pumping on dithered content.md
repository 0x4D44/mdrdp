# AVC444 colour pumping on dithered content (MDR-BUG-FLUX-00007)

**Report.** Arthur: dithered/stippled UI fills (btop-style `▒` meter tails) show
colour instability in mdrdp sessions — the tone keeps shifting while the content is
static.

**Repro.** temper, PowerShell drawing a DarkYellow bar: moving `█` head + static `▒`
tail, redrawn 5x/s via `[console]::setcursorposition` (no cls — a cls repro would
blank-flash and flicker in any client). Driven entirely with `--input-script`;
`--capture-failures` collected 32 raw AVC444v2 payloads. Arthur independently watched
the dither tail pump tones in both setup sessions.

**Diagnosis method that worked.** Offline replay (`examples/avcreplay.rs`, new):
parse each captured container, decode both sub-streams through the real
VideoToolbox decoder, run the real `Yuv444Buffer` passes, convert a probe rect, and
print per-frame mean RGB + moved-pixel counts + the four 2x2-phase YUV values.
Attribution was immediate:

- temper steady state alternates LC=1 (luma-only) and LC=2 (chroma-only) PDUs.
- After a chroma frame the dither is correct 4:4:4 (probe mean B≈5).
- The next luma-only frame degraded it to replicated 2x2 averages (mean B≈37):
  33,000/48,000 probe pixels jumped by up to 98 RGB units — at every L↔C
  transition. Continuous, visible pumping.

**Root cause.** `avc444::apply_luma` replicated the main frame's averaged chroma
into all four positions of each 2x2 block, clobbering true odd-position samples
previously delivered by aux chroma frames. Faithfully transcribed from FreeRDP,
which carries the same defect. The encoder's contract: luma-only means chroma
unchanged — the client must keep what it was given.

**Fix.** `Yuv444Buffer` tracks per-2x2-block "true chroma delivered" (`chroma_seen`
bitset, set by both chroma passes for fully covered blocks). `apply_luma` writes the
average only to even/even (its MS-RDPEGFX home) in chroma'd blocks; virgin blocks
keep full replication (first-paint 4:2:0, and the FreeRDP differential oracle still
byte-matches on fresh buffers). Documented as the module's second deliberate FreeRDP
divergence (vendor/README.md).

**Validation.** Two regression tests, both proven red with the fix disabled;
avc444diff oracle 10/10; full suite 577+13+5; clippy/fmt; check-windows.sh; offline
replay of the same payloads now shows zero moved pixels across every L/C alternation
after first chroma delivery.

**Dead end / gotchas.**
- First repro attempt died at `--duration 45`: typing the long PowerShell one-liner
  via `--input-script` takes longer than expected — budget ~90 s.
- Temper wedged its logon path (CredSSP hang, TCP/X.224/TLS green — the documented
  signature) after ~4 rapid connects; the post-fix live visual pass is deferred
  until the host settles. quench was avoided: `ano` logons broken this evening and
  the rhydra rig owns its console.
- A transient remains by design: brand-new colourful content painted by luma-only
  frames renders with stale/neutral odd chroma until the server's chroma catch-up
  (~1.4 s observed). That is information-forced — the aux samples had not been sent.
