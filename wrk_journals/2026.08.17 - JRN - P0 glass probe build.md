# 2026.08.17 — P0: `probe glass` build (low-latency exploration, phase 0)

Executes P0 of the signed-off HLD (`wrk_docs/2026.08.17 - HLD - low-latency server
exploration.md`) plus P1 step zero (quench RTT baseline).

## Decisions taken at build start

- **No new bootstrap machinery.** `probe::stats::summarise` already carries a
  distribution-free 95% CI on the median (order statistics). That satisfies the
  HLD's "p50 with bootstrap CI" intent — a defensible nonparametric CI — without
  duplicate code. Glass summaries suppress p99 (HLD: no p99 claims at n=500).
- **Bindings**: `objc2-screen-capture-kit`/`objc2-core-media`/`objc2-core-video`
  (objc2 0.6 already in tree via winit) for capture; servo `core-graphics`
  (already in tree) for CGEvent injection. All macOS-gated in the root manifest,
  per the HLD's file-impact plan; `check-windows.sh` must stay green.
- **Timebase**: injection stamped with `CMClockGetTime(host clock)`; frame times
  from `CMSampleBuffer` presentation timestamps — same clock, so subtraction is
  legal. Startup sanity check: one captured frame's PTS within 1 s of now.
- **Workload geometry**: trials alternate a press key ('x') and an erase key
  (delete) so the watched terminal cell toggles and never drifts. Pre-trial
  quiet gate (300 ms) detects caret-blink pollution; poisoned trials are
  recorded and excluded, not silently dropped.
- Implementation delegated to an Opus worker against a fixed contract; lead
  owns review, live validation (TCC permissions, oracle checks), and the
  measurement runs.

## Live validation

- **Local Terminal (macOS)**: 20/20 valid at 120 fps capture, p50 24.9 ms;
  20/20 at 60 fps, p50 25.2 ms — capture-rate stability holds (CIs overlap).
- **Focus-routed injection failed on a busy desktop**: with four mdrdp
  processes and other apps stealing frontmost mid-run, 25/30 trials timed out
  because keystrokes went to the wrong app (only ~0 of the probe's events
  reached the session; the session's 33 internal latency samples match the
  setup script's own keys, which bypass macOS focus). Fix: `--target-pid`
  posts via `CGEventPostToPid` straight to the session process — misrouting
  is now impossible. Verified by a single-press trial: the `x` visibly echoed
  at the remote prompt (screenshot), 70.9 ms first / 87.6 ms converged.
- **mdrdp → quench (AVC444v2, 1280x800, DWMFI=15)**: 150/150 valid, 0
  poisoned, 0 timed out. **first-change p50 54.8 ms** (95% CI 51.7–58.0),
  p95 71.7; **converged p50 73.6 ms** (CI 70.4–75.7). Observed capture gap
  16.7 ms (60 Hz delivery — matches the host's 60 fps ceiling), band +8.3 ms
  mean. Sits exactly in the HLD's predicted 45–55 ms glass range.
- Second capture rate (60 fps cap, n=100, same session): **p50 53.0 ms**
  (CI 51.3–60.2) — median stable across rates on the remote target too. This
  run also caught a real host-side stall: trials ~52–85 contiguously timed
  out or ran 0.4–1.5 s (episode began ~8 min into the session, partial
  recovery after ~15 s). Not an instrument artifact — the pattern is a
  contiguous block, medians before/after agree with the 120 fps run. The
  instrument can see latency-degradation episodes, which is requirement 3
  made measurable.
- Remote Windows Terminal caret does not blink over RDP: quiet gates passed
  at exactly 300 ms throughout; 0 poisoned trials in every quench run.
