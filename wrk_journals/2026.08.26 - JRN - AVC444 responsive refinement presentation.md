# AVC444 responsive refinement presentation journal

## 2026-08-26 — Intake and diagnosis

- Arthur reported very sticky full-screen remote window dragging in mdrdp 0.1.237 against Crucible and Kiln, and questioned the new 100 ms chroma settling policy.
- Confirmed regression commit: `d94d5f6` (`fix(graphics): settle AVC444 chroma refinements`).
- Root cause: separate LC1 and LC2 commits can be collapsed behind one `DamageGate` event. LC2 restores `presentation_not_before` before the window observes LC1, so repeated refinements continually postpone the visible update.
- Baseline controls: the 33 ms large-canvas cadence and latest-value mouse coalescing predate 0.1.237. The reveal-only correction in `f96fe83` does not affect a continuously visible drag.
- Recorded and claimed `MDR-BUG-FLU-00124`.
- Chosen design direction: a fresh-content epoch persists across later refinements until a snapshot carrying that epoch is successfully presented.

## 2026-08-26 — Adversarial design review

- Two independent reviewers inspected the producer-to-presenter state machine and cross-refuted each other's findings.
- The main finding survived: epoch urgency must change `request_damage_redraw` scheduling as well as the eventual snapshot copy, or the event loop still sleeps until the LC2 deadline.
- Active-frame retention exposed a wake-loss edge. The design now retries only while a frame is active; it deliberately leaves aborted-frame suppression unchanged because those pixels are not atomic.
- Transient platform failures currently consume the only redraw opportunity. The design now keeps the stamp pending and uses the existing event-loop deadline for a bounded retry.
- The 33 ms large-canvas cadence remains independent. Freshness bypasses only the chroma refinement deadline.

## 2026-08-26 — External design review and checkpoint

- One read-only Claude/Fable review approved the epoch approach with no critical unresolved issue.
- Accepted explicit 33 ms retries for active-frame deferral and transient platform failures. This keeps failure accumulation comparable to the existing frame-driven behaviour; compositor `Busy` remains a separate 2 ms retry.
- Accepted a distinct active-frame `PresentationCopy` result and optional coherent presentation stamp. Retained aborted/suppressed snapshots neither poll nor acknowledge default state.
- Rejected a new producer-side frame-commit counter. It would spread a local presentation edge into the session notification and statistics path for little practical gain over a 30 Hz, no-render active-frame state check.
- Marked the HLD `SELF-APPROVED`; the only residual is subjective real-server drag verification after deterministic tests.

## 2026-08-26 — Implementation and regression evidence

- Added the coalesced LC1→LC2 regression first. On unchanged 0.1.237 it failed with `Err(100 ms deadline)` where an immediate latest-pixel copy was required.
- Added `PresentationStamp { generation, fresh_content_epoch }`. Immediate visible commits advance both values; quality-only refinements advance only the generation.
- Made both damage scheduling and locked snapshot copying filter the refinement deadline through the last successfully presented stamp.
- Replaced, rather than maximised with, an older event-loop deadline when new coherent store state arrives. This is necessary for fresh full-screen content to shorten a stale 100 ms LC2 wake to the 33 ms large-canvas cadence.
- Split active-frame `Pending` from aborted/suppressed `Retained`. Pending frames retry at 33 ms without rendering; retained state neither polls nor acknowledges a stamp.
- Transient platform errors now retry at 33 ms without acknowledgement. The existing 30-failure threshold remains about one second at frame cadence; compositor `Busy` still retries at 2 ms.
- Observed deliberate red mutations for the active/retained distinction and failure threshold. A 5120×2880 cadence test failed at 100 ms with the epoch filter disabled, then passed at 33 ms when restored.

## 2026-08-26 — Code review and simplicity pass

- One independent code review found a blocker: timer dispatch retried only when the store stamp changed. A resize/reveal present that hit compositor backpressure or a transient error could therefore lose its only retry at an unchanged stamp.
- Added a red-first dispatch test and one `redraw_retry` bit. Platform backpressure, active-frame deferral, `Busy`, and transient errors set it; timer service consumes it and retries regardless of stamp equality; a successful present clears it.
- The single targeted re-review confirmed the blocker fixed, including equal-stamp resize/reveal and occlusion behaviour.
- Rejected the review's aborted-frame proposal. An aborted transaction has already mutated live pixels without rollback, so the prior committed generation no longer has a safe store image to copy. Retaining the last snapshot is the intentional atomicity boundary; solving that differently would require a second full-surface snapshot outside this change.
- Simplicity pass consolidated four identical retry-state writes into `schedule_redraw_retry`, simplified the epoch deadline predicate, and removed stale generation/cadence-only wording. No dead code or broader abstraction remained.
