# JRN — Rhydra function, latency, and rendering hardening

## 2026-08-23 — intake and baseline

- Goal: match Windows App's everyday function and rendering quality while beating its
  input-to-visible latency at 5K/200% on Quench.
- Started a dedicated docs worktree from `origin/main` at `4b03e518`.
- Claimed Quench on the fleet board. No current claim was visible.
- Non-disruptive deploy probe: Rhydra v0.5.0 is healthy; Quench console user is `marti`;
  desired display is 5120×2880 at 240 Hz and 200%; driver and VB-CABLE checks are green;
  dry-run planned no mutation.
- Local client is `mdrdp v0.1.125`. The installed comparator is Windows App 11.3.8 build
  3054 (`com.microsoft.rdc.macos`).
- Confirmed `MDR-BUG-FLU-00034`: `mdrdp Quench --doctor` fails key authentication, while
  the explicit `quench.lan.example --user marti --ssh-user marti --doctor` path is green
  through SSH, tunnel, agent, display, server, input desktop, audio, and empty viewer slot.
- Opened independent function, latency, and rendering review lanes. No reviewer may edit,
  open a viewer, or touch Quench.
- Drafted the hardening HLD. The previous low-latency design's omitted Windows App row is
  superseded by Arthur's explicit comparison requirement.
- Attempted the single read-only Claude/Fable review with Claude Code 2.1.240. It returned
  a session-limit refusal before reviewing the design, so the external review did not run
  and was not retried. Correlated same-family review blind spots remain a residual risk.

## Review and implementation log

- Function review found disconnect-held input and a bounded-deadline defect. It refuted
  auto-reconnect, resize, and visibility items as intentional MVP exclusions.
- Latency review found two production server risks (stats on the sender thread and
  message-sized 5K backpressure), one production telemetry bias, one reader batch risk,
  and three spike-viewer-only costs.
- Rendering review found the IOSurface pool falls back to overwriting a surface that
  CoreAnimation still reports in use. It refuted current channel-order, move-rect,
  AVC444, H.264 reference, and HEVC epoch hypotheses.
- All three reviewers completed one cross-lane refutation pass. Every candidate mechanism
  survived, but deadline, queue visibility, stats-thread, and batch/UI overclaims were
  narrowed in the HLD.
- Raised `MDR-BUG-FLU-00048` through `MDR-BUG-FLU-00057` for the ten new survivors.
- Marked the reviewed design `SELF-APPROVED`. External Fable review remains the stated
  residual risk; there is no unresolved architectural fork at this checkpoint.

## Green unit — atomic 5K logical-frame admission

- Claimed `MDR-BUG-FLU-00051` in a fresh worktree. The previous two-message queue
  admitted rect, tile 0, and tile 1 independently, so pressure could strand one half
  of a 5K desktop frame.
- Added a portable bounded assembler and observed all four initial completion,
  ordering, fallback, and expiry tests fail before implementation. Reconnect and
  mixed-keyframe recovery tests were also observed red under deliberate mutations.
- The sender now receives one complete tile set per logical desktop frame. Queue-full
  loss is atomic, pending assembly is capped at three frames, late retired tiles cannot
  resurrect a partial, and recovery admits no delta set until all tiles align on one
  keyframe sequence.
- Dirty rects deliberately stay independent: the client can advance exact pixels from
  them while decoding suppressed AUs only for reference state. Waiting for both encoders
  would directly regress the interaction path this programme is meant to improve.
- Adversarial design review agreed on atomic tile grouping, bounded assembly, all-tile
  recovery, one-drop telemetry, and the one-tile HEVC case. Its proposal to bundle rects
  was rejected because `NativeSink::paint` and `on_tile_au` already separate pixel
  exactness from decoder-reference progress; the proposal adds encoder latency without
  repairing another invariant.
- Code review disposition:

  | # | item | type | action | note |
  |---|---|---|---|---|
  | 1 | `dropped_frames` conflates queue and recovery losses | Issue | Fixed | schema 10 explicitly defines complete logical frames withheld by assembly, recovery, or admission |
  | 2 | staggered tile keyframes can wedge recovery | Issue | Fixed | mixed keyframe sets now request all encoders again; portable recovery oracle added |
  | 3 | no combined recovery integration oracle | Optional | Partly fixed | pure recovery/queue-pressure state is covered; live 5K wire grouping remains the Quench oracle |
  | 4 | bounded per-frame assembler allocations | Nit | Accepted | three-frame cap bounds payload ownership; no AU bytes are copied |

  Both required findings were fixed. One optional was partly applied and the bounded
  allocation nit needed no code change. The simplicity pass removed boolean return
  values which could only ever be true. The single targeted re-review confirmed both
  required fixes and found no remaining critical issue.

## Green unit — recover the input listener from partial records

- Claimed `MDR-BUG-FLU-00038` in a fresh worktree. `serve_one` waited forever after
  receiving a record kind but fewer than its declared remaining bytes, so the inline
  listener could never accept a healthy replacement connection.
- Moved the socket record boundary into a portable helper. Waiting between records
  remains unlimited, but once a kind arrives the remaining body has one absolute
  one-second deadline. A byte dribble cannot renew it. Every exit still flushes the
  move aggregate and releases tracked held keys/buttons.
- The silent-partial oracle was observed hanging until its process-level timeout,
  then passed after the fix. A deliberate slow-dribble counterexample also failed
  before the absolute deadline loop and passed after it. Focused tests cover healthy
  idle gaps and unknown kinds too.
- Code review disposition:

  | # | item | type | action | note |
  |---|---|---|---|---|
  | 1 | pre-first-record idle can retain the connection | Issue | Disagreed | unlimited idle is the healthy established-session contract; replacement needs an explicit ownership/handshake policy and is outside this partial-record defect |
  | 2 | clamp sub-millisecond socket timeouts on Windows | Optional | Fixed | round the final fraction to 1 ms, then re-check the absolute deadline |
  | 3 | timeout reset skipped after a body error | Optional | Disagreed | `set_read_timeout(None)` is called before matching the body result; only a reset failure is intentionally secondary because the stream is immediately dropped |

  One review cleanup applied. One policy expansion and one incorrect reading were
  rejected; no valid required change remains in the partial-record scope.

## Green unit — bind every advertised side channel before video startup

- Claimed `MDR-BUG-FLU-00037` in a fresh worktree. Input and auxiliary listeners
  previously bound only inside detached service threads after the video contract had
  already advertised their ports.
- Startup now pre-binds input and optional auxiliary sockets as one transaction before
  the header or video listener exists, then moves those sockets into their service
  threads. A failed auxiliary bind releases the already-bound input socket as the
  transaction unwinds.
- Both portable regression tests were observed red before auxiliary pre-binding, then
  passed. The full Rhydra suite passed 324 tests and the Windows cross-target gate passed.
- Code review found no required changes and confirmed bind ordering, partial cleanup,
  disabled-aux behaviour, and API compatibility. Its optional exact-port assertion was
  skipped because the tests already exercise real kernel binds and exact port selection
  is `TcpListener::bind` behaviour rather than project logic.
- The simplicity pass kept the existing safe `serve(port, ...)` APIs and made the new
  pre-bound entry points crate-private, so callers cannot bypass the loopback-only API.

## Green unit — bound NV12 conversion surfaces under encoder pressure

- Claimed `MDR-BUG-FLU-00043`. The converter previously allocated a new 5K tile
  surface whenever all encoder submissions remained in flight, so a slow or wedged
  Media Foundation transform could consume GPU memory without a ceiling.
- Added portable fixed-budget lease bookkeeping. Its exhaustion regression was
  observed red while it still reproduced the growth policy, then passed after the
  pool refused a fifth lease. Round-robin reuse and invalid-release cases also pass.
- The capture loop now pumps all tile encoders before conversion. If any tile still
  lacks capacity, it sheds the whole desktop frame before any conversion, raw rect,
  or pixel-diff baseline update. No decoder reference is lost, no partial 5K tile set
  is submitted, and the following rect overlay is suppressed because its damage
  metadata cannot span the skipped capture.
- The shed is counted in `dropped_frames` without entering keyframe recovery: the
  encoder never saw the frame, so its existing reference chain remains valid.
- Full Rhydra tests passed 327 cases. The Windows cross-target repository check
  passed with only the existing missing-icon warning.
- The rendering reviewer found that the assembler's old three-frame pending bound
  was one below the four-surface maximum tile-output skew. The bound now derives
  directly from `convert::POOL_SIZE`, so draining one tile first cannot evict a
  valid half-frame or cause avoidable keyframe recovery. This keeps the hot path
  allocation-free instead of sorting emitted AUs after every pump.
- The same reviewer found that pumping after acquisition lets pointer-only capture
  events starve a completed AU and puts old encode work in front of a fresh desktop
  update. Pumping now happens at the start of every connected capture-loop turn,
  before the bounded acquire, so output and surface retirement cannot be starved by
  cursor motion and newly captured interaction pixels do not wait behind old work.
- The code reviewer identified a transform that accepts four inputs but withholds
  output as a permanent-freeze counterexample. A portable 500 ms saturation
  watchdog was observed red before implementation. It resets when every tile again
  has whole-frame capacity. Persistent saturation exits with a clear error so the
  existing session supervisor rebuilds the encoder instead of leaving frozen video alive.
- Adversarial review disposition:

  | item | action | reason |
  |---|---|---|
  | pointer-only events can starve encoder output | Fixed | pump moved before every bounded acquire |
  | pumping after acquire delays fresh rect pixels | Fixed | the same move drains old work before capture |
  | four tile-0 outputs overflow a three-frame assembler | Fixed | pending bound now derives from the fixed four-surface budget |
  | persistent surface saturation freezes forever | Fixed | 500 ms watchdog hands recovery to the supervisor |
  | `dropped_frames` schema text omitted conversion pressure | Fixed | schema and README now name it |
  | sort all outputs sequence-major | Rejected | the assembler bound equals the maximum submit skew by construction; sorting adds hot-path work |
  | add a separate surface-pressure counter | Deferred | useful for tuning, but the cumulative visible-loss counter is correct; Quench evidence decides whether it earns wire/schema cost |

  No critical finding survived, so the lean flow did not run another review round.

## Green unit — select a legal HEVC fallback level

- Claimed `MDR-BUG-FLU-00041`. The fallback requested and required Level 4.1 for
  both supported desktops, although even 2560×1440 exceeds that level's picture
  limit and 5120×2880 exceeds it by much more.
- The portable selector uses the H.265 Main-tier level limits for picture samples,
  maximum dimension, luma samples per second, and bitrate. At Rhydra's declared
  60 fps and default 20 Mbit/s it selects Level 5 for 1440p and Level 6 for 5K.
- The geometry/rate/bitrate selector tests were observed red before implementation.
  They also prove higher bitrate/rate promotion and fail closed beyond Level 6.2.
- The same selected `general_level_idc` now drives the Media Foundation media type,
  output renegotiation checks, and independent emitted-SPS validation. No layer can
  silently accept a different stream contract.
- Three independent adversarial reviewers were started for standards, Media
  Foundation, and function/simplicity, but all three hit the harness-wide usage cap
  before reviewing. They are not counted as evidence. The sequential fallback
  rechecked the H.265 Table A.1/A.2 values and dimension rule, Windows' Level 1–6.2
  enum mapping, every startup/renegotiation/SPS propagation edge, custom bitrate,
  exact-level policy, and fail-closed overflow. It found no critical or required
  change; the simplicity pass made the selector crate-private and rejected zero
  contracts explicitly. The final cross-target gate exposed three new dead-code
  warnings in client-only builds, so the selector and table now compile only in a
  Windows host build or in tests.

## Green unit — bootstrap a viewer from the retained desktop

- Claimed `MDR-BUG-FLUX-00011`. The connect edge requested a keyframe but supplied
  no pixels when the capture source timed out on an unchanged desktop, leaving a
  fresh viewer blank until the user caused a repaint.
- The pipeline now retains one current BGRA desktop texture on the GPU independently
  of the optional pixel-diff path. After a connect edge it gives the source its normal
  bounded poll first, then re-encodes that retained texture when the source is idle.
  Fresh content wins and a source rebuild invalidates the cache before it can be used.
- The portable bootstrap state tests were observed compile-red before implementation.
  They cover first connect, reconnect, absent or invalidated cache state, admitted
  fresh frames, and recovery keyframe reuse.
- The first review found that clearing bootstrap after submission could strand a
  static viewer when the recovery keyframe itself met outbound backpressure. A later
  recovery request now reuses the retained frame too. This survived the countercheck:
  encoder output is pumped before the source poll, so the retry is requested before
  the idle fallback decision on the same loop turn.
- The simplicity pass kept the cache in the existing `PixelDiff` GPU texture and
  added only a small portable two-bit state machine. It did not add a source-specific
  replay API, duplicate a 5K texture, or retain CPU pixels.
- Full Rhydra tests passed 280 cases. The Windows cross-target gate passed with only
  the existing missing-icon warning. Live idle-desktop reconnect verification remains
  for the integrated Quench deployment.

## Green unit — keep rect overlays on the admitted recovery baseline

- Review of the static bootstrap exposed and recorded `MDR-BUG-FLU-00064`: encoded
  recovery already suppressed unsafe deltas after queue loss, but metadata and pixel-
  diff rects bypassed that state and could paint against a frame the viewer never got.
- The recovery oracle now publishes one read-only predicate. Both rect paths snapshot
  it once per captured frame and remain off until an all-tile keyframe has entered the
  outbound queue. The retained GPU frame then matches the viewer's restored baseline.
- The recovery assertion was observed compile-red before the predicate existed. It
  proves overlays are disabled at startup and reset, then enabled only by successful
  all-keyframe admission; the surrounding test exercises incomplete sets, mixed tile
  keyframes, queue rejection, and pre-encode shedding.
- Adversarial function review checked three failure orders: rect admitted then video
  dropped, rect dropped then video dropped, and socket failure after queue admission.
  In the first, the complete rect update itself advances the viewer correctly; the
  second enters recovery with overlays disabled; the third drops the connection and
  the next connect resets recovery. No counterexample survived.
- The review-agent quota remained unavailable, so this review ran sequentially and is
  recorded as degraded rather than independent evidence. The simplicity pass kept the
  existing recovery state as the sole oracle and added no queue, copy, or protocol bit.
- Full Rhydra tests passed 280 cases. The Windows cross-target gate passed with only
  the existing missing-icon warning.

## Green unit — let a reconnect evict a silent auxiliary peer

- Claimed `MDR-BUG-FLU-00039`. The host served an auxiliary connection inline, so
  a peer that never sent or closed held the only clipboard/audio slot forever and
  later connections remained in the accept backlog.
- A simple read timeout was rejected because a healthy clipboard session may be
  silent indefinitely. The accept loop now stays live and gives the slot to the
  newest connection: it shuts down and joins the old session first, then creates the
  replacement's two clipboard handles. Clipboard ownership therefore stays serial.
- The loopback replacement test was observed compile-red before the lifecycle owner
  existed. It connects a silent client, replaces it, sends from the second client,
  and proves only that replacement reaches the host pasteboard.
- Host and client auxiliary sockets now share a five-second write bound. A write
  failure shuts down both socket directions so the paired reader wakes and the host
  tears down its poll/audio threads rather than retaining half a connection.
- Adversarial lifecycle review checked factory ordering, shutdown across cloned socket
  handles, a previously finished worker, replacement setup failure, and loopback-only
  authority. The factory calls were moved after the old join so two sessions never
  hold clipboard handles together. It also found that the accept loop's ownership
  clone could keep a socket alive after an early worker setup error; an on-exit clone
  now shuts the shared socket in every return path. No critical finding remained.
- The review-agent quota remained unavailable, so this review ran sequentially and is
  recorded as degraded rather than independent evidence. The simplicity pass kept
  the existing per-connection implementation and added one small ownership wrapper;
  it did not add heartbeats, idle disconnects, or protocol messages.
- Full Rhydra tests passed 281 cases. The Windows cross-target gate passed with only
  the existing missing-icon warning.
