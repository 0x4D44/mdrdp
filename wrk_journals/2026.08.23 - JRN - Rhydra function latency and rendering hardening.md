## Review and implementation log

- Function review found disconnect-held input and a bounded-deadline defect. It refuted
  auto-reconnect, resize, and visibility items as intentional MVP exclusions.
- Latency review found two production server risks (stats on the sender thread and
  message-sized 5K backpressure), one production telemetry bias, one reader batch risk,
  and three spike-viewer-only costs.
- Rendering review found the IOSurface pool falls back to overwriting a surface that
  CoreAnimation still reports in use. It refuted current channel-order, move-rect,
  AVC444, H.264 reference, and HEVC epoch hypotheses.
- All three reviewers completed one cross-lane refutation pass. Every candidate mechanism
  survived, but deadline, queue visibility, stats-thread, and batch/UI overclaims were
  narrowed in the HLD.
- Raised `MDR-BUG-FLU-00048` through `MDR-BUG-FLU-00057` for the ten new survivors.
- Marked the reviewed design `SELF-APPROVED`. External Fable review remains the stated
  residual risk; there is no unresolved architectural fork at this checkpoint.

## Green unit — atomic 5K logical-frame admission

- Claimed `MDR-BUG-FLU-00051` in a fresh worktree. The previous two-message queue
  admitted rect, tile 0, and tile 1 independently, so pressure could strand one half
  of a 5K desktop frame.
- Added a portable bounded assembler and observed all four initial completion,
  ordering, fallback, and expiry tests fail before implementation. Reconnect and
  mixed-keyframe recovery tests were also observed red under deliberate mutations.
- The sender now receives one complete tile set per logical desktop frame. Queue-full
  loss is atomic, pending assembly is capped at three frames, late retired tiles cannot
  resurrect a partial, and recovery admits no delta set until all tiles align on one
  keyframe sequence.
- Dirty rects deliberately stay independent: the client can advance exact pixels from
  them while decoding suppressed AUs only for reference state. Waiting for both encoders
  would directly regress the interaction path this programme is meant to improve.
- Adversarial design review agreed on atomic tile grouping, bounded assembly, all-tile
  recovery, one-drop telemetry, and the one-tile HEVC case. Its proposal to bundle rects
  was rejected because `NativeSink::paint` and `on_tile_au` already separate pixel
  exactness from decoder-reference progress; the proposal adds encoder latency without
  repairing another invariant.
- Code review disposition:

  | # | item | type | action | note |
  |---|---|---|---|---|
  | 1 | `dropped_frames` conflates queue and recovery losses | Issue | Fixed | schema 10 explicitly defines complete logical frames withheld by assembly, recovery, or admission |
  | 2 | staggered tile keyframes can wedge recovery | Issue | Fixed | mixed keyframe sets now request all encoders again; portable recovery oracle added |
  | 3 | no combined recovery integration oracle | Optional | Partly fixed | pure recovery/queue-pressure state is covered; live 5K wire grouping remains the Quench oracle |
  | 4 | bounded per-frame assembler allocations | Nit | Accepted | three-frame cap bounds payload ownership; no AU bytes are copied |

  Both required findings were fixed. One optional was partly applied and the bounded
  allocation nit needed no code change. The simplicity pass removed boolean return
  values which could only ever be true. The single targeted re-review confirmed both
  required fixes and found no remaining critical issue.

## Green unit — recover the input listener from partial records

- Claimed `MDR-BUG-FLU-00038` in a fresh worktree. `serve_one` waited forever after
  receiving a record kind but fewer than its declared remaining bytes, so the inline
  listener could never accept a healthy replacement connection.
- Moved the socket record boundary into a portable helper. Waiting between records
  remains unlimited, but once a kind arrives the remaining body has one absolute
  one-second deadline. A byte dribble cannot renew it. Every exit still flushes the
  move aggregate and releases tracked held keys/buttons.
- The silent-partial oracle was observed hanging until its process-level timeout,
  then passed after the fix. A deliberate slow-dribble counterexample also failed
  before the absolute deadline loop and passed after it. Focused tests cover healthy
  idle gaps and unknown kinds too.
- Code review disposition:

  | # | item | type | action | note |
  |---|---|---|---|---|
  | 1 | pre-first-record idle can retain the connection | Issue | Disagreed | unlimited idle is the healthy established-session contract; replacement needs an explicit ownership/handshake policy and is outside this partial-record defect |
  | 2 | clamp sub-millisecond socket timeouts on Windows | Optional | Fixed | round the final fraction to 1 ms, then re-check the absolute deadline |
  | 3 | timeout reset skipped after a body error | Optional | Disagreed | `set_read_timeout(None)` is called before matching the body result; only a reset failure is intentionally secondary because the stream is immediately dropped |

  One review cleanup applied. One policy expansion and one incorrect reading were
  rejected; no valid required change remains in the partial-record scope.

## Green unit — bind every advertised side channel before video startup

- Claimed `MDR-BUG-FLU-00037` in a fresh worktree. Input and auxiliary listeners
  previously bound only inside detached service threads after the video contract had
  already advertised their ports.
- Startup now pre-binds input and optional auxiliary sockets as one transaction before
  the header or video listener exists, then moves those sockets into their service
  threads. A failed auxiliary bind releases the already-bound input socket as the
  transaction unwinds.
- Both portable regression tests were observed red before auxiliary pre-binding, then
  passed. The full Rhydra suite passed 324 tests and the Windows cross-target gate passed.
- Code review found no required changes and confirmed bind ordering, partial cleanup,
  disabled-aux behaviour, and API compatibility. Its optional exact-port assertion was
  skipped because the tests already exercise real kernel binds and exact port selection
  is `TcpListener::bind` behaviour rather than project logic.
- The simplicity pass kept the existing safe `serve(port, ...)` APIs and made the new
  pre-bound entry points crate-private, so callers cannot bypass the loopback-only API.
