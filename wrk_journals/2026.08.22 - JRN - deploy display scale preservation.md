# Deploy display scale preservation

## 2026-08-22

- The integrated v0.1.117 deployment copied all combined artifacts to Quench, then
  failed its stable-green check. The replacement agent reported actual 2560x1440 at
  200%, desired 2560x1440 at 100%, `mode_ok=false`, and no server.
- Root cause: preflight reads the old agent's status but retains only version,
  green, and server state. Full deploy then runs `rhydra-agent install`, whose new
  process starts with safe 2560x1440/100% defaults, losing the old process's desired
  5K/200% tuple.
- The fix will preserve only a complete prior desired tuple through the existing
  `prepare-display` control request. A fresh host remains on safe defaults.
- Design review exposed that a post-start control replay can fail after the old
  process, and therefore its only copy of the tuple, is gone. The corrected design
  passes a validated optional display tuple to agent install; the scheduled task
  starts every replacement with that tuple before its first reconcile tick.
- Final deploy verification will compare the exact desired tuple. Schema older than
  5 and any zero/partial status fields provide no preservation evidence.
