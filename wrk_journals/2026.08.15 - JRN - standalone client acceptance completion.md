### Unit 3 — empty/image clipboard and audio device-loss fail-safe

The clipboard bridge now carries either Unicode text or bounded RGBA image content. Empty
text is advertised and served as a valid empty Unicode payload. Images use standard CF_DIB:
outbound data has a top-down BITMAPV5HEADER with BI_BITFIELDS, explicit RGBA masks, and sRGB;
inbound decoding accepts bounded 24/32-bit BI_RGB and 32-bit BI_BITFIELDS, including top-down
and bottom-up layouts. Text remains preferred when both text and image are offered. Malformed
or oversized image data resets the paste state and leaves the next transfer usable.

Image and text fingerprints include the content kind and dimensions while hashing only a
bounded prefix, so remote-origin content is not echoed back and large clipboards do not add
unbounded hash work to every 250 ms poll. Ordinary 32-bit BI_RGB treats its reserved byte as
opaque rather than transparent. The exact 2x2 RGBA wire round-trip also asserts the V5 sRGB
declaration.

A cpal runtime device error now latches a shared playback gate off. The network side still
acknowledges RDPSND packets but stops decoding and queuing them; the output side emits silence,
and `AudioPlayback::is_active` reports false without restarting or hanging the RDP session.

Mutation evidence covered empty advertise selection, image format choice, B/R and alpha
mapping, malformed/oversized recovery, bounded fingerprinting, BI_RGB opacity, V5 color-space
metadata, and late audio packets after device failure. Focused clipboard (24 tests) and audio
(31 tests) suites pass, as do formatting, diff checks, all-target clippy with warnings denied,
and the optimized release build.

Quench is now reachable without the account-conflict prompt. A clean 45-second 0.1.17 run
rendered 204 frames at 1920x1080 through ClearCodec, uncompressed surfaces, and RFX Progressive

### Unit 5 — redacted acceptance metrics and complete first-run rendering

`--metrics-json` now writes a versioned, payload-free session report. It contains elapsed
time and end state; latency distribution and frozen-baseline drift; frame, wire-byte,
bitmap-cache and codec totals; graphics and audio failure counts; joined channel names; and
process CPU and peak resident memory where the platform exposes them. Its Rust value shape
has no host, username, credential, path, clipboard, pixel, or audio-payload field. The
serializer builds the complete JSON document in memory before opening the write path.

The process sampler uses dependency-free platform APIs: `getrusage` with the exact Darwin
`timeval` layout, and `GetProcessTimes` plus `GetProcessMemoryInfo` on Windows. macOS unit
tests cover monotonic snapshots and delta calculation. The Windows module also compiled by
itself with warnings denied for `x86_64-pc-windows-msvc`; the full Windows application check
remains blocked by this Mac's missing Windows CRT/MSVC headers, as recorded in Unit 1.

The Quench acceptance run exposed two graphics lifecycle defects before the final metrics
could be trusted. First, `ResetGraphics` had been treated as destroying surfaces and bitmap
cache entries. MS-RDPEGFX 3.3.5.14 requires only resizing the Graphics Output Buffer; the
protocol has explicit `DeleteSurface` and `EvictCacheEntry` commands. Preserving that state
changed 260 post-reset cache references from missing regions to successful paints. The
vendored EGFX client now preserves its private surface metadata too, and the handler now
implements the dedicated eviction callback instead of silently ignoring it.

Second, the exit image still showed horizontal stale bands despite zero counters. A
successful ClearCodec command was captured only through the explicit session-content
capture path, then decoded offline. Residual and band layers matched FreeRDP 3.27.1 exactly;
all 69,554 differing bytes came from the subcodec layer. The published IronRDP decoder's
`SubcodecId::NsCodec` arm was an empty success. The new bounded NSCodec plane/RLE/chroma
decoder makes every residual/band/subcodec combination of that 448x448 command match
FreeRDP byte-for-byte. A separate short-V-bar boundary was also corrected to clip cached
rows to the current band height.

The new report-writer, resource-delta, end-state, surface-reason, reset, eviction, short
V-bar, and NSCodec tests were each observed failing before their fixes. The final optimized
35-second 1920x1080 Quench run ended gracefully. Its visually inspected screenshot had no
missing regions. Metrics recorded zero decode errors, zero undecoded regions, zero surface
errors, zero unhandled PDUs, and 1,021 of 1,021 bitmap-cache lookups hit. The short idle run
used 0.57% average CPU and 169 MiB peak resident memory. It produced no latency samples
because unattended macOS accessibility policy still prevents input through the first-run
screen; it is not multi-hour latency or resource-stability evidence.

### Unit 6 — live desktop input and serialized clipboard advertisements

Direct RDP scancodes, sent through the same `InputEvent` channel as the session window,
completed Quench's Location and privacy pages and reached the full Windows desktop. This
bypassed only macOS host automation policy; the network input path was the product path.
Every bounded session ended through graceful shutdown. A 50-second optimized input smoke
run yielded 43 input-to-next-paint samples: 11.173–81.063 ms, p50 40.078 ms, p95 72.230 ms,
and p99 81.063 ms. It used 2.41% average CPU and 187 MiB peak resident memory. This is not
the required Ethernet/Wi-Fi 6 comparison or multi-hour stability evidence.

Live clipboard tests then proved Unicode text, empty text, a deterministic 1 MiB payload,
rapid changes, and a 1920x1080 image. Unicode returned byte-for-byte with SHA-256
`e853e3de…`. Windows normalized the large payload's LF line endings to CRLF; after applying
that expected normalization, all 1,110,256 returned bytes matched SHA-256 `da7cbf95…`.
Paint displayed the client image at 1920x1080, and after independently replacing the local
clipboard, copying it back returned a PNG with the same dimensions.

The first rapid-change run pasted the oldest value. Tracing the protocol exposed two
ordering defects: local polling could send the initialization FormatList before CLIPRDR's
Monitor Ready request, and later changes could send more FormatLists while one response was
outstanding. The bridge now defers the initial list until the protocol request and coalesces
all in-flight changes into one latest-value resend after acknowledgement. Quench then pasted
`RAPID-THREE-FINAL`. Both regressions were observed red before the fix, including the exact
pre-Monitor-Ready output and the three concurrent advertisements; the focused clipboard
suite now covers the corrected order.

Quench's Windows Audio service reports `Running`, and its `fDisableCam` playback-redirection
policy is unconfigured. A FreeRDP reference session opened the server's
`AUDIO_PLAYBACK_DVC`, while mdrdp's static RDPSND channel still negotiated no format for a
SoundPlayer attempt. Audible/loopback audio therefore remains unverified rather than being
claimed from channel membership alone.
