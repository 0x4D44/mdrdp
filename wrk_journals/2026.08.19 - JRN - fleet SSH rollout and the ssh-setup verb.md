# 2026.08.19 — JRN — Fleet SSH rollout, and the `ssh-setup` verb it produced

Two halves. First, SSH from this Mac to every fleet Windows box by hand. Then
`mdrdp ssh-setup`, which exists because the by-hand part went badly enough to
be worth encoding.

## The rollout

Starting state: quench only, on a per-host key (`id_ed25519_quench`, installed
2026-08-17). Arthur's call was one shared fleet key installed everywhere rather
than per-host keys, so `id_ed25519_fleet` was minted and added to quench
alongside its existing key — additive, both verified to authenticate on their
own before the backup was removed.

Five hosts now work: quench (`ano`), crucible, kiln, anvil and temper (all
`marti`). Every one matches quench's posture — OpenSSH installed as a Windows
capability, `DefaultShell` unset, `administrators_authorized_keys` restricted
to SYSTEM + Administrators, SSH sessions at High Mandatory Level. That last one
matters beyond tidiness: it is what lets `mdrdp deploy` run against any of them
unchanged.

DHCP was raised as a concern and turned out to be a non-issue by construction:
no IP appears in `~/.ssh/config`, `known_hosts` is keyed by hostname only, and
`CheckHostIP` defaults to `no` in modern OpenSSH. A box taking a new lease
changes nothing.

## Three failures, and why each was slow

**The firewall profile.** crucible and temper both timed out with sshd running
and listening on `0.0.0.0:22`. A timeout rather than a refusal means a drop,
but the rule looked present and enabled. The answer came from reading quench's
own config: its built-in `OpenSSH-Server-In-TCP` is **Private**-profile, the
network (`BA55-SA-B9B5-TQM`) is categorised **Public**, and a second hand-added
rule `mdrdp-sshd-in` with Profile Any was doing the actual work. Someone had
hit this before and left the evidence in place.

**The capability rewriting the rule.** On temper the script *did* create a
Profile-Any rule — the output showed it. Then `DISM.exe` installed OpenSSH,
which rewrote the same-named rule back to Private. Three rounds went into that
one, and the fix is simply to use a name the capability does not own.

**PowerShell 7.** `Add-WindowsCapability` threw "Class not registered", which
reads as a broken servicing stack; `DISM.exe` then worked fine. Worse, the CIM
cmdlets returned *silent empties*, so `Get-NetTCPConnection -LocalPort 22`
reported nothing while `netstat` showed it listening. That empty output caused
a wrong diagnosis ("sshd is not binding") that survived a full round.

Common thread: **every symptom pointed away from its cause.** That is the
argument for the tool.

## The verb

Arthur asked for a menu option that does the client config and copies the
Windows commands. I initially argued against putting it in Settings — wrongly:
`src/hostscripts.rs` already *is* that pattern (two scripts, both surfaced in
the launcher and session menus, both copied to the clipboard for pasting into
PowerShell over RDP). His instinct was right and I was aiming at the wrong
surface.

What SSH genuinely needs beyond the existing two:

- the **client half** done as well (key + `~/.ssh/config`), which AVC444 and
  60 fps do not need;
- a script that is a **function, not a constant**, because it carries this
  machine's public key;
- **verification**, because of everything above.

So: `src/sshsetup.rs` with `classify` as a pure function mapping (resolved,
tcp, ssh) to a `Diagnosis` — `Dropped` and `NothingListening` deliberately
distinct, since they are opposite fixes and the symptoms mislead. Plus
`mdrdp ssh-setup <host>`, idempotent and re-runnable (run it, paste, run it
again to verify), the two menu entries, and a pointer from `deploy`'s first
host contact.

An unexpected confirmation: `ssh-setup --print` picked up the key I had created
by hand earlier in the day, because `ensure_key` reuses whatever is at
`id_ed25519_fleet` rather than regenerating. Regenerating would silently orphan
every host that already trusts the old key.

## What was proven, and what was not

Proven live: `ssh-setup crucible` reports working and exits 0; the generated
script body was extracted and run on crucible over its elevated SSH, printing
its evidence block with no errors and leaving `keylines=1`, the ACL untouched
and the rule still Profile Any — so the PowerShell is syntactically correct and
genuinely idempotent. The deploy pointer was exercised against an unresolvable
host using stub artifacts. Every new test was mutation-checked: dropping
Profile Any, collapsing timeout into refused, single-newline block separation,
prefix-matching aliases, and block-scope leak each turn exactly the intended
test red.

Not proven live: the `Dropped` and `KeyRejected` paths end-to-end. Both have
unit coverage in `classify`, but no host is currently in a state to exercise
them — every fleet box now has working SSH, which is a good problem.

Also unproven: the UAC self-elevation wrapper. The inner body was validated
over SSH, which cannot raise a UAC prompt, so the `Start-Process -Verb RunAs`
line is carried on the same convention the two existing scripts use.

## Loose end

temper's WMI/CIM layer misbehaved throughout — DISM cmdlets failing, Net\*
cmdlets returning empty. Now that SSH works there, it is worth a `box-doctor`
pass. temper underpins every mdrdp measurement before 2026-08-16, so a flaky
COM layer there is worth understanding on its own merits.
