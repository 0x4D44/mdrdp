# 2026-08-16 — AVC444v2 decode

Task: design + implement AVC444/AVC444v2 decode (quench sends Avc444v2 for the whole
desktop once V10.7 is confirmed — measured in the previous session's diagnostics).
Worktree: `~/worktrees/mdrdp/20260816-TSK-HUM-avc444v2-decode`.

## Understand

- Wire container already parsed (`vendor/ironrdp-egfx/src/pdu/avc.rs::Avc444BitmapStream`);
  the gap is `client.rs:721` forwarding Avc444/Avc444v2 to `on_unhandled_pdu`, plus the
  RGBA-only `H264Decoder` trait.
- Pulled FreeRDP `prim_YUV.c` and `h264.c` (raw source, in scratchpad) and verified the
  actual v1/v2 chroma packing and the LC dispatch from the C code, not from a summary.
  Two load-bearing discoveries:
  - **One decoder decodes both sub-streams** — FreeRDP feeds stream1 then stream2
    through a single H264 context; the encoding is single-decoder-compatible. No second
    VideoToolbox session needed.
  - **YUV444→RGB is full-range BT.709 fixed point** (403/475/48/120 >> 8), so VT must
    output raw planar YUV ('y420') and we convert in Rust.

## Design

HLD written: `wrk_docs/2026.08.16 - HLD - AVC444v2 decode.md`. Key shape: trait gains
`decode_yuv420` (default Err); new pure `avc444.rs` combination module in vendored
egfx (direct index mapping, per-rect ROI with enlarge-only alignment); per-surface
persistent YUV444 buffer; capability advertisement moves to V10.7-with-AVC on macOS.

## Adversarial review (3x Opus: protocol / VideoToolbox-FFI / architecture)

Unusually productive round — the VT reviewer built C probes and *measured* VideoToolbox
behavior rather than reasoning about it. Surviving findings folded into rev 2:

- **'f420' not 'y420'** (measured): VT normalises to the requested format's range
  regardless of stream VUI. Rev 1 had the default and fallback inverted.
- **VT always delivers SPS-cropped dims**; planar strides ≠ width (1728 for w=1680).
- **Session rebuild mid-GOP = stream death until next IDR** (measured -12909) → one
  output format for everything; AVC420 RGBA decode reimplemented atop the YUV path
  (also faster: 4.9+1.4 ms vs 7.3 ms BGRA).
- **v2 `W` = min(align32(surface_w), plane_row)** per FreeRDP yuv.c:483 (verified
  myself in source) — not "16-aligned frame width" as rev 1 said.
- **Wire rects are exclusive** despite `InclusiveRectangle` typing; validate + drop.
- **Emit per region rect, not destRect** — destRect painting would miss chroma-only
  rects and repaint non-AVC surface content from the stale 444 buffer.
- **Stats blindness**: vendored-client AVC failures never reached GfxStats → new
  `on_decode_failure` seam; AVC420's frame-smaller-than-rect arm currently kills the
  channel — fixed to skip+count.
- **Vendored egfx suite is currently red** (stale reset_graphics test asserting
  pre-patch behavior) and not run by the root cargo test — fix + name the command.
- **FreeRDP differential oracle** available on this machine (3.27.1 installed,
  `primitives_get()` exports the exact combine functions; tools/codec-oracles pattern
  exists) — replaces the self-agreeing round-trip splitter as the primary oracle.
- **Combination math moved to ironrdp-graphics** (repo's codec-math crate).
- ROI enlargement dropped for absolute-coordinate index mapping (no alignment
  constraints, no stale-fringe writes).

Refuted (did not survive): "single VT session corrupts interleaved streams" — the
probe used two independently-encoded ffmpeg streams; Windows' AVC444 pair is jointly
encoded for sequential single-decoder decode (FreeRDP field evidence). Kept as a live
acceptance guard (numeric color check on captured buffer) rather than a design change.

## External review (Codex gpt-5.6-sol, xhigh, one pass)

Nine findings, all folded (one reframed):

1. **2x2 chroma reconstruction missing** — confirmed in prim_YUV.c:340-371: the
   even/even chroma sample is the encoder's block average; RGB pass must reconstruct
   `4*p00 - p01 - p10 - p11` with CONDITIONAL_CLIP (threshold 30, keeps the average
   for small deltas). The biggest catch of the round — rev 2 omitted it entirely.
2. Absolute mapping vs FreeRDP ROI phase → oracle comparison domain constrained to
   phase-aligned rects (reframed: we keep absolute mapping; unaligned rects pinned by
   our own fixtures).
3. Guard strengthened: decoded dims must equal align16(surface dims), not merely
   aux == main.
4. H.264 state lifetime across ResetGraphics stated explicitly (reset stays; Windows
   follows with SPS+IDR).
5. SPS ABAB-oscillation guard inside the decoder (reject without rebuild).
6. Client-level LC=0/1/2 tests with distinct rect lists (stub YUV decoder).
7. Acceptance 2b gains saturated-color numeric checks + P-frame-heavy capture timing.
8. decode_yuv420 takes an out-param; client owns two scratch frames.
9. on_decode_failure carries a reason string.

Design marked SELF-APPROVED (rev 3). Proceeding to implement.
