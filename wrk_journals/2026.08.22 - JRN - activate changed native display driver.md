# Activate changed native display driver

## 2026-08-22

- The v0.1.118 deploy copied the integrated cursor-capable IDD artifacts into
  `C:\mdrdp\v0.5.0`, but reported driver 0.3.0.1 current and skipped installation.
- Inspection confirmed MDR-BUG-FLU-00030 changed the driver DLL without changing the
  INF `DriverVer`. MDR-BUG-FLU-00026 also allows the exact-stack fast path before it
  checks package identity, so a same-length version bump alone would still be skipped.
- Intended fix: make active/staged driver identity part of exact-stack evidence and
  assign the changed package version 0.3.0.2.
- Design review survivors added a present-instance-bound driver query and a final
  active-package oracle. A green agent alone is not evidence that Windows selected the
  newly staged package.
- Regression proof: with every other exact-stack condition satisfied, stale driver
  0.9.0.0 incorrectly returned the fast path before the fix. A second test showed final
  verification incorrectly accepted active 1.0.0.1 when 1.0.0.2 was required. The
  probe-binding assertion also failed when its present-instance variable was deliberately
  corrupted. All three now pass restored.
- Validation passed all 739 root tests (including 22 focused deploy tests), workspace
  Clippy with warnings denied, formatting, the IDD PE build/sanity check, and both
  Windows Rust cross-checks. The
  single independent code review found no actionable defect. The simplicity pass kept
  the final probe explicit; extracting a one-call wrapper would add indirection without
  reducing policy duplication.
