# Rhydra tranche 6b — HEVC build journal

## Scope

Implement revision 3 of the single-stream HEVC design, prove it on quench, and use
the resulting HEVC tail measurement for the tranche 7 IddCx decision.

## 2026-08-20 — host and wire foundation

- Moved the native transport dialect from v3 H.264 to v4 HEVC while leaving the
  legacy RDP H.264 path alone.
- Configured the Windows encoder for HEVC Main 4:2:0 8-bit, High tier, Level 4.1,
  studio-range BT.709. Low-latency acceptance is mandatory; refusal stops startup.
- Replaced H.264 NAL parsing with HEVC two-byte-header parsing. The live path now
  validates profile, tier, level, chroma, depth and dimensions in every epoch.
- Made epoch transitions fail closed. A new epoch cannot paint before an IRAP, a
  bare IRAP without cached VPS/SPS/PPS is withheld, and MF clean-point claims are
  cross-checked against the bitstream.
- Added exact rectangle-union area and per-frame raw-rectangle attempt/result
  evidence. Unchanged-region AU bytes are explicitly a proportional estimate;
  HEVC cannot attribute compressed bytes spatially without slice parsing.
- New tests were observed red before implementation: missing HEVC NAL helpers,
  missing stream-contract validation, parameter sets ordered after an IRAP, wire
  v3 still accepted, overlapping rectangle area, and the byte-ratio calculation.
- Green evidence: 292 portable server tests and both Windows target checks. The
  only Windows output was the existing non-fatal missing-icon warning.

Client wiring, release/live quench evidence, the one-hour load run, and the IddCx
decision remain open.

## 2026-08-20 — native and standalone clients

- Added an mdrdp-owned `VideoDecoder` for the native HEVC stream. The RDP/EGFX
  H.264 decoder and capability path remain unchanged.
- VideoToolbox session creation now supplies VPS/SPS/PPS through CoreMedia's HEVC
  format-description API and requires hardware acceleration. Output is restricted
  to studio-range `420v`; the decoder applies an explicit BT.709 conversion.
- The native session and spike viewer use the HEVC decoder and report HEVC in the
  title/HUD statistics.
- Both native consumers require wire v4. The standalone viewer validates the first
  complete message as a v4 server header before it can dispatch any video.
- Green evidence: 707 root tests, 73 viewer tests including loopback, root and
  viewer clippy with warnings denied, formatting, and both Windows target checks.

Release/live quench evidence, the one-hour load run, and the IddCx decision remain
open.
