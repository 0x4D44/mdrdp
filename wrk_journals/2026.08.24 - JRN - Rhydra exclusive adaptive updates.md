## Green unit 1 — exclusive coverage planner

- Added a portable codec-block planner. Full fallback is a separate enum state; incremental output
  owns every changed block through exactly one of move, raw, or video.
- The new regression test was observed failing to compile before the planner existed. It now checks
  all 65,536 damage masks on a 4×4 grid, plus precedence, invalid candidate coverage, geometry,
  overflow, and exclusive full fallback.
- Correctness review challenged priority and partial validation. Move ownership legitimately wins
  because a move representation includes its required raw dirty remainder; all planning mutates only
  local scratch and returns no partial plan on error. The findings did not survive refutation.
- Simplicity review removed an internal many-argument helper suppression by grouping immutable grid
  geometry. No abstraction or dependency was added.
- Focused tests and formatting are green. Strict whole-crate Clippy is blocked by existing dead-code
  and style warnings in untouched modules; no new warning names `adaptive.rs`.

## Green unit 2 — atomic move composition

- Added the portable move compositor used by the future bulk update message. It validates the
  canvas, every source/destination, every raw remainder, and cumulative move/raw area before any
  visible mutation. It stages all move sources in one canvas-bounded buffer, applies moves in wire
  order, then paints exact raw pixels.
- The overlapping-source regression was observed compile-red before `MoveRect` and the compositor
  existed. A separate raw-area oracle was deliberately observed red against the implemented limit,
  then corrected; both move and raw staging now prove one-canvas ceilings.
- Correctness review challenged whether later invalid raw data could leave an already-moved canvas.
  It cannot: all raw validation precedes staging and mutation, and the regression compares every
  byte with the original canvas after refusal. Saturating area accounting also fails closed.
- Simplicity review retained one contiguous staging buffer instead of per-move allocations and
  shared the existing validated BGRA blitter rather than adding another pixel conversion path.

## Green unit 3 — baseline-bearing move payload

- Added a portable move payload: exact baseline sequence, ordered move records, then the existing
  frame/geometry/raw-rectangle payload. Raw-only traffic cannot use this bulk form; it remains on
  the independent low-latency rectangle message.
- Round-trip and every-truncation tests were observed compile-red before the codec existed. Decode
  now rejects a missing move, a non-older baseline, out-of-frame moves, and cumulative move or raw
  coverage beyond one canvas before returning anything paintable.
- Adversarial review challenged nested reuse of the existing rectangle payload. It survived: the
  layout has one sequence/geometry source of truth, reuses the mature strict decoder, and adds only
  ten prefix bytes plus twelve bytes per move. A separate duplicate parser would add more attack
  surface without removing bytes.
- Quality review added sender-side assertions for the two protocol invariants it can prove cheaply:
  a bulk move payload is non-empty and its baseline is older than its result.

## Green unit 4 — atomic regional video payload

- Added one portable video message containing the complete logical tile set, update kind, codec
  block size, exact paint coverage per tile, and every Annex-B access unit.
- Decode preallocates at most the planner's block ceiling, rejects duplicate tile IDs and duplicate
  block coverage, caps total coverage records and AU bytes, and refuses trailing or truncated data.
  Regional coverage cannot claim the full frame; full/recovery coverage must claim every block;
  recovery additionally requires an H.264 IDR from every tile.
- The codec began compile-red. Independent field-offset, aggregate-AU, and recovery-IDR oracles were
  each then observed red before their expectations were corrected, avoiding a self-round-trip-only
  proof.
- Adversarial review challenged rectangle overlap checks and full-frame semantics. A bounded block
  ownership bitmap survived as the simpler answer: it proves disjointness and completeness in one
  pass and naturally handles partial edge blocks.
- Quality review separated the reserved-byte refusal from rectangle errors. No new dependency or
  dynamic rectangle codec was introduced.

## Green unit 5 — planned tile assembly

- Added a bounded assembler that registers the exact tile IDs selected by each video plan before
  encoder submission. A one-tile regional update completes without waiting for the unchanged tile;
  multi-tile updates still retire in capture order.
- Tests were observed compile-red first. They now cover one selected tile, out-of-order completion,
  unselected/late output suppression, and whole-plan eviction at the pending budget.
- Correctness review confirmed that eviction must retire the whole plan even though the encoder may
  later emit one of its AUs. The assembler ignores that late output; the caller receives the drop
  count and must enter all-tile IDR recovery.
- Simplicity review kept the existing fixed assembler intact until the Windows pipeline switches;
  the new type carries only the per-frame plan and selected tile slots it actually needs.

## Green unit 6 — shared coverage geometry

- Added portable conversion from row-major codec blocks to coalesced exact pixel regions, including
  partial frame-edge blocks, plus global-coordinate tile intersection.
- The first geometry tests were observed compile-red. Adversarial review then found that a valid
  final block could hide a consecutive out-of-frame block inside one run; its focused oracle was
  observed red and the run scan now rejects that exact case.
- Coalescing extends only identical horizontal runs on adjacent rows. It therefore reduces GPU copy
  and wire rectangle count without ever filling a hole or claiming an unchanged block.

## Green unit 7 — persistent codec canvas

- Added one persistent BGRA texture per future H.264 tile. The update operation copies only the
  planner-owned video regions from the captured desktop and leaves raw/move-owned and unchanged
  pixels at the encoder's last shared state.
- The portable clipping and coalescing logic was proved test-first in green unit 6. This Windows
  adapter translates each clipped global rectangle once into tile-local destination coordinates;
  a tile with no selected coverage reports that it needs no access unit.
- Correctness review checked source/destination bounds and overlapping coverage. Tile layout owns
  the source bounds, intersection proves destination bounds, and the planner already guarantees
  disjoint coverage. Re-copying an accidental overlap would be harmless but is not relied upon.
- The documented Windows cross-check is green. It reports only the existing viewer unused-argument
  warnings and the deliberately not-yet-wired planned-assembler dead-code warnings.

## Green unit 8 — coverage-limited client video commit

- Added the new atomic video-update message type to the shared framing and native client dispatch.
  The handler preflights every tile and coverage rectangle against the probed layout before any
  decoder reference advances, then commits all selected regions in one surface generation.
- The regression was observed compile-red before the handler existed. It bootstraps two tiles,
  decodes a later full tile, and proves that only one declared pixel changes while every other
  decoded-but-unowned pixel remains byte-for-byte at its prior value.
- Correctness review rejected allowing a normal full-coverage P-frame to close a sequence gap:
  complete visible coverage does not repair a missing decoder reference. Only an all-tile IDR
  recovery may bootstrap or jump a gap; regional and ordinary full updates must be adjacent.
- Quality review removed a full-tile duplicate copy: one-region whole-tile updates now hand the
  decoder buffer straight to the atomic compositor. Regional updates pack only their declared
  regions. Focused native-session tests and the Windows cross-check are green.

## Green unit 9 — H.264 runs through persistent canvases

- Wired each H.264 tile to its persistent BGRA codec canvas and changed its converter to tile-local
  geometry. The capture loop currently copies the whole tile before every encode, preserving the
  previous visible behavior while proving the new reference plane independently of selection.
- HEVC fallback remains on its existing direct full-desktop crop. It cannot accidentally advertise
  or depend on regional state.
- Correctness review checked command ordering and geometry: copy and video-process commands use the
  same immediate D3D11 context, while the canvas and converter have identical tile dimensions.
- The Windows cross-check is green with only the already-recorded warnings.
