# Wait for active driver evidence

## 2026-08-22

- v0.1.119 installed and bound IDD 0.3.0.2, but its immediate final full-probe sample
  returned 0.3.0.1 and deploy reported failure.
- A later query of the same present instance reported `oem104.inf`, driver 0.3.0.2, and
  the unchanged verify-only deploy passed. The strict oracle is correct; its one-shot
  sampling is not.
- Added a read-only `driver-status.ps1` sampler. It re-enumerates the present healthy
  device and signed-driver rows, bounds each CIM query to two seconds, and returns the
  last structured observation after a 30-second deadline. Rust requires exactly one
  device, exactly one matching row, and the expected raw version.
- Regression proof: the initial placeholder classifier accepted stale, absent,
  ambiguous, and query-error evidence, so the new rejection test failed. The script
  contract test also failed against a deliberate missing marker before its real bounded,
  read-only assertions replaced that marker.
- Quench exercised both paths without mutation: 0.3.0.2 matched immediately; a requested
  9.9.9.9 timed out after one second and returned the live 0.3.0.2/oem104.inf evidence
  followed by the sentinel.
- Independent review found that unvalidated INF version text reached the remote
  PowerShell command. A failing regression reproduced the injection-shaped value; the
  INF parser now accepts only four decimal components in the Windows 16-bit range.
