# Quench `marti` 200% native reprovision

## Intent

Move quench's supported native console from `ano` to the existing `marti` profile, set the
5K IDD desktop to 200%, and leave Arthur a flag-free saved connection. No reboot and no
dynamic logon machinery.

## Chronology

- Preflight found `ano` active on console session 2 and `marti` disconnected in session 3.
  SSH key authentication succeeds independently as both `ano` and `marti`.
- The current `rhydra-agent` scheduled task is interactive/highest under `ano`; the agent
  and IDD therefore cannot simply remain there after the console transfer.
- The saved Quench favourite already names `user@example.com`, but its host is the
  mixed-case short name `Quench`. OpenSSH resolves `quench.lan.example` and lowercase `quench`
  to `ano` automatically, while `Quench` falls through to the local username. The favourite
  needs the FQDN, not a stored SSH user.
- Fullscreen on this Mac measures 5120x2880 physical / 2560x1440 logical and requests 200%.
  The overnight soak's 100% result came from its explicit `--size 5120x2880` compatibility
  path, not from fullscreen scale detection.
- Preflight identified `MDR-BUG-FLU-00026`: a same-version deploy can take its size-based
  fast path and preserve the `ano` task. The migration will quiesce and recoverably rename
  the old v0.5.0 directory before deploying a clean v0.5.0 from integrated trunk.
- Two independent reviewers challenged rollback, ownership verification, scale transition,
  favourite alias/mode selection, and end-to-end audio/clipboard evidence. The surviving
  findings are folded into the HLD. The SSH-user objection was refuted: the final tunnel
  may remain `ano`; only deploy requires its SSH principal to match the console owner.
- The one-pass Claude/Fable review ran successfully. It confirmed the core deploy and scale
  assumptions in code. Medium findings added a pre-mutation `marti` elevation check, an
  explicit failed-partial-directory rollback step, and an RDP escape hatch for an unexpected
  initial Windows scale. Low findings tightened quiesce/transfer ordering, `tscon` identity,
  and remembered-fullscreen handling. The suggested fleet-board check was rejected because
  it cannot establish interactive idleness and Arthur has explicitly authorised the switch.
- Integrated-trunk artefacts built cleanly. Quench moved from `ano` console session 2 to
  `marti` console session 3 without a reboot. The old task was uninstalled cleanly and its
  exact directory preserved as `C:\mdrdp\backup-v0.5.0-ano-20260821`. A fresh deploy created
  an interactive `marti` task; agent, creator, and server all ran in session 3 and doctor
  was green.
- Windows Display Settings was driven through the supported UI. The physical 1920x1080
  monitor is display 1 and the 5120x2880 rhydra IDD is display 2. The IDD was explicitly
  selected and changed from 100% to 200%; a local screenshot confirmed both 5120x2880 and
  200% under the `user@example.com` profile.
- Acceptance then exposed `MDR-BUG-FLU-00028`: `rhydra-agent status` reported effective
  scale 0/unknown at 200% even though Windows had applied it. The agent runs DPI-unaware and
  calculates a physical midpoint before a DPI-virtualised `MonitorFromPoint` call; at 200%
  that point falls outside the logical IDD. The exact fullscreen gate correctly refused the
  unmeasurable state. A narrow shipped fix is required before reprovision acceptance can pass.
- Cross-family code review found no blocker. It correctly rejected a first regression shape
  that constructed `WinOps`, because that constructor may recover a real audio lease on a
  Windows test host. The test now invokes a side-effect-free reconcile-thread initializer.
  A process-wide setter also proved too brittle: the isolated Windows test harness had
  already fixed process awareness and returned access denied. The final fix sets only the
  agent reconcile thread to per-monitor-v2, which is the thread performing every display
  query.
- The Windows regression was executed on Quench as an isolated test binary. With the
  initializer deliberately disabled it failed `0 passed; 1 failed`; after restoration it
  passed `1 passed; 0 failed`. Neither run touched the live task, display, or audio policy.
- The integrated fix made monitor lookup succeed, but the deployed agent then reported
  180% while Display Settings still showed 200%. `GetScaleFactorForMonitor` describes the
  monitor recommendation, not the effective user choice. Revision 2 keeps the physical
  coordinate fix and replaces only that semantic query with effective monitor DPI.
- Both revision-2 reviewers found that the proposed `GetDpiForMonitor` call is unsupported
  from the agent's per-monitor-v2 thread; the finding survived mutual refutation. Revision 3
  instead obtains effective DPI from a temporary hidden window on the IDD through the
  supported `GetDpiForWindow` API. Effective accessibility overrides remain intentionally
  in contract because the native client must match the DPI Windows gives application UI.
- The single Claude/Fable review accepted the window-based API boundary and found three
  useful hardening points: fail instead of continuing when PMv2 initialization fails, use
  a non-activating popup guarded by same-thread RAII, and prove live 200 -> 100 -> 200
  tracking without restarting the agent. These are folded into revision 3. Its suggestion
  to compare against the unsupported API was rejected because the observed disagreement is
  the regression, not a trustworthy oracle.
- The conversion regression was compiled for Windows and run directly on Quench. The stub
  returned `None` and the exact test failed against `Some(100)`; after implementation the
  same exact test passed. Portable server tests then passed 299/299. The bug record was
  reopened for the failed live verification and returned to Fixed at commit `0ce21e5`,
  pending a fresh deployed-host verifier.
- Independent code review found no code defect. Its sole P2 noted that macOS does not run
  the Windows-only conversion test; the recorded exact Quench red/green execution is the
  intended Windows lane, so no portability abstraction was added. The separate simplicity
  pass retained the small HWND guard because unconditional same-thread destruction is the
  real stable boundary. Server tests passed 299/299, clippy passed with warnings denied,
  `scripts/check-windows.sh` passed, Windows all-target test compilation passed, and the
  release Windows server build passed.
