# 2026.08.20 — client-negotiated 5K H.264 tiled native transport

The HEVC soak was stable but its 21.1 ms encode median killed the latency premise. The
replacement returns the native path to H.264 and makes 5K the target rather than 1080p.

The implementation now carries a client-selected IDD request through the control channel,
reconciles it before server spawn, advertises an exact tile layout in wire v5, encodes 5K
as two 2560x2880 Media Foundation streams, and composites them through two independent
VideoToolbox decoder sessions. The 2560x1440 control remains one stream.

Arthur corrected the initial removal of HEVC: it is retained as a startup-only fallback.
The host first constructs every H.264 tile. If that fails, partial AVC state is dropped and
one full-frame HEVC encoder is restored from the previous path. The header names
`hevc-420`, and the client selects its retained HEVC decoder. There is no mid-session codec
switch and no claim that fallback latency matches H.264.

Two correctness traps mattered:

- the old global exact-through gate would accept the first tile and suppress the second
  because both share one capture sequence; exactness is now per tile;
- counting each tile paint as a frame would double 5K FPS and close input latency on a
  half-frame; stats now complete only when every tile for the sequence has painted.

The IDD package advances to `DriverVer` 0.3.0.0. Deploy now compares that identity with
the driver bound to the live device; device presence alone previously let an older DLL
masquerade as current and would have left the old mode catalogue running.

The Windows mode path can set and verify backing pixels. Windows exposes a documented
effective-scale query but no documented per-monitor UI-scale setter. The agent now reports
actual and desired scale separately and gates encoder start on equality. This replaces an
earlier dishonest draft that merely echoed the requested percentage. Live 5K/200% will
therefore either prove the IDD already has the right scale or expose the remaining design
fork explicitly.

Local evidence before live deployment:

- rhydra portable suite: 298/298 green, including the HEVC fallback layout regression;
- mdrdp library suite: 715/715 green, including the HEVC header-contract regression;
- both workspaces pass `clippy -D warnings`;
- Windows cross-check and Windows rhydra clippy: mdrdp and rhydra host cfgs compile cleanly;
- Windows release cross-link: both rhydra executables link;
- IDD cross-build: driver DLL and creator EXE link and pass PE sanity checks;
- new tile exactness, logical-frame, scale-gate, stale-driver and HEVC fallback
  regressions were each observed red against the wrong implementation, then green.
