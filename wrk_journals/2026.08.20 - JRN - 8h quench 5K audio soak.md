# 8-hour quench 5K audio soak

## Mission

Run the deferred eight-hour native session on quench with the integrated 5K tiled-video
fix and periodic real VB-CABLE audio. Preserve enough evidence to judge audio clock drift,
loss, decoder health, session survival, and resource use without retaining screen or audio
content in the repository.

## Pinned build and conditions

- Source: `89b3d12b145deef63cb4d679b965c7dd1794dcfe` on `origin/main`.
- Client: installed release `mdrdp v0.1.112`, SHA-256
  `9054cf581f1767f5cb3dd36a506635740813a39f03ce84f839dc1113ff06d30e`.
- Host: quench, rhydra-agent v0.5.0, mdrdp IDD v0.3.0.1, native wire v5.
- Display: 5120x2880 @ 240 Hz, Windows scale 100%. The soak pins the explicit pixel size;
  the separate unsupported 200% scale prerequisite is not part of this run.
- Audio: verified base VB-CABLE loopback, 48 kHz stereo. A console-session scheduled task
  renders a 30-second tone warm-up, then a real 10-second 440 Hz-left/660 Hz-right WAV
  followed by 50 seconds quiet, repeating for the session. The warm-up ensures the
  client's one-shot signal oracle runs after the slower 5K encoder startup.
- Duration: 29,100 seconds (8 h 05 m), giving more than 28,000 post-warm-up one-second
  depth samples if the session remains healthy.

`TESTING-GUIDE.md` is absent. The repository HLD and prior partial-soak evidence therefore
supply the mechanics and oracles. The exact fixture was recovered from the earlier run:
one release client session throughout, `caffeinate`, periodic real console audio, metrics
JSON, final screenshot, client log, and host server telemetry.

## Decision trail

- Arthur explicitly released quench for eight hours after interactive testing.
- The failed fullscreen attempt left no viewer. Quench has active console user `ano`; the
  old `marti` session is disconnected. No reboot or device transition is authorised or
  needed for this soak.
- Pass requires a clean planned end, at least eight hours elapsed, at least 28,000 depth
  samples, median depth below 200 ms, maximum below 300 ms, trend within ±1 ms/hour, zero
  capture gaps, queue drops, overruns, device errors, and decode errors. High-water trims
  may occur during initial playout fill but must not keep growing during steady state.
  Periodic quiet intervals deliberately reset continuity; startup/final drain underruns
  are recorded separately from unexplained in-window faults.
- Local runtime artefacts are temporary and contain possible screen data. Only redacted
  numeric conclusions will be committed under `wrk_docs/evidence/` after completion.
