# 2026.08.20 — 5K tiled H.264 reference-chain recovery

Goal: turn the integrated 5K rhydra build on quench into a usable interactive session.

## Diagnosis

The size-aware IDD copy deadline fixed the original zero-frame fault: quench's shared pool
advanced normally. The next live run briefly painted 5K, then VideoToolbox rejected nearly
all tile AUs with `-12909` (`kVTVideoDecoderBadDataErr`). Server telemetry showed complete
two-tile output with no drops or timestamp mismatches.

Captured rejected access units decode in both FFmpeg/VideoToolbox and mdrdp's own decoder.
Changing output format and sample-buffer timing did not repair live sessions. One live
isolation was decisive: decoding both tile streams while suppressing canvas state changes
produced zero errors. The raw-rect path advances every tile's `exact_through`; the tiled AU
path then returned before decoding the same sequence. That discarded a predictive reference
picture. The next non-redundant P-picture correctly failed because its reference was absent.

The fix will preserve the decoder feed and suppress only redundant painting.

## Implementation and validation

The focused two-tile regression failed against the old gate: each decoder had consumed
only the first AU after a rect completed the next sequence. Moving the exactness return
below successful decode and decoded-size validation made the same test pass. Suppressed
AUs still bypass the canvas blit, tile completion, paint metrics, wake, and exactness
updates.

All 18 native-session tests passed. An independent code review found no concrete issue;
the follow-up simplicity pass kept the direct control flow and added no abstraction.

Two 5120x2880 quench sessions then completed with zero decode errors. The first captured a
complete 5K desktop. The second injected Start-menu and desktop-toggle activity to force
mixed rect/tile traffic: it painted 51 frames, wrote 16 input records, received 1,644,587
video bytes, and ended cleanly with zero decode errors. This discharges the live regression
criterion. Windows remained at its separately configured 100% scale.

Final local checks passed: formatting, clippy with warnings denied, and all 729 library,
15 binary, and 5 wire-deadline tests.

## Design review

Two independent reviewers and their cross-refutation produced no surviving findings. They
confirmed that decoded-size validation must remain before suppression and that the focused
test must prove both decoder calls plus an unchanged rect-painted canvas/frame count. The
single Claude/Fable pass could not run because its session quota was exhausted until 20:40;
this remains an explicit residual risk rather than a blocker.

## Other live findings

- Quench's 5120x2880 mode is active, but Windows scale is 100%. The 5K HLD deliberately
  treats 200% as an out-of-band prerequisite because Windows exposes no supported
  per-monitor scale setter. A fullscreen 200% request therefore waits until the console is
  manually set to 200%.
- `mdrdp deploy --force` can accept same-version, same-size stale artifacts as exact;
  MDR-BUG-FLU-00026 tracks that separate deploy defect.
