## Review round: two live-verified facts that rewrite the driver arm

While the reviewers ran, two one-command checks on quench settled the design's
two open host assumptions:

- **SSH sessions are elevated**: `whoami /groups` shows High Mandatory Level
  (S-1-16-12288) over plain SSH as ano. pnputil/certutil/schtasks all runnable.
- **testsigning is OFF on quench and the IDD driver runs anyway** (bcdedit
  {current} has no testsigning line; DISPLAY8 was alive all evening). mdrdp-idd
  is UMDF — user-mode driver signature policy accepts the self-signed cert
  chain (CN "mdrdp latency spike", in machine root + trustedpublisher, expires
  2027-08-17) without test signing. The README/deploy.ps1 testsigning phase is
  kernel-driver lore our driver does not need. Deploy therefore needs **no
  bcdedit gate and no reboot path at all**.

Scope/simplicity reviewer reported 9 findings, all substantive — headline: the
subcommand branch must precede the --help scan and the detach logic (else
deploy detaches and ssh prompts read EOF); quiesce keyed on exe presence, not a
control-port answer; preflight must check for an interactive console session;
Step enum closed at Run/Copy with decisions in pure functions; drop pnputil
text parsing (the idempotent script's exit code is the oracle); cut the posture
report to what deploy gates on; agent `status --wait` with exit 1 = "not green
yet"; versioned host directories restored (failure atomicity + rollback);
`StatusReport` gains a version field so the verify step can actually falsify
"new agent running".
