# HLD — size-aware IDD copy proof deadline

- **Status:** SELF-APPROVED
- **Bug:** MDR-BUG-FLU-00025

## Intent and scope

Make the 5K IDD pool publish complete frames on quench by giving its full-surface GPU copy a realistic, still-bounded proof deadline. This does not solve the separate idle-desktop bootstrap defect (MDR-BUG-FLUX-00011), promise sustained 5K/240 capture, or redesign the synchronous shared-pool copy.

## Evidence

The live 5120×2880 session had a healthy generation-3 pool but stayed at zero published frames. A 100-sample D3D11 `CopyResource` probe on quench measured 2.001 ms minimum, 2.095 ms median, 6.815 ms p95, and 6.848 ms maximum. Every copy therefore exceeded the driver's fixed 2 ms limit and took the slot-invalidation path.

## Approach and file impact

- `tools/latency-spike/idd/driver/SharedPool.cpp`: derive the deadline from surface pixels with overflow-safe 64-bit arithmetic. Scale linearly from 2 ms at 1080p, round up in microseconds, and clamp to 2–16 ms. The 5K budget is 14.223 ms, over twice the measured worst sample. Compute it once when the pool starts and make the runtime wait consume that value. Start the elapsed-time sample before `CopyResource`, so submission and `Flush` cannot consume the budget and then receive a fresh polling budget.
- `tools/latency-spike/idd/driver/SharedPool.h`: store the per-pool deadline used by `WaitForCopy`.
- `tools/latency-spike/server/src/win/idd_source.rs`: correct the consumer comment that currently assumes the driver always releases its keyed mutex within 4 ms. The existing `Taken::Busy` path safely skips a contended slot.
- `tools/latency-spike/idd/driver/mdrdp-idd.inf`: advance the driver package version so Windows installs the changed DLL.
- Add compile-time assertions that call the shipped budget helper for zero, the lower floor, every advertised resolution, upward rounding, and `UINT32_MAX` dimensions at the upper cap. They exercise the pure rule without a GPU mock, while source review confirms `WaitForCopy` uses the stored result and the old fixed runtime constant is gone.

## Acceptance criteria

1. The pre-fix fixed 2 ms implementation fails the new 5K budget assertion.
2. The shipped helper uses 64-bit intermediates and yields 2 ms for zero/small/1080p surfaces, 14.223 ms for 5K, and 16 ms for oversized surfaces.
3. The IDD cross-build completes and its PE sanity checks pass.
4. Install driver package `0.3.0.1` from integrated trunk and verify it is the active package. During a 30-second 5120×2880@240 native session with deliberate desktop activity, session frames and bytes both increase above zero; a DebugView cadence sample reports `published > 0` and zero copy-wait timeouts.
5. Existing shared-pool integrity remains: a copy is published only after its event query proves completion, and a failed proof still invalidates the slot.

## Decision log

- Scale from the existing 1080p/2 ms baseline because copy cost is dominated by surface bytes. Size-awareness preserves the tight stuck-GPU bound at smaller modes instead of raising every mode to 16 ms.
- Cap polling at 16 ms. Direct3D calls themselves cannot be pre-empted, so this is not a hard wall-clock bound on a misbehaving driver; starting the sample before submission prevents normal submission time from being excluded.
- Retire the old claim that the driver mutex hold must stay below both 4 ms and the 240 Hz frame interval: measured healthy 5K copies already exceed both in the tail. The consumer skips `Taken::Busy` slots, so a longer hold cannot wedge it. A stuck 5K GPU may now back-pressure the swap-chain thread for up to 16 ms; this bounded degradation is accepted to restore usable 5K output. Sustained 5K/240 remains outside this fix.
- Do not remove the query wait. Publishing before copy completion could pair a truthful record with incomplete pixels.

## Review

Two adversarial reviewers found no critical defect. Findings that survived cross-refutation were folded in: include submission/flush in elapsed timing; assert every mode and extreme dimensions; prove runtime wiring; accept and measure 240 Hz back-pressure; correct the mutex comments; and pin the live duration, counters, cadence, timeout count, and installed package identity. The standalone probe is strong but not exact in-driver telemetry, so the live cadence check remains the final root-cause oracle. Timeout invalidation is unchanged and retained by source review; a deterministic GPU-query failure harness would require a disproportionate D3D mock and remains a residual test gap.

External Claude/Fable review independently confirmed the root-cause fit and the 14.223 ms calculation. It added the explicit 2 ms floor, overflow-safe shipped-helper assertions, keyed-mutex comment correction, and active-desktop live check. Its suggestion to yield the thread after 2 ms was rejected for this narrow fix: changing polling cadence would add an unmeasured latency variable; bounded busy-spin remains the residual CPU risk.
