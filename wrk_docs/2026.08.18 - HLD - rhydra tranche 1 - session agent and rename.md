# HLD — rhydra tranche 1: the session agent, and the rename

Status: SELF-APPROVED
Parent: `wrk_docs/2026.08.18 - HLD - native product shape and session ownership.md`
(§3.2, §3.4, §9 step 1). This is the first productization tranche of the native
transport; Arthur's go was given 2026-08-18 evening.

## 1. Intent (one line)

Make a host's capture stack come up by itself and stay up — a logon-task **session
agent** that owns the IDD creator, the display mode, and the capture server — and
carry the `rhydra` name into the tree in this first productization commit.

## 2. Scope

**In:**
- Rename: package `spike-server` → `rhydra`; binary `spike-server` → `rhydra-server`;
  new binary `rhydra-agent`. Viewer's path dependency and `spike_server::` imports
  updated. Directory stays `tools/latency-spike/server` for now.
- The agent: reconcile loop (creator alive → device present → display mode set →
  server running), restart-with-backoff supervision, loopback control port with a
  JSON status/restart protocol, `install`/`uninstall` subcommands registering the
  logon scheduled task.
- Bring-up on quench: install the agent, prove the loop end-to-end (including the
  headless drain-client capture smoke), prove reboot survival with auto-logon.

**Out (explicitly):** `mdrdp deploy` (step 2); `--native` client mode (step 3); the
health/remediation ladder and `--doctor` (step 4); clipboard/audio (steps 5–6);
retiring the quench rig tasks (deferred until tonight's queued measurements are
done); renaming `spike-viewer` (it is scheduled to be absorbed into mdrdp at
step 3 — renaming a crate that is about to disappear is churn); moving directories.

## 3. Approach

### 3.1 Crate shape

The agent is a second `[[bin]]` in the (renamed) `rhydra` crate, not a new crate.
It shares the crate's build config, the cross-compile environment, and later the
wire/stats types; a separate crate would duplicate all three to save nothing.

- `src/control.rs` (portable): the control protocol. Loopback TCP, one JSON object
  per line, clients served one at a time with a short read timeout (a silent
  client cannot wedge the listener). Requests: `{"cmd":"status"}`,
  `{"cmd":"restart-server"}`, `{"cmd":"shutdown"}` (kill children, exit — the
  sanctioned stop path; `schtasks /end` provably orphans children). Responses
  carry `schema` (integer, starts at 1); `status` distinguishes every failure
  mode the wedge post-mortem catalogued: creator alive?, device present?,
  display mode (actual vs desired), server alive?, and per-child restart count,
  last exit code, and current backoff. Unknown `cmd` → error response, connection
  survives.
- `src/agent.rs` (portable): the reconcile state machine. Owns desired state and
  backoff; talks to the platform through a small trait (`AgentOps`) so the whole
  loop unit-tests on macOS with a scripted fake. **No fatal states**: every step
  (creator spawn, device arrival, mode set, server spawn) retries on the next
  tick forever — device arrival takes seconds and an onlogon task can fire
  before the desktop settles, so "not yet" is normal, and `status` names the
  stuck step. The display-mode step is an idempotent check (actual vs desired
  each tick), not a once-after-attach flag — a re-created device comes back at
  its default mode. Backoff for a crash-looping child: 1 s doubling to a 30 s
  cap, reset after 60 s of health.
- `src/win/agent_ops.rs` (Windows): the real `AgentOps` — spawn and watch
  `mdrdp-idd-create.exe --wait`, find the `mdrdp latency-spike display` via
  `EnumDisplayDevicesW`, read/set 1920x1080@240 via `EnumDisplaySettings` /
  `ChangeDisplaySettingsExW`, spawn and watch `rhydra-server.exe` with
  stdout/stderr to `logs\server.log`. **Adoption sweep at agent start**: kill any
  pre-existing `rhydra-server.exe` / `mdrdp-idd-create.exe` by image name before
  spawning — a hard-killed agent (Drop never runs on `taskkill /f`) leaves
  orphans holding the device and ports 9500–9502, and without the sweep the
  restarted agent crash-loops on bind. Single-owner semantics: while an agent
  runs, it owns both images on the box.
- `src/bin/agent.rs`: `rhydra-agent run` (the task target: logging to
  `logs\agent.log`, reconcile loop + control listener), `rhydra-agent install`
  (registers the logon task via `schtasks /create /sc onlogon /rl highest`,
  then starts it now via `schtasks /run` — onlogon alone would not fire until
  the next logon), `rhydra-agent uninstall` (control `shutdown` first, name-kill
  fallback, then task deletion).

### 3.2 Layout and lifecycle decisions

- **Host home is `C:\mdrdp\`**: `rhydra-agent.exe`, `rhydra-server.exe`,
  `mdrdp-idd-create.exe`, `logs\`. The agent resolves its siblings relative to its
  own exe path — no env vars, no config file. The spike rig in `C:\mdrdp-spike\`
  is untouched by this tranche.
- **The server runs always-on** while the agent runs. Today's finding makes this
  free: a viewer-less server parks in 50 ms sleeps and captures nothing, so there
  is no on-demand lifecycle to build. Ports stay 9500 (video), 9501 (input);
  control is 9502. All three bind 127.0.0.1 only — SSH remains the security
  boundary.
- **The creator stays a supervised C++ child.** Absorbing device creation into the
  agent (SwDeviceCreate in Rust) is possible but rewrites a working, signed-cert
  moving part for no tranche-1 gain. The agent owns its lifetime, which is the
  actual product defect being fixed (the device died with ad-hoc processes and
  never came back after reboot).
- **Display mode set by the agent** (retiring `set-240.ps1`'s job): one
  `ChangeDisplaySettingsExW` after the device attaches. If the mode set fails, log
  and continue — a 60 Hz display is degraded, not down, and the status report says
  so.
- **schtasks over the COM Task Scheduler API**: one `std::process::Command` per
  install/uninstall, exactly the invocation the rig has proven for weeks, versus a
  COM interop module. Deploy (step 2) can revisit if it needs richer task
  definitions.

### 3.3 Host posture on quench

Reboot survival needs auto-logon (ownership HLD §3.1 posture). Bring-up sets the
standard registry auto-logon for `ano` (`AutoAdminLogon`/`DefaultUserName`/
`DefaultPassword` under Winlogon). The password lands plaintext in the registry:
acceptable for this box because `ano` is a documented throwaway account on a LAN
host we own, and this is precisely the v1 posture the parent HLD names. The
lock-screen policy is already permissive on quench (rig has run unlocked for
weeks).

## 5. Acceptance criteria

1. `cargo test` green on macOS in `server/` and `viewer/`; new portable tests cover
   the control protocol (parse/serialize/unknown-cmd/shutdown) and the reconcile
   loop (ordering: creator before mode before server; restart backoff and its
   reset; idempotent mode re-set after device re-creation; status snapshot
   correctness with distinct per-field fixture values so a swapped field cannot
   pass) — each new test proven to fail once against a broken implementation.
2. `./scripts/check-windows.sh` green (agent + rename included).
3. `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` green in
   both crates.
4. On quench: `rhydra-agent install` registers and starts the task; the agent
   brings up creator → device → 240 Hz → server; `status` over the control port
   reports the chain green; the headless drain smoke (tunnel + `nc -d` + posted
   keystrokes) captures frames; killing `rhydra-server.exe` gets it restarted by
   the agent; the agent is then stopped via control `shutdown`, its task disabled,
   and the evening rig left exactly as it was.
5. Reboot survival: with auto-logon set, a quench reboot comes back to a green
   `status` with no hands.

## 6. Risks and mitigations

- **Port collision with tonight's measurement rig** (both want 9500/9501): the
  agent is validated, then stopped via control `shutdown`, and its logon task is
  **disabled** (`schtasks /change /disable`) — a registered-but-enabled task would
  auto-start on any reboot before the queued A/Bs and take the ports. Re-enabled
  when the rig is retired. The adoption sweep kills only rhydra-named images, so
  it can never touch the rig's `spike-server-inc3.exe`.
- **Increment 4 rebase cost**: the un-integrated Increment 4 branch's viewer files
  import `spike_server::`; after this tranche lands, its rebase needs a one-line
  mechanical import fix. Known and accepted (same author owns both branches).
- **`onlogon` task semantics**: task must run in the interactive session with the
  interactive token — the rig's task pattern (same flags) has proven this class;
  verified live by criterion 4.
- **Child lifetime**: if the agent dies, orphaned creator/server would hold the
  device and ports. v1 kills children on drop and the install is a single task —
  acceptable; a job-object hard guarantee is noted for deploy hardening.
- **Auto-logon plaintext password**: accepted for throwaway `ano` on an owned LAN
  box; called out in §3.3 so it is a decision, not an accident.
