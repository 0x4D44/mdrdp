# HLD — P0a credential-free measurement harness

2026-08-14 · **Status: SELF-APPROVED** · Gauntlet part P0a

## Scope

The two measurements reachable without a credential, in Rust, as the first piece of the
scoreboard everything else is judged by:

1. **X.224 security-protocol negotiation** — what the server demands, observable before any
   authentication.
2. **TCP handshake RTT** — the latency floor.

Ports the throwaway Python probe from the P1 spike into the repo, properly, and replaces
the provisional 4.20 ms baseline with one that meets the plan's pass condition.

**Out of scope:** anything needing a credential, any session-level measurement, the HUD.

## Pass condition (from the Phase 0 plan)

Release build emits JSON containing the negotiation verdict matching the spike, and TCP RTT
over ≥1000 samples spread across ≥3 times of day, p50 stated with a 95% CI.

One sampling run cannot span three times of day, so the harness separates **collection**
from **summary**: batches append to a JSONL file, and a summarise step merges them and
reports whether the coverage requirement is actually met. The tool reports coverage
honestly rather than asserting it.

## Approach

`mdrdp` becomes lib + bin so the app and the harness share one implementation — the
negotiation and statistics code is what the HUD will later reuse, so this is not
speculative structure.

```
src/lib.rs              pub mod probe
src/probe/negotiation.rs  X.224 CR encode, CC parse, protocol/failure names
src/probe/stats.rs        percentiles, nonparametric median CI
src/probe/rtt.rs          TCP handshake sampling, time-of-day coverage
src/bin/probe.rs          CLI: negotiate | rtt | summarise
src/main.rs               unchanged app skeleton
```

`probe negotiate <host>` · `probe rtt <host> --samples N --out <file>` ·
`probe summarise <file>`

## Decisions

- **Median CI is nonparametric, not mean ± 1.96σ.** A confidence interval for the mean says
  nothing about the median, and RTT distributions are right-skewed, so the two differ
  materially. Uses the order-statistic method (normal approximation to the binomial).
  Quoting a mean-CI beside a p50 would be a number that looks rigorous and is wrong.
- **Parsing is bounds-checked and returns `Result`, never panics.** It reads network data
  from an unauthenticated peer. A panic here is a crash the far end controls.
- **Time-of-day coverage is measured in UTC hours** — std has no timezone database, and
  pulling one in for a coverage heuristic is not worth a dependency. Stated in the output so
  the number is not mistaken for local time.
- **New dependencies: `serde` + `serde_json`.** The pass condition mandates machine-readable
  output; hand-rolling JSON serialisation would be worse in every respect. No other deps —
  argument parsing uses `std::env::args`.

## Acceptance criteria

1. `probe negotiate temper` reports HYBRID_EX selected, and HYBRID_REQUIRED_BY_SERVER when
   offering legacy security — matching the spike's captured bytes.
2. Encoding a connection request produces the exact bytes the spike sent.
3. Parsing reproduces the correct verdict from both real captured server responses.
4. Malformed, truncated and hostile input returns `Err`, never panics.
5. Percentile and median-CI maths verified against hand-computed values.
6. `summarise` reports sample count and distinct-hour coverage, and states plainly when the
   ≥1000-sample / ≥3-hour condition is not met.
7. `cargo fmt`, `cargo clippy -- -D warnings`, `cargo test` all clean.

## Testing note

Per `CLAUDE.md`, each new test is made to fail once before being trusted. The parser tests
use **real captured bytes from the live host**, not constants this code derives — a test
that checks an encoder against its own decoder can only prove they agree with each other.
