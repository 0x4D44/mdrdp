# Rhydra metadata-first inferred moves

Status: SELF-APPROVED

## Goal and scope

Make screen moves a first-class low-latency update: preserve real capture metadata where it
exists, infer terminal-style vertical scrolling on modern IDD, send the small move description
as soon as its baseline is ordered, encode only the pixels the move cannot reproduce, and apply
the common client move without staging a 5K-sized copy.

This change covers:

- IDD shared-section layout v2, preserving current-frame dirty and ordered move metadata while
  retaining the accumulated final-pixel coverage fallback;
- bounded, exact vertical-translation inference against Rhydra's existing retained previous
  frame for IddCx 1.7 and later, where Windows no longer supplies moves;
- a wire-v9 move prelude on the sparse lane, a baseline barrier on the bulk lane, and an
  independently selected raw, regional-H.264, or empty remainder;
- overlap-safe in-place client copying for a single move, with the existing staged semantics for
  potentially interdependent multi-move batches;
- telemetry and focused correctness/performance tests.

It does not introduce arbitrary optical flow, infer window drags or horizontal motion, change
the GPU/CPU ownership of the macOS canvas, add a transport, or change the full-frame recovery
contract. HEVC remains the full-frame fallback and does not gain regional updates here.

Microsoft removed move metadata at the source: from IddCx 1.7 onward
`IDDCX_METADATA.MoveRegionCount` is always zero and dirty rects include the changed pixels. See
<https://learn.microsoft.com/en-us/windows-hardware/drivers/display/iddcx1.7-updates> and
<https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/iddcx/ns-iddcx-iddcx_metadata>.
The inference path is therefore required for this work to improve Quench rather than merely
exercise an old API.

## Approach

### 1. Preserve native metadata without weakening the fallback

Set `IDDCX_ADAPTER_FLAGS_CAN_USE_MOVE_REGIONS`. It has no effect on current Windows, but it is
required for pre-1.7 runtimes to provide moves rather than silently turn them into dirty rects.

Layout v2 keeps each slot's existing accumulated coverage for
`(DirtySinceFrameSeq, FrameSeq]`. It adds current-frame dirty rects and packed moves
(`source point + destination RECT`) in the unused part of the slot's 4096-byte page. Counts use
the existing absent/overflow sentinels. The driver retrieves metadata into fixed scratch buffers,
folds dirty rects and move destinations into every accumulated coverage record, and publishes the
current ordered metadata only with the matching copied texture under the slot seqlock.

The server may replay current moves only when its last consumed IDD frame is exactly
`FrameSeq - 1` and both current metadata lists are complete. Any gap, overflow, query failure, or
invalid geometry uses the accumulated final-pixel coverage. Thus the optimization can disappear
without omitting pixels.

### 2. Infer modern-IDD vertical moves conservatively

The existing `PixelDiff` already retains the last consumed frame on the GPU. Inference runs only
when all of these hold:

- the source supplied no native move;
- the codec is H.264, the viewer has a sparse channel and is outside recovery;
- the retained texture corresponds to the immediately preceding scheduled frame;
- the claimed change exceeds the raw-rectangle budget and would otherwise enter H.264;
- a clipped dirty region is large enough to make a move useful.

Candidate generation tests bounded vertical offsets in both directions using small, distributed
row samples. Only the single best candidate receives a complete check. The complete check compares
the current destination with the shifted previous-frame source on the existing 64x16 desktop
grid. Every unequal tile becomes final-pixel remainder; exposed rows are remainder by definition.
The selected candidate must reproduce at least 75% of its destination and save more pixel area
than its descriptor costs. Constants are code-level safety/work budgets, not environment knobs.

The final remainder is exact coverage, not an optimistic claim: subtract the move destination
from the source dirty coverage, then add every unequal/exposed tile inside it. If geometry,
mapping, bounds, candidate limits, or the savings predicate fail, leave the original change
untouched. This deliberately spends the existing two staging copies only on large H.264-bound
regions; typing-class raw updates pay no inference cost.

Initially infer one vertical move per frame. That covers the primary terminal-scroll case and
keeps candidate choice and baseline reasoning small. Native IDD/DXGI batches remain ordered and
unlimited by raw-remainder size, subject only to existing canvas-sized safety bounds. Every source,
including DXGI, may replay a move only when the retained source frame is the immediately preceding
scheduled frame; accumulated metadata after a skipped or unsent frame falls back to final pixels.

### 3. Send move metadata before its independently encoded remainder

Wire v9 changes the move payload into a pixel-free prelude:

```text
baseline_seq, frame_seq, frame_width, frame_height
remainder_kind = none | raw | video
ordered move_count and move rectangles
```

The server chooses the remainder route from the final-pixel rects, then atomically admits two tiny
messages with one admission gate:

1. the move prelude on the sparse queue, after all older sparse pixels;
2. the matching baseline barrier on the bulk queue, after all older video.

The writers may deliver either first. The client registers both and applies the move only when
both lanes have reached the named baseline and the displayed block state matches it. The move is
then visible immediately. The raw remainder follows the prelude on sparse; a regional H.264
remainder follows the barrier on bulk; an empty remainder completes at move application.

Move destinations are not committed to the block-fence sequence until the declared remainder is
painted. Otherwise same-sequence remainder pixels would be suppressed. Any later pixel update
waits behind the pending move. A missing, duplicate, mismatched, malformed, or five-second-stalled
prelude/barrier/remainder fails the session closed; after a prelude is admitted, failure to enqueue
or produce its remainder is terminal rather than silently recovering over a provisional canvas.

The move itself has no raw-byte, rect-count, or remainder-size eligibility cap. One move frame has
one completion route: all remainder is raw when its exact rect set fits the existing raw budget;
otherwise all remainder is regional H.264 (or the existing full fallback when the regional planner
requires it). Avoiding a mixed raw/video completion keeps the cross-lane state machine finite while
still sending only the remainder coverage.

The lane which does not own the declared remainder waits on the rendezvous condition variable with
the pending move's absolute five-second deadline. Raw therefore holds the bulk pump while sparse
finishes; video holds sparse while bulk finishes. A missing remainder times out without requiring
another packet to wake either socket reader.

### 4. Apply the common client move in place

`SurfaceStore` remains the authoritative RGBA canvas. A GPU-only copy would leave that CPU state
stale and require a new GPU-authoritative compositor, so it is the wrong altitude for this change.

After validating the complete batch, one move uses `Vec::copy_within` row by row:

- upward moves copy top-to-bottom;
- downward moves copy bottom-to-top;
- overlap within a row uses `copy_within`'s memmove semantics.

This allocates no move-sized staging buffer and copies each moved pixel once. Multi-move batches
keep pre-update source semantics by staging all sources before any write, because one move's
destination may cover another's source. Dirty pixels still paint after all moves.

## Acceptance criteria

1. An adjacent layout-v2 IDD record yields ordered source/destination moves plus current dirty
   rects; a gap or incomplete current metadata yields only complete accumulated final-pixel
   coverage. Literal-offset Rust fixtures and C++ static assertions agree on every new field.
2. Portable inference recognizes up/down terminal-style translations with exposed and scattered
   changed pixels, reports every non-reproducible tile, and rejects ambiguous, low-savings,
   out-of-bounds, and non-adjacent cases without changing the original coverage.
3. Small typing-class changes never run inference. Telemetry reports native/inferred move counts,
   attempts, hits, and inference time so its cost and benefit are measurable.
4. A move prelude contains no pixel payload and enters the sparse priority queue before remainder
   readback/encoding. Its bulk barrier preserves both-lane baseline ordering.
5. No raw-remainder byte limit suppresses a valid move. Empty, raw, regional-H.264, and full-video
   remainders all complete the same exact logical update without sending move-reproduced pixels.
6. The client may display the move before a video remainder, but it does not advance block fences
   or allow a later update through until that remainder paints. Every mismatch, duplicate, drop,
   and timeout fails closed and reconnect recovery restores a full canvas. A missing remainder
   times out without requiring another packet to wake the check.
7. A single overlapping move in every direction uses the in-place path and produces the same
   pixels as a staged pre-update copy. Multi-move dependency cases retain the staged oracle.
8. New regressions are observed failing before their fixes. Formatting, lint, root tests, Rhydra
   server tests, macOS native tests, both Windows cross-checks, and the IDD driver build are green.
9. A live 5K/200% Quench terminal scroll reports inferred move updates, a materially smaller
   remainder than the moved area, no decode/ordering errors, and visually correct exposed rows.

## Decision log

- Infer moves on modern IDD. Preserving driver metadata alone was rejected because IddCx 1.7+
  guarantees zero move regions; Arthur chose bounded exact inference over switching back to the
  slower Desktop Duplication capture path.
- Keep CPU canvas ownership and use in-place memmove for one move. A GPU-only copy was rejected
  because the next CPU composite would overwrite it from stale authoritative pixels.
- Permit one inferred vertical move but preserve arbitrary native batches. This solves the proven
  terminal mainline without introducing general motion estimation.
- Show a provisionally moved canvas before its remainder, but delay exactness/fence commit. Waiting
  for H.264 would erase the latency benefit; claiming completion early would corrupt ordering.
- Fail the session after a post-prelude remainder failure. There is no safe local rollback once the
  client may have displayed the move, and reconnect recovery is already the canonical repair.
- Use one raw-or-video remainder route, not a mixed completion. Mixed routing saves little after a
  successful scroll move and doubles the pending-state/error surface.

## Review journal

Native reviewer seats were unavailable because the surfaced quota does not reset until
2026-08-27. The three requested roles and cross-refutations therefore ran sequentially under the
prompt's explicit fallback.

- **Correctness/concurrency review:** found that source metadata or inferred pixels are replayable
  only from the exact preceding scheduled canvas, not merely from any `last_scheduled_seq`. The
  protocol reviewer tried to refute this with lane ordering, but ordering cannot repair a source
  texture that the viewer never received. The finding survived and now applies to IDD, DXGI, and
  inference. It also confirmed that move destinations must remain uncommitted until remainder
  completion; the performance review's suggestion to commit at the early wake was refuted because
  same-sequence remainder would then be suppressed.
- **Latency/altitude review:** found that fully checking several sampled displacement candidates
  can multiply two 5K staging-map scans and put detection above the encode cost it replaces. The
  correctness review's concern about a missed candidate does not refute it: a sampling miss safely
  uses H.264. The finding survived; only one sampled winner receives the complete exact scan. It
  also challenged the second provisional presentation copy, but that did not survive: the user's
  goal is early visible movement, the authoritative in-place copy removes the move-sized staging
  allocation, and macOS unified-memory copies remain cheaper than waiting for encode/decode.
- **Protocol/security review:** found that `none | raw | video` cannot describe the normal planner's
  mixed raw/video result, and that a missing video remainder had no thread guaranteed to wait on
  the stated timeout. Correctness confirmed both: ambiguous completion can advance exactness early,
  and an idle blocking read never checks a deadline. Both survived. Move frames now choose one
  remainder lane, and both pumps poll an armed deadline through bounded reads. A proposal to stage
  the entire move until remainder completion was refuted by the latency role and the explicit
  metadata-first requirement; fail-closed provisional state is retained.

The one Claude/Fable pass was invoked read-only and produced no output for four minutes, so it was
stopped rather than stalling the unattended build. External review did not run; this remains the
checkpoint residual risk. There were no external items to accept or reject.
