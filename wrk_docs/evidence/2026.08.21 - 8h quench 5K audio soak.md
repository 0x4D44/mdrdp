# 8-hour quench 5K audio soak

**Result: PARTIAL.** The integrated native session survived 8 h 05 m at 5120x2880 with
correct real stereo audio, no transport loss, no decoder errors, bounded queue depth, and
no resource-growth warning. The strict depth-trend clause missed: -2.760 ms/hour against
the ±1 ms/hour acceptance band. This single observation does not distinguish real clock
skew from the regression metric's interaction with deliberate 50-second quiet resets.

## Pinned conditions

- Client: installed release `mdrdp v0.1.112`, SHA-256
  `9054cf581f1767f5cb3dd36a506635740813a39f03ce84f839dc1113ff06d30e`.
- Host: quench; rhydra-agent v0.5.0; IDD v0.3.0.1; native wire v5.
- Display: 5120x2880 at 240 Hz, Windows scale 100%.
- Audio: VB-CABLE loopback at 48 kHz stereo. The console rendered 30 seconds of initial
  tone, then repeated 10 seconds of 440 Hz left / 660 Hz right and 50 seconds quiet.
- Client: one uninterrupted process and native session, bounded to 29,100 seconds and held
  awake with `caffeinate`.

The repository has no `TESTING-GUIDE.md`; the tranche 6 HLD supplied the acceptance
criteria. Raw logs, JSON, WAV, and screenshots were inspected in OS temporary storage and
then removed because they may carry screen or audio content. Only this redacted result is
retained.

Depth conversion divides interleaved samples by 96 samples/ms: 48 samples/ms for each of
two channels. Hourly checks kept resident memory around 313–319 MiB; the final peak includes
startup and screenshot work and showed no monotonic growth.

The client detected 443 Hz left at RMS 0.246889 and 657 Hz right at RMS 0.185159. This
matches the rendered 440/660 Hz stereo fixture. It received 2,870,056 native audio records.
The server independently reported 2,870,056 produced, queued, and written records, with
zero silent or dropped records.

There were 488 underrun transitions. The fixture deliberately drained the ring during each
50-second quiet interval, yielding about 485 expected tone-to-quiet transitions plus startup
and final boundaries. The count therefore has an explained cadence and does not show an
in-window loss. Quiet intervals are explicitly continuity resets in the HLD.

## Video and host integrity

The final 5120x2880 screenshot showed a complete Windows desktop with no tartan, blank
region, tile corruption, or stale strip. For the soak's logical frames 10 through 501, host
telemetry contained 492 logical frames and 984 tile records. The maxima for dropped frames,
dropped rects, stamp mismatches, clean-point mismatches, and parameter-set failures were all
zero. The session was intentionally static apart from normal desktop updates, so its
roughly one-minute painted-frame cadence is endurance evidence, not the separate full-motion
A/B latency test.

An immediate post-run doctor check was green for SSH, tunnel, agent, creator, device, pool,
display mode, server, input desktop, liveness, and audio. It reported no viewer. The tone
task was stopped and unregistered, and every task-owned remote temporary file was removed.
Quench was not rebooted.

## Judgment and remaining work

This run discharges the eight-hour survival, sample-count, queue-bound, loss, decoder, and
resource-health parts of acceptance criterion 7. It does **not** discharge the ±1 ms/hour
trend clause, so criterion 7 remains partial rather than passed.

The earlier 2 h 36 m partial run wrote no final metrics because it was intentionally stopped
for evening integration. There is therefore no independent second trend measurement. Under
the testing-session promotion rule, no defect was added to the bug ledger from this single
result. A targeted follow-up should compare a continuous-tone run with the periodic-reset
fixture. That will show whether the miss is real source/playback clock skew or a sampling
oracle biased by the repeated drains.

The 200% Windows scaling prerequisite, device-loss test, synchronized flash/tone latency
measurement, continuous-animation video A/B, and temper provisioning were outside this run.
