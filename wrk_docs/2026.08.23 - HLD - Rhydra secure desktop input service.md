# HLD — Rhydra secure-desktop input service

**Status: SELF-APPROVED**  
Bug: `MDR-BUG-FLU-00066`

## Intent

Let a native Rhydra session control Windows' real PIN and UAC desktops while Windows
continues to own authentication.

## Scope

In scope:

- replace the per-user on-logon scheduled task with an auto-start LocalSystem service;
- have that service launch the existing Rhydra agent with its SYSTEM token moved into
  the active console session;
- move the server's input thread to Windows' current input desktop and retry one rejected
  `SendInput` call;
- migrate old task installs during install/uninstall and expose enough logging to verify
  the service, console session, desktop switch, and retry;
- harden `C:\\mdrdp` before service registration so only SYSTEM and Administrators can
  modify the privileged executable or its ancestors;
- deploy and validate on Quench at the Windows PIN desktop.

Out of scope:

- bypassing Windows authentication, storing or forwarding Windows credentials, or adding
  a Credential Provider;
- an RDP bootstrap or session transfer;
- changing Rhydra's wire protocol, capture, codec, display, audio, or clipboard design;
- supporting several simultaneous Windows sessions. Rhydra continues to own the active
  physical-console session only.

## Approach

### Service and session ownership

`rhydra-agent.exe service [--display ...]` will be a conventional Windows service entry
point. Before registering it, `install` will set Administrators as owner, protect
`C:\\mdrdp` with inheritable SYSTEM and Administrators grants, then reset every descendant
to inherit exactly that protected root. It will then
remove the legacy `rhydra-agent` scheduled task, register the service as LocalSystem with
automatic start, and start it. `uninstall` will ask the session agent to shut down, stop
and delete the service, and remove any legacy task left by an older build. It will not
weaken the installation ACL.

The service will remain in session 0. It will poll `WTSGetActiveConsoleSessionId`; when a
console session exists, it will duplicate its own SYSTEM primary token, set that token's
`TokenSessionId`, and launch the existing `rhydra-agent.exe run` command through
`CreateProcessAsUserW` on `winsta0\\default`. A console-session change stops the old child
through Rhydra's existing control shutdown, then starts one in the new session. Child exit
is supervised and retried. Service stop performs the same graceful shutdown, with a bounded
process termination fallback.

This follows Sunshine's proven Windows shape without copying its code. It adds no package
dependency: the existing `windows` crate supplies the service, token, session, and process
APIs.

The duplicated primary token requests `TOKEN_ALL_ACCESS`, matching Sunshine's production service
path. A narrower hand-selected mask reached `DuplicateTokenEx` but failed at
`SetTokenInformation(TokenSessionId)` under LocalSystem on Quench; the live Windows behavior is the
contract here.

### Secure input desktop

The server input thread will retain the latency-critical fast path between bounded desktop
checks. It opens the current input desktop with `OpenInputDesktop`, switches itself with
`SetThreadDesktop`, and then injects. It synchronises when the listener starts and at most
once per 250 ms while records are arriving; this covers lock/unlock transitions where
`SendInput` can misleadingly return success on the stale desktop. If Windows rejects an
event between checks, the thread synchronises immediately and retries exactly once.

The input thread retains exactly one switched desktop handle, replacing it only when the
desktop name changes; Windows does not allow a thread's current desktop handle to be closed.
The agent health observation opens the input desktop with the same access rights but leaves
switching to the dedicated input thread. Success means this process can follow the input
desktop; access denied remains Unknown.

### Security boundary

The network-facing processes gain SYSTEM integrity, but their three TCP listeners remain
loopback-only and external access still requires the existing SSH key-authenticated tunnel.
The input listener additionally resolves the reverse loopback connection's owning process and
accepts only the protected `%SystemRoot%\\System32\\OpenSSH\\sshd.exe`; this prevents an
ordinary local process from using the SYSTEM input path to drive UAC or Winlogon. Video,
control, and clipboard retain the repo's existing local-user trust boundary.
Service command lines always name the exact deployed executable; no PATH lookup or shell
interpretation is used for the privileged child. Service registration cannot happen until
the installation root no longer grants write or delete rights to non-administrators.

## Acceptance criteria

1. A regression test is observed red before the implementation and green after it. It pins
   the service command contract and the bounded synchronise/send/retry policy with distinct
   outcomes, including no repeated desktop call inside the 250 ms steady-state interval.
2. Install first makes `C:\\mdrdp` and its existing descendants non-writable by ordinary
   authenticated users, then removes the legacy scheduled task and creates one auto-start LocalSystem
   `RhydraAgent` service with the exact versioned executable and display arguments, and starts
   it. The root is owned by Administrators. Uninstall is idempotent and removes both current
   and legacy registrations.
3. The service reports Running only after its handler is registered. It waits harmlessly
   with no console, launches one child in the current console session, restarts it after exit
   or a session-id change, and stops it gracefully with a bounded hard-stop fallback.
4. On Quench's PIN desktop, the service and child run as SYSTEM in the active console
   session, input-desktop health is green, and fresh keyboard plus pointer records each make
   `SendInput` report one injected event. Windows still displays and validates the PIN.
5. After unlock, native display, keyboard, pointer, clipboard, audio, 5120×2880/240 Hz, 200%
   scaling, and 40 Mbit/s per H.264 tile remain working. A direct local input connection is
   rejected while an SSH-forwarded connection succeeds. The success path adds at most four
   desktop checks per second and no new input buffering.
6. Formatting, full Rhydra tests, the Windows all-target cross-check, and the repository's
   focused integration checks are green. The integrated trunk build is redeployed before
   live acceptance.

## Decision log

- Use a LocalSystem service and console-session child because it is the smallest established
  Windows pattern that can open the secure input desktop; an RDP bootstrap and Credential
  Provider solve a larger authentication problem Rhydra does not have.
- Keep service and agent as modes of one executable. A third artifact or crate would duplicate
  deployment and versioning for no isolation benefit.
- Poll the console-session id at a short service interval instead of adding WTS notification
  plumbing. Session changes are rare, while the bounded poll keeps the callback and teardown
  model small and testable.
- Synchronise input at listener start, after rejection, and at most every 250 ms while active.
  Failure-only retry misses a known Windows case where stale-desktop `SendInput` returns success;
  checking on every mouse move would directly tax the latency path.
- Preserve Windows authentication: Rhydra carries input, never credentials.
- Authenticate the privileged input channel by the connection owner's protected OpenSSH image,
  rather than adding a second secret or handshake on top of the existing SSH boundary.

## Review record

Three sequential adversarial lenses replaced unavailable helper seats, then each finding was
checked against the other two lenses:

- Security found a critical service-path replacement vulnerability: Quench's current inherited
  ACL grants `Authenticated Users` Modify on `C:\\mdrdp`. Correctness and operations both
  confirmed it; install-root ACL hardening before service registration is mandatory.
- Correctness found that failure-only desktop switching does not cover the repo's measured case
  where a stale-desktop `SendInput` succeeds but lands nowhere. Security did not refute it and
  the latency lens bounded the remedy to four checks per second.
- Operations found that service stop before the control port appears can orphan the creator and
  server. Correctness confirmed the lifecycle hole; uninstall and session replacement therefore
  require a bounded child stop followed by the existing installation-scoped process sweep.
- The security overclaim that loopback becomes newly exposed was refuted: all three channels are
  already machine-wide loopback. Elevation increases consequence, so the existing local-user trust
  remains an explicit residual risk, but it is not new network reach.

All three survivors are folded above. Independent helper review could not run because the fleet's
review-agent quota remains unavailable until 2026-08-27; those passes are degraded, not silently
counted as independent evidence.

The single external Claude/Fable review did not run. Claude Code 2.1.241 remained alive but
produced no output for four minutes and was stopped; a silent process is not a review. Residual
risk: the design has no independent cross-family evidence, particularly around less-common SCM
and desktop-transition races. The live Quench acceptance and bounded lifecycle tests carry that
risk rather than pretending it disappeared.

The implementation review repeated security, correctness, operations, and latency lenses, with
each proposed finding checked against the other lenses:

- Security found that loopback-only was insufficient after elevation: an ordinary local process
  could otherwise ask the SYSTEM worker to inject into UAC or Winlogon. Correctness confirmed the
  privilege-boundary change and operations confirmed that legitimate input connections are owned
  by the protected Windows OpenSSH image. The input listener now checks that owner once per accepted
  connection. This significant finding survived all refutations.
- Correctness found that closing a thread's current desktop handle fails, so the first periodic
  implementation could leak four handles per second. Security confirmed this would become an
  unbounded service-lifetime leak; latency confirmed name comparison adds bounded work only during
  the existing 250 ms check. The thread now retains one switched handle and replaces it only after
  a real desktop-name transition. This significant finding survived all refutations.
- Operations found that ignoring legacy-task deletion could leave two supervisors. Correctness
  confirmed the port and child-ownership race; install and uninstall now fail closed on deletion.
- A proposed hot-path penalty from the OpenSSH owner check was refuted: it runs once when a tunnel
  connects, before any input record is read, and never runs per event.

No critical finding remains unresolved. These were sequential reviews because independent review
seats remain quota-blocked; the external-review residual risk above remains.
