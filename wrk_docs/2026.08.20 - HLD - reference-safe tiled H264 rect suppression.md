# Reference-safe tiled H.264 rect suppression

**Status: SELF-APPROVED**

## Intent and scope

Make the 5K native viewer keep both H.264 tile decoders synchronised when the raw-rect
fast path makes an encoded frame visually redundant. This fixes MDR-BUG-FLU-00027.

In scope: the native tiled client gate and its focused regression test. Out of scope:
encoder changes, tile geometry, codec fallback, Windows DPI configuration, and the
separate deploy fast-path defect MDR-BUG-FLU-00026.

## Evidence and root cause

- Quench publishes complete two-tile sequences with zero frame drops, stamp mismatches,
  or encoder clean-point mismatches.
- VideoToolbox reports `kVTVideoDecoderBadDataErr` (`-12909`) after the first frames.
- FFmpeg and mdrdp's own decoder replay the exact rejected IDR/P/P/P access units cleanly.
- A live client that decodes every tile AU but skips canvas updates has zero decode errors.
- `NativeSink::paint` advances each tile's `exact_through` after a raw rect update.
  `NativeSink::on_tile_au` currently checks that marker *before* decoding, so it drops the
  matching H.264 P-picture. The following P-picture references the missing picture and is
  rejected. The marker proves only that a canvas write is redundant; it cannot prove that
  a predictive codec input is redundant.

## Approach and file impact

- `~/worktrees/mdrdp/bug-MDR-BUG-FLU-00027-run-fix-20260820T190256Z-28ceb536/src/native/session.rs`
  will always feed a received tile AU into its decoder. After successful decode, it will
  use the existing exactness marker to suppress only the redundant canvas blit and paint
  accounting. A decode error remains counted and non-terminal.
- Add a focused fake-decoder regression showing that a rect-completed sequence still
  consumes both corresponding tile AUs while leaving the canvas at the rect result.
- Update the bug record and work journal. No protocol, server, dependency, or feature flag
  changes.

## Acceptance criteria

1. A rect update that advances tiled exactness no longer prevents either tile decoder from
   consuming that sequence's AU.
2. The redundant decoded pixels do not overwrite the rect-completed canvas or count as a
   second painted frame.
3. Existing stale-AU, complete-tile, rect-gap, and native-session tests remain green.
4. A repeated 5120x2880 quench run paints beyond the first two frames with zero H.264
   decode errors under mixed rect and tile traffic.
5. Formatting, focused tests, clippy, and the repository's required local gate are clean.

## Decision log

- Keep raw rects. They reduce changed-frame latency and are not themselves corrupt.
- Do not reset the decoder after a suppressed AU. Decoding the AU is cheaper and preserves
  the exact reference chain without waiting for another IDR.
- Keep suppression per tile and after decode. This is the smallest fix at the layer where
  visual redundancy was incorrectly conflated with codec redundancy.
- Reject output-format, timing, and encoder-epoch changes: controlled replay and live
  isolation refuted them as causes of this failure.
