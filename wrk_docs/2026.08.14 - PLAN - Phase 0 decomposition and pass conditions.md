# PLAN — Phase 0 decomposition and pass conditions

2026-08-14 · Gauntlet charter Phase 0 · **Status: BLOCKED — AWAITING ARTHUR** (revision 3)

Two forks below need Arthur's decision before this can be self-approved. P0a and P1a are
unaffected and proceed regardless.

Three reviews — measurability lens, RDP technical lens, and a cross-family Codex pass —
each found the prior revision structurally defective, the third finding *more* blockers
than the second. That is itself the most important signal in this document, and revision 3
responds to it by changing shape rather than patching cells.

## The lesson the third review taught

Revision 2 tried to fix defects by writing *more* specification: exact thresholds and
evidence artifacts for all thirteen parts, including parts that depend on a system nobody
has built. Several of those artifacts turned out to be impossible to produce or forbidden
to commit. Specifying acceptance criteria for audio soak testing before a single frame has
been decoded is guessing dressed as rigour.

**So revision 3 specifies in depth only what is about to be built, records the known traps
for everything else, and derives each part's criteria when that part starts** — with real
knowledge instead of speculation. The charter already supports this: Phase 4 says to re-cut
the part list as you learn, and say why.

## Fork 1 — the scoreboard-first constraint cannot be met as written

The charter makes it a hard constraint that the measurement harness is proven against
Microsoft's client before anything it judges. But measuring the reference client means
running a real session with it, which needs a credential. Every route to satisfying the
constraint is credential-gated.

Revision 2 downgraded this to a "known deviation" and self-approved anyway. That was
wrong — a hard constraint is not something the plan being constrained may relax.

**The three honest options:**

| | Option | Cost |
|---|---|---|
| **A** | Block all of Phase 1 until a credential exists, then build the reference harness across every graded dimension first | Nothing moves until Arthur acts; strictly honours the charter |
| **B** | Proceed with P0a and P1a only (both credential-free and needed regardless), hold everything else | Small forward progress, constraint still honoured for anything judged |
| **C** | Amend the charter: scoreboard-first applies per-dimension, at the moment that dimension is first judged, rather than globally up front | Weakens a constraint Arthur set deliberately |

**Recommendation: B.** It moves the two parts that need nothing from anyone, and no part
gets *judged* before its dimension's baseline exists. C is tempting but it relaxes the rule
that stops the whole Gauntlet becoming self-referential.

## Fork 2 — soak-class parts and critic independence

P4 (≥4 h), P5 (≥8 h) and P6 (physical display power-off) need hours of exclusive access to
this Mac, its monitor and `temper`.

Revision 2 proposed the builder run the soak and the critic audit the artifact. The Codex
review refuted that, correctly: **independence is about who controls the experiment, not
whose hardware it runs on.** An artifact audit cannot detect an omitted failed run, a
biased workload, or a collector wired to the wrong event. My reasoning was backwards.

**Better, and now recommended:** the fresh critic starts the release binary and the
collection itself on the same machine, fixes the protocol and random seed in advance, and
owns the resulting artifact end to end. A human may perform physical actions (power off the
monitor) but never selects the evidence window. If a full independent soak cannot be run,
the verdict stays UNVERIFIED.

**What needs Arthur's decision:** this costs real wall-clock — an 8 h soak the critic must
own, per attempt, per part. Confirm that is acceptable, or accept slower/weaker evidence
knowingly.

## Known traps — recorded so the knowledge survives to when each part starts

These came out of the three reviews. Each is a specific way a pass condition can look
rigorous and prove nothing.

**Evidence and security (applies to every part).** Under HYBRID_EX everything after
negotiation is TLS-protected, so a pcap cannot demonstrate CredSSP, licensing or capability
semantics — and decrypting one manufactures credential and session material that
`CLAUDE.md` forbids committing. Captured display streams and screenshots *are* session
contents. **Therefore: evidence is an allowlisted, payload-free protocol event trace above
TLS** — PDU type, negotiated flags, timings, sizes, build identity — plus generated
non-secret test patterns. Commit hashes, expected outputs and aggregate diffs. Raw captures
stay ephemeral and outside git. Grepping logs for credential strings is not a security
oracle.

**P4 — "RTT" is four different signals.** Network RTT, RDP network-detection RTT, decode
time, and input-to-visible-pixel latency are not interchangeable. An EGFX frame
acknowledgement says a *server-originated* frame was decoded; it is not causally tied to an
input event, so it cannot measure input latency. Measure them separately, and measure
end-to-end with a deterministic host response and external high-frame-rate capture applied
identically to both clients. Also: "no significantly positive slope" rewards noisy data —
failing to reject a null is not proof of no effect, and adding variance makes passing
easier. Use an equivalence test with an upper confidence bound against a predeclared
margin, plus worst-window and p99 comparisons.

**P5 — a completed transfer is not a correct transfer.** Stale, reordered, truncated or
corrupted data passes a liveness test. Use unique generated payloads with end-to-end
hashes. Test rapid ownership replacement and delayed/lazy render, which are the real
CLIPRDR wedge modes; malformed-PDU injection tests transport violation instead and belongs
in a separate state-machine test with a named injection seam.

**P2b — a reconnect that logs in again is not a reconnect.** "No credential re-prompt"
passes if the client silently re-reads the keychain and lands in a *new* Windows session.
Require the same session ID plus a pre-planted host marker, and assert no keychain read or
CredSSP exchange on the fast path.

**P6 — two traps.** `NSWindow.frame` is in AppKit points; backing pixels need explicit
conversion, so a bare "±2 px" is undefined across scale changes. And requiring the
reference client to fail ≥1 sequence creates a perverse incentive: a tie cannot pass, so
the critic is rewarded for retrying until the reference misbehaves. Compare deviation
*distributions* against predeclared non-inferiority margins instead.

**P3a/P3b.** A replay decoder passes 1000 repeats of one trivial frame while live channel
dispatch, frame ordering, damage rectangles and cursor updates stay broken — require
diverse damage regions and live first-pixel evidence. And `backingScaleFactor` is not
physical density; with a fixed remote resolution some resampling is unavoidable, so "no
resample blur" cannot be promised universally.

**P1b/P3a — OpenH264.** If AVC turns out to be required, IronRDP's OpenH264 integration is
optional and carries packaging and licensing consequences. Stop and raise it rather than
absorbing it into a part.

## Corrections to previously published claims

- **The 4.20 ms floor is provisional** — ten samples, one burst, one time of day, no
  contention. P0a re-establishes it.
- **"IronRDP handles the Early User Authorization Result PDU" is UNVERIFIED** — asserted
  without reading `ironrdp-connector`. The PDU's existence under HYBRID_EX is Confirmed
  from our own capture; the crate's handling is not. P1a settles it.
- **The FreeRDP flag was wrong** — `/log-level:TRACE`, confirmed against 3.27.1 here.
- **"P2 definitively settles the codec question" was wrong** — EGFX negotiates separately
  over its own DVC afterwards. That is now P2c.
