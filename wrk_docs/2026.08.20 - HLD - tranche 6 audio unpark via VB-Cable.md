# HLD — tranche 6 audio unpark via VB-Cable

Status: SELF-APPROVED

Parent: `wrk_docs/2026.08.20 - PLAN - tranche 6 audio unpark via VB-Cable.md`.

## Goal and boundaries

Make real audio rendered by the Windows console session audible through an mdrdp
native session. Provision the base VB-Audio VB-CABLE driver, route the console's
default render endpoint through it while a client listens, capture its WASAPI system
mix, and leave audio failure non-fatal and visible.

In scope: base VB-CABLE provisioning on quench and temper; 48 kHz/16-bit/stereo
endpoint configuration; CABLE default selection and restoration; live WASAPI fixes;
doctor guidance; real two-tone and multi-hour soak evidence.

Out of scope: a custom driver, RDP protocol-provider work, per-session isolation,
microphone capture, Opus, and any audio wire-format change.

## Approach

### 1. Provision from a pinned official package

`mdrdp deploy` will treat VB-CABLE as part of a healthy rhydra host. Its preflight
will distinguish three facts: the base driver package is staged, an active CABLE
render endpoint exists, and WASAPI has an active default render endpoint. PnP state
must not stand in for the WASAPI answer.

When the base driver is absent, deploy uploads and runs one PowerShell script after
all existing stop-before-mutation checks but before quiescing or replacing the agent,
the IDD, or another working component. The script will:

1. download `VBCABLE_Driver_Pack45.zip` only from
   `https://download.vb-audio.com/Download_CABLE/VBCABLE_Driver_Pack45.zip`;
2. require SHA-256
   `b950e39f01af1d04ea623c8f6d8eb9b6ea5c477c637295fabf20631c85116bfb`
   (1,318,877 bytes, observed 2026-08-20);
3. extract to an OS-temporary staging directory;
4. require the base x64 INF/catalog/sys/setup set, a valid signature on the official
   installer, the Microsoft Windows Hardware Compatibility Publisher signature on the
   catalog, and the VB-Audio provider identity in the INF before install;
5. run the official root-device installer as
   `VBCABLE_Setup_x64.exe -i -h`; `pnputil /install` is not used because it can stage
   and bind a driver but cannot create VB-CABLE's root-enumerated device node;
6. require installer success and an active base endpoint within 30 seconds; rescan once,
   then report a required reboot or broken install instead of looping;
7. remove its uniquely named staging directory in `finally` and print the required
   identity notice:
   `VB-CABLE by VB-Audio (www.vb-cable.com) is donationware; all
   participations are welcome.`

The installer archive is never committed or made a normal deploy artifact. A hash
mismatch, invalid signature, wrong product identity, install failure, or a required
reboot stops before agent replacement, leaving the old agent untouched. Reboot remains
a separate Arthur-authorised host action. Deploy uses the existing sentinel-validating
script runner, retains stdout as evidence, and does not send this action through the
generic remote-command path that discards output.

The planner handles observed states explicitly:

- absent package: verify and install before agent quiesce;
- staged package without an active endpoint: if the official setup has not run, run it;
  otherwise rescan once, then stop as reboot-required or broken rather than looping;
- active endpoint with the wrong format: configure through the interactive agent;
- active endpoint and no prior render default: make CABLE the durable default;
- active endpoint with another default: preserve it until a runtime capture lease;
- exact rhydra artifacts plus healthy CABLE: no-op;
- exact rhydra artifacts plus unhealthy CABLE: repair audio only, without tearing down
  the IDD or server.

The official product page names Pack45 and requires extraction plus an administrator
install. The official licence page permits base VB-CABLE distribution when its origin
and donationware status remain visible. Premium A+B and C+D packages stay excluded.

### 2. Put endpoint policy beside WASAPI, once

Add a small Windows-only endpoint-policy module beside `win/audio.rs`. It will use the
same Core Audio enumerator as capture plus the `IPolicyConfig` interface already used
by Sunshine. It will:

- identify the base `VBAudioVACWDM` device through its PnP instance and VB-Audio
  driver provider, then map its render and capture endpoint IDs; friendly names are
  evidence only, and duplicate or mismatched devices fail closed;
- set both device formats to 48,000 Hz, PCM16, stereo;
- set `CABLE Input` as the default render endpoint for console, multimedia, and
  communications roles;
- persist the displaced defaults in an atomic lease before mutation, roll back every
  changed role if a later role fails, and restore a role on disconnect only if that
  role still points at CABLE, so a user's mid-session choice wins;
- recover a stale lease when the interactive agent starts after a crash, and remove
  the lease only after restoration completes;
- fail soft only after rollback: log the operation and continue with the current
  default endpoint when an undocumented policy call is unavailable or refused.

The same code serves two callers. `rhydra-agent configure-audio` is a control request
to the already-running interactive scheduled-task agent; the SSH-side CLI never tries
to mutate per-user Core Audio policy in the SSH service session. `LoopbackCapture`
uses the same operation defensively when an audio-enabled client connects, then
captures the selected device directly rather than depending on a default-change race.

The existing `audio-source` host setting remains the gate. Deploy writes `loopback`
only after a healthy base CABLE endpoint is observed, so CABLE hosts default on and
other hosts retain their current setting. The audio source is constructed lazily on
the `false -> true` audio-control transition
and dropped on disable or disconnect. The server admits one viewer and serializes
sessions, so no reference counter is needed; the configure operation refuses while a
capture lease is active. If a user independently selects CABLE during an mdrdp-owned
lease, that intent is indistinguishable from the lease, so disconnect restores the
saved default. Any later selection of another endpoint is preserved.

There is no new setting surface. Selecting the existing `loopback` audio source is the
setting; automatic default switching is enabled only when the discovered target is a
base CABLE endpoint. A host without CABLE does not gain automatic switching.

### 3. Keep device loss supported and bounded

`LoopbackCapture` already converts float32 or PCM16 mix formats, strides multichannel
input correctly, advances across silent buffers, drains every ready WASAPI packet, and
returns `Captured::Unavailable` without spinning when open or read fails.

The live pass will also validate the selected endpoint's 48 kHz rate, distinguish a
successful zero-frame poll from synthesized silence, and split a single oversized
WASAPI packet into wire-sized chunks with a correct capture position for every chunk.
Capture positions are compared only within continuous rendered-audio windows. A quiet
endpoint emits no loopback packets and therefore establishes a new continuity baseline
when rendering resumes; that expected idle is not a lost-audio gap and needs no silent
keepalive stream.

Disabling CABLE during a connection will stop that source and leave the session
healthy. Re-enabling it requires a reconnect; a new capture object then re-enumerates
the endpoint. Automatic in-session reopen is deliberately omitted because reconnect
is bounded and observable, while an endpoint retry state machine is extra failure
surface for no acceptance benefit.

Any defect found in the first live capture run will be fixed at its actual layer and
covered by a focused regression where the behavior can be isolated from hardware.

### 4. Make diagnosis actionable and evidence measurable

The existing non-gating `audio` health rung stays non-gating. Its missing-endpoint
detail will say: `fix: install VB-CABLE with mdrdp deploy`. `tools/audio-probe` will
print the default endpoint friendly name and both CABLE endpoint formats, so the P0
acceptance evidence proves identity as well as presence.

For the soak, `AudioStats` will expose current ring depth plus a fixed histogram sampled
once per second. It records n/min/median/max without retaining audio or an unbounded
sample list. The native receiver will account for capture-position gaps and full-queue
drops. Host telemetry will distinguish produced, queued, socket-written, silent, and
outbox-dropped audio instead of treating an Outbox enqueue as delivery.

The shared ring keeps its 400 ms hard capacity and unchanged RDPSND behavior. A
per-construction high-water policy is enabled only by the native auxiliary path; it
trims a complete incoming frame whenever depth crosses 200 ms and records that
separately. This avoids placing normal RDPSND's measured 150–250 ms lead inside a trim
zone. Evidence will state host, release build identity, duration, sample count, and
conditions.

## Acceptance criteria

1. Deploy planner and script tests cover every state above, prove verification and
   install precede agent quiesce, retain the script sentinel/evidence, reject bad hash,
   signature, identity, and post-install endpoint states, and keep every existing
   stop-before-mutation guard intact.
2. On quench, the official package's hash and signer evidence are recorded; the base
   driver is installed without an unapproved reboot; `audio-probe` reports active
   `CABLE Input`, 48 kHz/stereo, and viable loopback. Both CABLE endpoints are pinned
   to 48 kHz/16-bit/stereo.
3. A real 440 Hz-left/660 Hz-right WAV rendered in quench's console session is detected
   at the Mac in the correct channels over five release-build runs of at least 60 seconds
   each, with nonzero RMS and zero underruns inside each continuous-tone window, zero
   overruns or queue drops, and no unexplained capture-position gap. Natural drain after
   a tone ends is expected idle, not an underrun failure.
4. Disabling CABLE mid-session leaves video/input/clipboard healthy, reports audio
   unavailable at most once per source lifetime, and increases agent CPU by less than
   one CPU-second over 60 seconds. On loss, any role still pointing to CABLE is eligible
   for restoration; an OS-repointed or user-changed role is preserved, and either outcome
   completes that role's lease. Re-enable plus reconnect restores the real tone.
5. Injected policy tests cover failure at each role, rollback, a user's mid-session
   endpoint change, device loss, stale-lease recovery, repeated connect/disconnect,
   and configure refusal during capture. On a host where another render endpoint is
   default, a client switches only the three roles to CABLE and restores only roles
   still owned by the lease. Policy failure leaves the session alive and is visible.
6. `mdrdp --doctor` names `mdrdp deploy` as the remedy for a missing endpoint while
   the audio rung remains non-gating.
7. An eight-hour quench run samples ring depth once per second and retains at least
   28,000 post-warm-up samples. Median depth stays below 200 ms, maximum below 300 ms,
   and linear trend within ±1 ms/hour. Every periodic rendered-audio window has zero
   unexplained gaps, queue drops, overruns, or in-window underruns. Quiet intervals reset
   the continuity baseline. Every measurement names host, release build, duration, and
   audio conditions.
8. The soak records VB-CABLE's added end-to-end latency from a synchronized visible
   flash plus tone edge, compared with the same release build's synthetic source. The
   method, sample count, median, p95, and delta are evidence; no zero-cost assumption is
   made and this tranche sets no new latency budget.
9. An A/B video check drives the same continuous full-screen animation and clipboard
   copy loop for each arm and collects at least 1,000 painted-frame gaps per arm.
   Full-rate audio p50/p95 are no more than 10% worse than audio-enabled idle, there is
   no unexplained painted-frame gap over 100 ms, and clipboard progress is not starved.
10. The same idempotent deploy and a short two-tone smoke pass on temper after quench.
11. Focused tests, `cargo fmt --all`, `cargo clippy --all-targets -- -D warnings`,
   relevant Cargo suites, and `scripts/check-windows.sh` pass with stdin closed and
   bounded runtimes. A construction test proves the native high-water policy is enabled
   only for the native auxiliary path and remains disabled for RDPSND.

Every new regression test must be observed red once before its fix is restored.

## Decision log

- Use base VB-CABLE Pack45 because Arthur selected it; premium cables remain excluded.
- Use the official setup's documented silent flags because VB-CABLE needs a root device
  node that `pnputil /install` cannot create.
- Install and prove the endpoint before quiescing a working agent; there is no deploy
  rollback because failure leaves the old runtime untouched.
- Keep package integrity and installation in deploy; keep endpoint behavior beside
  WASAPI so install-time and runtime paths share one implementation.
- Use a durable, transactional per-user default lease because process `Drop` cannot
  repair defaults after a crash.
- Reuse the existing `loopback` choice instead of adding an environment variable or
  feature flag.
- Rely on the existing single-viewer/serialized-session invariant rather than add a
  speculative multi-client reference counter.
- Require reconnect after device re-enable; no retry state machine.
- Preserve the accepted system-mix privacy boundary and the existing audio wire.

## Review record

Three independent native reviewers critiqued this design, then each tried to refute
the other two reviewers' findings. No critical finding survived. The following
survived refutation and were folded into the design:

- install before quiesce, retain script evidence, define reboot detection, make temp
  cleanup unconditional, and test negative installer states;
- use stable PnP/provider identity, reject ambiguity, and make default switching a
  durable transaction with partial-failure rollback and crash recovery;
- route user-scoped policy through the interactive agent and construct capture lazily;
- distinguish a zero-frame poll, split oversized WASAPI packets, and account for
  receiver gaps, queue drops, and actual socket writes;
- give the soak, device-loss/no-spin, real-tone, and video-isolation claims numerical
  pass/fail oracles.

Rejected after refutation: a multi-client default-policy reference counter, because
the admitted viewer and auxiliary session are serialized. The design still refuses a
configure request while capture owns the lease. The claim that red-before-green was
missing was also rejected because the acceptance section already requires it; exact
red observations belong in the implementation journal.

One Claude/Fable cross-family review found two critical, four significant, and three
useful issues. All were accepted and folded in: use the official silent setup to create
the root device; scope the 200 ms trim to the native ring; judge underruns and capture
positions only inside continuous render windows; preserve the existing source setting;
measure added audio latency; require the Microsoft catalog signature; define the video
workload; and make loss-restoration eligibility explicit. No external finding was
rejected. The one permitted targeted native re-review passed both corrected critical
findings: the official setup can create the root device without weakening pre-quiesce
failure safety, and the native-only construction seam keeps RDPSND behavior unchanged.
