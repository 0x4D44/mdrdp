# HLD — egui hosting architecture for the UI handoff

Companion to `wrk_docs/2026.08.16 - HANDOFF - launcher and diagnostics UI/README.md`,
which owns every visual and behavioural value. This document settles only what the
handoff leaves to the implementer: how egui is hosted in each process, the dependency
set, and the one new IPC seam.

## Constraints that shape everything

- **One winit `EventLoop` per process** (winit global; `lessons_learnt.md`). The session
  process already builds it up front (`src/main.rs`) and `window.rs::SessionApp` runs it.
- **One OS process per session** (decided architecture). Diagnostics windows belong to
  the session process (handoff decision 3); the launcher never sees session stats.
- The session window's render path (softbuffer, damage-driven) is working, measured, and
  out of scope — it keeps rendering the desktop exactly as today.

## Decision 1 — launcher process hosts egui via eframe (glow backend)

The launcher becomes an `eframe::App`: one 900×700 window carrying every launcher
surface (wizard, connections list, settings modal, connect modal, dialogs — all
in-window per the handoff). eframe owns the event loop; the current
`launcher::pick`/`run_on_demand` structure is replaced, and `main.rs`'s no-args branch
calls the new shell instead. Spawning session children (`spawn_session`) is unchanged.

eframe is taken with `default-features = false` plus the glow backend — no wgpu tree.
Verified compiling 2026-08-16: eframe/egui/egui-winit/egui_glow 0.36.1, winit 0.30.13,
glutin 0.32.3, muda 0.19.3.

## Decision 2 — session process hosts egui manually (egui-winit + egui_glow + glutin)

The session's event loop is already owned by `SessionApp`; eframe cannot join it. A new
`src/ui/egui_host.rs` hosts N auxiliary egui windows on an existing winit loop: each
window = glutin GL context + `egui_glow::Painter` + `egui_winit::State`. `SessionApp`
gains an optional host holding the three diagnostics windows (cache, latency, channels)
and routes their `WindowEvent`s by `WindowId`; everything else falls through to the
session window exactly as today. Toasts are drawn into the *session* window's softbuffer
frame (like `draw_overlay`), not as egui — they must sit over the desktop image.

The 1 s diagnostics poll uses `ControlFlow::WaitUntil` only while a diagnostics window
is open; a session with none open keeps today's pure `Wait`.

## Decision 3 — menus via muda, attached per platform

One `muda::Menu` per process. macOS: `init_for_nsapp()` (system menu bar; the in-window
strip from the mocks is hidden). Windows: `init_for_hwnd()` on the main window (native
menu bar — this *is* the in-window presentation the mocks draw). Menu events arrive on
`muda::MenuEvent::receiver()`; the launcher polls it in `App::update`, the session in
`about_to_wait`. Launcher: File · Connection · View · Help. Session: Session · View ·
Diagnostics · Help.

## Decision 4 — connect-as-modal without a second logon

The connect must run in the child (one process per session; the child owns the socket),
but the modal lives in the launcher. The child gets `--stage-json`: it writes one JSON
line per connect stage (stage name, elapsed ms, qualifier) plus a terminal
success/failure line to stdout, which the launcher reads from the child's piped stdout
to drive the Connecting modal and the failure dialogs. Stage names are exactly
`stagelog.rs`'s. No credential, host secret, or pixel data crosses the pipe. On success
the child continues straight into its session window; the launcher just closes the
modal. Cancel kills the child before logon completes (pre-logon abort is safe; the child
sends its graceful shutdown from its own exit paths once a session exists).

The launcher tracks spawned children (`SessionHandle { pid, name, started }`) and polls
liveness for the "N sessions running" line and the Quit dialog.

## Decision 5 — fonts and theme

IBM Plex Sans + IBM Plex Mono (OFL) vendored as `.ttf` under `assets/fonts/` with the
licence file, registered at egui startup in both processes (`egui::FontDefinitions`) —
never resolved from the system. Handoff design tokens (colours, ramp anchors, type
roles, spacing, radii) become consts in `src/ui/theme.rs`, applied via `egui::Style`;
every screen reads tokens, never literals.

## Decision 6 — what happens to `src/ui`

`form.rs` and `list.rs` are deleted once the new shell renders (handoff decision 1),
with `FormError`'s validation wording moved into the wizard. `font.rs` stays — the
Ctrl+Alt+S overlay and toasts still render into the softbuffer frame. `ui/mod.rs`'s
"no UI framework" doc is rewritten; the module becomes the home of `theme.rs` and
`egui_host.rs`.

## New dependencies (Arthur approved the set 2026-08-16)

`eframe` (no default features; glow), `egui`, `egui-winit`, `egui_glow`, `glutin`,
`glutin-winit`, `muda`, plus `png` (icon decode for window/About icons) if nothing in
the tree already provides it. macOS menu/dock-icon code may use the `objc2-app-kit`
already in the tree via winit/muda, pinned to the same version.

## Risks

- **egui_glow/glutin on macOS**: OpenGL is deprecated but functional on macOS 26; eframe
  itself ships glow as a first-class backend. Fallback if a real blocker appears: move
  the *diagnostics* windows to `wgpu` via `egui-wgpu` (same host seam, heavier deps).
- **muda + winit coexistence**: both are Tauri-ecosystem crates designed to pair; the
  risk is macOS main-thread discipline, which the existing code already respects.
- **Windows cross-check**: currently broken on the trunk for environment reasons
  (`scratchpad.md` 2026-08-16); Windows-side verification of the new UI is deferred to a
  Windows box until that is repaired.
