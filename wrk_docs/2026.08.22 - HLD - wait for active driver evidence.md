# Wait for active driver evidence

Status: SELF-APPROVED

## Scope and approach

Prevent a false deploy failure when the newly bound IDD is active but
`Win32_PnPSignedDriver` briefly reports the prior version. Keep exact package verification;
do not weaken it or retry any mutation.

- Add one uploaded driver-status PowerShell script. On every iteration it freshly queries
  the matching present/healthy PnP entity and its signed-driver CIM rows. Both CIM calls use
  a two-second operation timeout. The loop deadline is 30 seconds, so the true bound is the
  deadline plus one final iteration (at most four seconds), excluding SSH process startup.
- Require exactly one present IDD instance and exactly one driver row for that instance.
  The script receives the expected raw version string only to exit early; it always emits
  the last raw per-instance/driver-row evidence as one compact JSON line plus `RHYDRA-OK`
  and exits zero. It catches query errors into structured evidence. Rust remains the gate
  and classifies matching, stale, absent, ambiguous, and query-error outcomes.
- Replace the final full `probe.ps1` call with that bounded read-only query and compare its
  device/version result to the artifact version in Rust.
- Keep the initial full probe and all deploy planning unchanged.

## Acceptance criteria

1. Stale samples followed by 0.3.0.2 succeed without reinstalling or rerunning deploy.
2. Thirty seconds of stale, absent, or ambiguous evidence fails with expected and actual
   versions in the error.
3. The wait script refreshes instances each sample, is instance-bound, has per-call and
   loop deadlines, and contains no mutation commands.
4. Pure Rust fixtures cover match, stale, absent, missing/duplicate rows, mixed instances,
   and query error. Script contract tests cover compact JSON, sentinel, timeouts, refresh,
   and forbidden mutation verbs.
5. Focused deploy tests, Clippy, formatting, Windows cross-check, and live Quench immediate
   success plus deliberately wrong-version timeout pass.

## Decision log

- Poll the small oracle, not the full host probe: repeating audio/display checks adds delay
  and repeats its `check-audio` process mutation during a driver-cache convergence wait.
- Thirty seconds matches the existing stable-green budget. A provider cache that remains
  stale longer safely fails and is a residual risk; no mutation is retried.
- Keep raw string equality with the initial probe. Updating both filters together remains a
  code-review obligation; abstracting a large PowerShell fragment across scripts would add
  more indirection than this small duplicate warrants.
- The initial planning probe remains a single sample and can choose an unnecessary reinstall
  immediately after an external driver change. That safe inefficiency is out of scope.

## Reviews

Both independent reviewers' per-call timeout, structured terminal output, fresh-enumeration,
exact row mapping, and executable-oracle coverage findings survived mutual refutation and
are incorporated. Their claim that the HLD failed to name the replaced call was refuted: it
already distinguishes the post-verify probe from the retained initial probe.

The single Claude/Fable review agreed with strict bounded polling. Useful findings added raw
per-instance evidence, Rust-owned judgment, early exit as optimization only, no-mutation
tests, the real 30+4 second bound, raw string equality, and the initial-probe residual.
