## 1. The one-sentence deliverable

`mdrdp <host>` detects a deployed rhydra host over SSH and opens the session
natively — ssh child with port forwards, the spike's proven decode/exactness
pipeline feeding mdrdp's existing session window — falling back to RDP when
rhydra is absent, with the transport always visible and chosen only at connect
time.

## 2. Settled inputs (not re-litigated here)

- Auto-detect default, deploy is the opt-in; per-favourite
  `native = auto|always|never`; `--native`/`--rdp` overrides.
- Transport visible in title/HUD/stage-json; no silent mid-session fallback.
- SSH v1 = shell out to system `ssh`; no new external Rust dependency. Server
  binds loopback only.
- The window shell embeds the presenter; one OS process per session.
- dxgi capture default; the wire is the transport HLD's v2 framing
  (`MSG_VIDEO_SEQ`/`MSG_RECTS`, `frame_seq`, exactness invariant), bumped to
  v3 by this tranche's input dialect (§5).

## 3. Code topology

`spike-viewer` cannot be a dependency of mdrdp (it depends on mdrdp by path —
cycle). Instead:

- **mdrdp takes `rhydra = { path = "tools/latency-spike/server", default-features = false }`.**
  rhydra gains a default-on **`host` feature** gating `win`, `agent`, and
  `idd_section` (its bins declare `required-features = ["host"]`), so the
  client build takes only the portable half — framing, rects, input records,
  control client, stats types — and a Windows *client* build does not link
  DXGI duplication, the MF encoder, or the `SendInput` injector (review
  S-M7/P-M7). No dependency on mdrdp exists in rhydra; no cycle. Internal
  path dependency, not a new external dep. rhydra's `[profile.release]`
  stanza moves out of its manifest (cargo ignores non-root profiles with a
  warning on every mdrdp build — the standalone build scripts carry the
  debug-symbol setting instead).
- **The viewer's transport-side logic ports into `src/native/`**: the pump +
  `MessageSink` shape, the sink's mandatory validation and
  `exact_through`/gap-hold ordering invariant, and the wire input encode.
  `app.rs`/`cli.rs`/`main.rs`/`interrupt.rs` do NOT move — mdrdp owns its own
  lifecycle. `clock.rs` dissolves (it already wraps mdrdp's HostClock). The
  spike-viewer crate stays untouched as the measurement rig; converging the
  rig onto `mdrdp::native` is later, optional work.
- mdrdp's Windows build stays green: `src/native/` is portable in shape; the
  decoder resolve (`mdrdp::h264::hardware_decoder`) already fails at runtime
  off-macOS, so native mode compiles everywhere and refuses cleanly where no
  hardware decode path exists.

## 4. Connect flow

### 4.1 Transport resolution (pure function, tested)

Conflicting `--native --rdp` is a usage error. Otherwise:
`--rdp` / `--native` > favourite `native` > `settings.defaults.native` >
`Auto`. Resolved before any network I/O; the decision and its source are
stage-logged.

- `Never` → straight RDP, no probe, zero cost.
- `Always` (or `--native`) → native or a hard, explained failure.
- `Auto` → **probe only hosts the local deploy record names** (§4.4); an
  unrecorded host goes straight to RDP at zero cost. This carries deploy's
  opt-in to the client: Auto never sprays SSH logon attempts (and Security-log
  noise, and domain lockout risk) at boxes that never opted in (review P-C1).

### 4.2 The ssh child

One `ssh` child serves probe and session — no separate probe connection:

```
ssh -N -o BatchMode=yes -o ConnectTimeout=4 -o ExitOnForwardFailure=yes \
    -o GatewayPorts=no -o StrictHostKeyChecking=accept-new \
    -o ServerAliveInterval=5 -o ServerAliveCountMax=3 \
    -L 127.0.0.1:<lv>:127.0.0.1:9500 -L 127.0.0.1:<li>:127.0.0.1:9501 \
    -L 127.0.0.1:<lc>:127.0.0.1:9502  [sshuser@]host
```

- Bind addresses are **explicit** `127.0.0.1` plus `GatewayPorts=no` — a
  user's `~/.ssh/config` must not be able to put the input-injection port on
  `0.0.0.0` (review P-M6). Stated posture: any local process on the Mac can
  reach the forwarded ports; accepted on a single-user machine, same class as
  the spike rig.
- stdio: stdin `null`, stdout `null`, stderr **piped** — stderr is the only
  classification signal ssh gives (exit code is 255 for everything), and
  nothing may pollute `--stage-json` stdout (review P-M5).
- `ServerAliveInterval/CountMax`: a dead transport (host suspend, monitor-
  sleep network drop, Wi-Fi stall) kills ssh within ~15 s, which closes the
  local forwards and ends the session with a visible error — not a silent
  freeze (review S-M6). A wedged server behind a healthy transport is the
  health ladder's job (tranche 4); stated, not hidden.
- Local ports `<lv>/<li>/<lc>`: bind `127.0.0.1:0`, record, drop. The race
  window is the full ssh connect+auth span, not theoretical (review S-M10);
  `ExitOnForwardFailure` turns a lost race into child exit, classified from
  stderr (`bind: Address already in use`) and retried once with fresh ports.
- Kill-on-drop, killed explicitly in shutdown, and killed on fallback before
  any RDP connect starts.

**SSH auth posture:** BatchMode means key auth is required — a GUI app owns
no tty for password prompts. This is host config, same class as auto-logon.
Honest state (review P-C3): tranche 2's deploy neither installs keys nor uses
BatchMode, so **deploy's verify step gains a BatchMode probe** (`ssh -o
BatchMode=yes … exit`) whose failure prints the actionable posture line
("native connect requires key auth: install a key —
administrators_authorized_keys for admin accounts") without failing the
deploy. Key *install* stays a documented manual step in v1 (Windows admin-key
ACL rules make silent automation a foot-gun). Validation installs the key on
quench as durable host config. A keychain-fed `SSH_ASKPASS` helper is
rejected for v1: it reimplements ssh auth UX for a host class the checklist
eliminates.

### 4.3 Probe → commit: the transport decision is made on the session sockets

The probe's verdict is **not** the control port's word — `green` is optimistic
by the agent's own design (spawn sets `running` before the server binds 9500;
`control.rs` documents one green tick per crash-loop cycle — review S-C1).
The sequence, all under one wall-clock deadline (8 s) that kills the child on
expiry (review P-M1/S-M3):

1. **Forward readiness**: poll-connect `<lc>` with short retries;
   ECONNREFUSED before the deadline means *ssh hasn't bound yet* — retry, not
   `no-agent` (review S-C2). `try_wait()` the child each tick so an exited
   ssh short-circuits with its stderr classification.
2. **Control pre-filter**: `query_status` (with an explicit timeout parameter
   — the current 5 s hardcoded read blows the budget, review S-M3) requiring
   `green`. No version check here — the agent's crate version says nothing
   about the server child's wire dialect (review S-C3).
3. **Video connect + header gate**: connect `<lv>`, read the first
   `MSG_STATS` header **synchronously on the connect path** (it also carries
   the desktop size `WindowConfig` needs — review S-M4). Accept a
   `wire_version` in the client's supported range (v3 only today, coded as a
   range); refusal messages distinguish "host older → run `mdrdp deploy`"
   from "host newer → update mdrdp" (review S-m4).
4. **Input connect**: connect `<li>` (brief retry — the server binds 9501
   just after 9500, review S-m7).

Only after all four does the client **commit to native**; the probe sockets
*are* the session sockets (header already consumed, socket handed to the
session thread). Under `Auto`, failure at ANY step falls back to RDP with a
classified, stage-logged verdict — including a wire-version mismatch (review
S-C3). Under `Always` each failure is a terminal, remedy-naming error.

Failure taxonomy (stage-json qualifiers, classified from ssh stderr patterns
where ssh is the failing party, with the stderr tail logged): `ssh-auth`,
`ssh-hostkey` (review P-m11), `ssh-unreachable`, `ssh-bind`, `no-agent`,
`not-green`, `no-server` (control green but 9500 refused — the S-C1 window),
`version-mismatch`, `deadline`. Unknown stderr → generic `ssh-failed` plus
the tail.

**Fallback guard (review P-C2):** before an Auto fallback issues an RDP
connect, check presence for a live *native* session to the same host; if one
exists, refuse with an explanation instead — an RDP logon takes the console
and would zero-frame the running native session. `--rdp` (explicit) is not
guarded; the user asked.

### 4.4 The deploy record

`mdrdp deploy` success writes the host into a small local record
(`native-hosts.toml` beside `favourites.toml`: host, version, timestamp).
`Auto` consults it; `Always`/`--native` ignores it (probe regardless). A host
deployed from a different Mac is connectable via `--native` once or
`native = always` — accepted v1 cost, stated.

## 5. Input: the protocol grows up

The spike input channel carries only VK down/up (8-byte records) — a
measurement rig, not a session. MVP needs the full keyboard and a mouse.

### 5.1 Wire (input channel v2, frameless, fixed width per kind)

Reader: one `kind` byte, then a fixed per-kind remainder; `rsvd` stays at
byte 1 across every kind (review S-m3). Existing kinds keep their exact
bytes; new kinds:

| kind | name | layout after kind (LE) | total |
|---|---|---|---|
| 1/2 | VkDown/VkUp (rig compat) | `u8 rsvd, u16 vk, u32 seq` | 8 |
| 3/4 | ScanDown/ScanUp | `u8 rsvd, u16 scancode, u32 seq` | 8 |
| 5 | MouseMove | `u8 rsvd, u16 x, u16 y, u32 seq` | 10 |
| 6 | MouseButton | `u8 rsvd, u8 button(1=L,2=R,3=M,4=X1,5=X2), u8 down, u32 seq` | 8 |
| 7 | Wheel | `u8 rsvd, u8 axis(0=v,1=h), u8 pad, i16 delta_x120, u32 seq` | 10 |

- `scancode` **wire convention**: low byte = set-1 code, high byte `0xE0`
  when extended — mapped from mdrdp's `Scancode { code: u8, extended: bool }`
  (that struct has no high byte itself — review S-m1). The client reuses
  `input::from_key_event`'s full, proven map; the viewer's 30-key
  `keymap.rs` stays rig-only. Known map holes (PrintScreen, Pause, F13+,
  media keys) are inherited and stated.
- `x,y`: capture-display-local pixels at the wire resolution (the header's
  `width/height`); the client maps through its letterbox `Viewport` exactly
  as the RDP path does. u16 suffices (H.264 ceiling 4096).
- Button/Wheel carry no x,y by design: one ordered TCP stream and one
  injection thread mean the preceding MouseMove fixes the position, and
  mdrdp only emits button/wheel with a known cursor (review: refuted
  concern, recorded).
- `delta_x120`: wheel notches ×120 (mdrdp's `WheelAccumulator` already emits
  whole ±120s).
- Unknown kind = terminal for the input connection (frameless streams cannot
  skip unknown lengths), logged server-side. A v2 record reaching a v1
  server dies on `BadKind` — fail-closed. The video header's
  `wire_version: 3` couples the dialects; the client never sends v2 records
  without having passed the §4.3 gate.

### 5.2 Server injection (rhydra `win`)

- **DPI**: the server calls
  `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` at start — a
  DPI-unaware process reads *logical* virtual-screen metrics and every click
  lands off by the scale factor (review S-M5).
- **Origin**: `dxgi::describe` plumbs `DesktopCoordinates` (origin, physical
  px) out — today it throws the origin away (review S-M5). MouseMove maps
  display-local → virtual-desktop absolute:
  `(origin + p − virtual_origin) * 65536 / virtual_extent`, injected with
  `MOUSEEVENTF_MOVE|ABSOLUTE|VIRTUALDESK`.
- Scancode kinds → `SendInput` `KEYEVENTF_SCANCODE` (+`EXTENDEDKEY` on the
  0xE0 convention) — layout-independent by construction.
- MouseButton/Wheel → the corresponding `MOUSEEVENTF_*` flags; X buttons via
  `mouseData`.
- **Stats discipline**: key and button records keep per-record JSONL;
  MouseMove gets counters only — per-record JSON serialisation on the
  injection thread at motion rate is a latency bug in waiting (review S-m5).

rhydra bumps 0.2.0 → 0.3.0 (deploy verify keys on version; wire_version → 3).

## 6. Client session architecture

Native mode is a **second producer against the existing four-handle window
contract** — `SessionApp`/`SessionWindow` unchanged in mechanism.

- **Frames — zero-copy into the store (review S-M2).** `Surface` gains
  `adopt_pixels(Vec<u8>)` (AU path: the decoder's output buffer is swapped
  in under the lock — no 8 MB copy per AU, preserving the property the spike
  measured its baselines against) and `pixels_mut()` (rect path: swizzle
  BGRA→RGBA straight from the wire payload into the surface rows — no
  intermediate allocation), both bumping the generation. The sink ports the
  viewer's mandatory validation and the `exact_through`/gap-hold invariant;
  **exactness advances only after a successful blit** and never on an error
  or size mismatch (review S-m9). Decode runs outside the lock; the window
  thread's full-window convert holds the same mutex as the RDP path does
  today — same contention shape, stated. A size change (decoded AU or rect
  header vs surface) is **terminal**: "host display mode changed; reconnect"
  — never a silent crop (review S-m8). Increment 4's damage-only convert is
  deliberately not ported (~1.2 ms at parity, measured); revisit only if
  tranche 7's gate demands it.
- **Threads.** `native-net` (owns the handed-over video socket: read, decode,
  blit, wake) and `native-input` (drain the window's input receiver with
  `recv_timeout` + stop-flag — a bare `recv()` deadlocks the join because
  the window holds the sender for its own lifetime (review S-M1) — encode §5
  records, write the input socket, and **poll the socket for readability
  between writes**: this thread never reads, so POLLIN means EOF/error, and
  without the poll a dead input channel silently eats keystrokes until the
  second write after death (review S-M8)). Either side's failure tears the
  session down with a visible error.
- **Commands.** `SessionCommand::Resize` → letterbox only in MVP (log once,
  toast "native: fixed host resolution"); renegotiation via the agent's
  display-mode ownership is deferred (§8). `SetVisibility` → no-op; the
  capture keeps running behind a minimised window — noted as a tranche 4
  item, beside the health ladder (review P-m7).
- **Lifecycle.** `NativeHandle` exposes `shutdown(self) -> SessionEnd`
  (matching `SessionHandle`'s actual surface — it has no separate
  stop/join, review S-m6). `SessionEnd` gains a native/transport-failure
  variant so the end dialog names the tunnel, not a fake RDP error.
  The ssh child dies here; server-side disconnect is already graceful (EOF
  poll frees the slot). **The session slot becomes
  `enum ActiveSession { Rdp(SessionHandle), Native(NativeHandle) }`** —
  the HLD's earlier "works unchanged" was false: the slot is a concrete
  type and `established.report` feeds four more sites (diag Channels
  window, channel prints, exit metrics, marker) that all need a native arm
  (review P-M3). Diagnostics windows show "n/a — native transport" rather
  than hiding.
- **Stats.** The generic `SessionStats` fields (decode ms, present, frames,
  bytes_in) are fed by the sink; `codec_painted` reports `AVC (rhydra)` so
  the existing title segment and HUD show the mix. RDP-only fields stay zero
  and self-omit. Input-echo latency has no native measurement yet — stays
  zero, stated.
- **Credential ordering (named refactor — review P-M5/P-M2).** Today the
  secret block (4 branches: `--password-stdin`, launcher pipe, keychain,
  tty prompt) runs ~200 lines before `establish`. It moves **after**
  transport resolution: the native arm reads no RDP credential at all;
  under `Auto` the secret is fetched only once the probe decides RDP. The
  launcher sees `password_prompt` after the probe stages — decoder-compatible
  (it keys on event names). Likewise **`reconcile`'s "no account" error must
  not fire before the probe** for a native-mode target: the RDP username
  requirement moves into the RDP arm, and the ssh login gets its own
  identity — `Favourite.ssh_user` + `--ssh-user` (absent → `~/.ssh/config`
  decides). The `--user` flag keeps meaning the RDP account in connect and
  the ssh account in deploy — a documented, pre-existing collision this
  tranche does not widen.

### Transport visibility

- Title: the base becomes `mdrdp — {name} (native)` (built in `main.rs` where
  the base is already formatted; `title_line` needs no change — review
  P-m12).
- stage-json: native emits `stage` events through the same `LiveStage`
  sender (`ssh-spawn`, `tunnel-up`, `probe`, `handshake`), and `connected`
  gains `"transport": "native"|"rdp"`. **The launcher's Connecting modal
  picks its canonical ladder by transport** — today's RDP-only ladder would
  render a native connect as four done rows plus seven forever-pending RDP
  stages (review P-M4); the first stage event names the transport and
  `dialogs.rs` selects the ladder from it, unit-tested.
- `CONNECTED_MARKER` prints with `native, wire v3` trailing fields
  (prefix-matched by the detach parent — compatible). `CONNECT_GRACE` rises
  10 s → 15 s: a worst-case probe (≤8 s) plus RDP fallback could exceed the
  old grace (review P-m10).
- Presence records gain a `transport` field so `mdrdp --sessions` stops
  reporting a native session as `user@host:3389` (review P-m6) — this field
  is also what the §4.3 fallback guard reads.

## 9. Acceptance criteria

1. **Native session live on quench**: `mdrdp quench` (Auto, deploy-recorded)
   opens natively — desktop visible, title says native, stage-json carries
   `transport: "native"`, presence shows the native transport.
2. **Real input**: typing (including UK-layout `"` and `\`), mouse
   move/click/double-click/right-click/drag, and scroll observed correct in
   a live session (Notepad + Explorer), including a click at each screen
   corner (origin/DPI mapping — review S-M5).
3. **Auto-detect three ways, measured**: quench (recorded) → native;
   temper (unrecorded) → straight RDP with zero probe traffic; a blackholed
   destination under `--native` → classified failure at the deadline
   (bounds proven). Probe cost on the native path quoted n≥5
   (min/median/max).
4. **No silent fallback + fallback guard**: agent stopped on quench +
   `--native` → hard error naming the remedy; same under Auto → RDP with a
   logged verdict; Auto fallback while a native session to the same host is
   live → refusal, not an RDP connect (review P-C2).
5. **Version gate, observable**: client against the live 0.2.0 host (wire
   v2) → the §4.3 step-3 refusal with the "run `mdrdp deploy`" message —
   reachable precisely because the probe no longer version-checks (review
   S-M11) — then redeploy 0.3.0 and connect.
6. **Teardown**: closing the window ends both threads, kills the ssh child
   (no orphan `ssh -N` after exit), frees the server slot; an immediate
   second connect decodes within Increment 0's bound (< 2.5 s hard,
   < 500 ms target).
7. **Hygiene**: fmt + clippy `-D warnings` (mdrdp and rhydra), focused tests
   green with stdin closed, `./scripts/check-windows.sh` green, server
   cross-build green, no new cargo warnings (the profile stanza), every new
   test demonstrated red once (saved-copy mutation, never `git checkout`).
   Precedence and ladder-selection tests enumerated.
8. **Latency sanity (reported, not gated)**: one glass run (n=100, single
   run — spread unmeasured, stated) against quench through `mdrdp --native`,
   quoted with full conditions beside the spike viewer's 48.6 ms p50
   baseline **with the pipeline differences named** (input hop via the
   channel + store publish path — review S-m2/M2); tranche 7 owns the formal
   gate.

## 10. Risks

- **Coordinate mapping** now has its mechanism specified (DPI awareness +
  origin plumbing); AC2's corner clicks are the falsifier.
- **SSH key posture**: real gap made explicit — deploy warns, install is
  manual, quench install is durable host config done in validation.
- **Wire bump**: the live 0.2.0 agent refuses the new client until redeploy —
  AC5 turns the risk into the test.
- **Probe latency**: bounded by the 8 s deadline; Auto pays it only on
  deploy-recorded hosts; per-favourite `never` opts out entirely.
- **Store contention** (window convert vs sink blit under one mutex): same
  shape as the RDP path; AC8's numbers will show whether it matters.
- **Decoder absence** off-macOS: compile-everywhere, clean runtime refusal.

### Two defects AC2 found, both fixed here

1. **The IDD source had no desktop origin** (`55bd63e`). It inherited
   `FrameSource::origin`'s `(0, 0)` default while the display sat at
   (1920, 0), so every click landed 1920 px to its left, on the other
   display — silently, because `SendInput` succeeds either way and the
   keyboard needs no coordinates. Typing worked; the first click stole
   focus and everything after it went nowhere. This was latent for as long
   as the virtual display happened to be the only one. GDI is the only
   route to the placement (`agent_ops::idd_display_origin`), and the origin
   is now logged at startup so a wrong one is visible rather than inferred
   from where clicks land.
2. **`autoinput`'s `scroll` sent notch counts as wheel units** (`de1f9f9`).
   rhydra refuses a delta that is not a nonzero multiple of 120 and closed
   the input channel mid-run. The verb now counts notches and emits one
   ±120 event per notch, matching real input. Its existing test asserted
   `units: -3` — it encoded the bug and passed throughout.

### Host-state lesson (cost an hour, worth writing down)

Two separate quench conditions each present as "native connects but decodes
nothing", and neither is a client fault:

- **A locked console eats all injected input.** `SendInput` returns success,
  the thread still reports `WinSta0\Default`, and nothing reaches the
  desktop, because a locked session's *input* desktop is the secure
  `Winlogon` one. `tasklist /FI "IMAGENAME eq LogonUI.exe"` naming session 2
  is the tell; the rig's own `mdrdp-tocon` task (`tscon 2 /dest:console`)
  clears it.
- **An RDP logon to the console recreates the IDD display**, renumbering it
  (`\\.\DISPLAY12` → `15` → `16`) and leaving the capture server bound to a
  pool that no longer receives frames. Recovery is three steps in order:
  `mdrdp-cycle-idd`, then kill `mdrdp-idd-create.exe` so the agent respawns
  it and republishes `Global\mdrdp-idd` (the cycle destroys the section, and
  the server then logs `waiting up to 30s for Global\mdrdp-idd`), then
  restart `rhydra-server.exe`.
