# HLD — rhydra tranche 6: audio

Parent: `wrk_docs/2026.08.18 - HLD - native product shape and session ownership.md`
§6 and §9 step 6. Prerequisite finding:
`wrk_docs/2026.08.19 - PARK - tranche 6 audio needs a render endpoint on the host.md`.

## 1. What this delivers

Host → client audio on the native transport: what the rhydra session plays comes out
of the Mac's speakers. One direction only. Microphone capture is out of scope and
stays out.

## 2. The constraint that shapes everything

**Neither fleet host has an audio render endpoint.** Measured with `tools/audio-probe`
on 2026-08-19: quench 6 endpoints / 0 active, temper 5 endpoints / 0 active, both
returning `0x80070490` from `GetDefaultAudioEndpoint`. Both are headless with nothing
in the jack.

WASAPI loopback capture attaches to a *render* endpoint, so on these hosts there is
nothing to attach to — and, more to the point, applications there cannot render audio
at all. Microsoft's RDP does not solve this by capturing harder: it **supplies a
per-session virtual endpoint** ("Remote Audio") that exists only inside the session,
and reads that. The eventual answer for rhydra is the same shape, and it is the audio
sibling of the IddCx virtual display driver we already ship. That driver is **not**
this tranche.

So this tranche is built to the following rule, which is a design constraint and not
an apology:

> **A host with no render endpoint is a supported configuration.** It reports the
> absence, plays nothing, and stays healthy. It never fails a session, never retries
> in a loop, and never looks like a bug.

That rule is what makes the tranche deliverable now and correct later: when an
endpoint appears — a jack plug, or our own virtual device — capture starts working
with no other change.

## 3. Wire format

A new message on the **auxiliary channel** (port 9503), which the parent HLD already
designates for audio, ranking above clipboard.

```
MSG_AUDIO = 0x21          (clipboard is 0x20; input kinds 1..=7 stay disjoint)

payload:
  u32 LE  sample_rate     e.g. 48000
  u8      channels        1 or 2
  u8      reserved        0
  [i16 LE samples]        interleaved PCM, native-endian-free
```

**PCM16, not Opus.** 48 kHz stereo is ~1.5 Mbps against video's tens of Mbps on this
LAN — roughly a 5% tax — and it adds no dependency, which an Opus crate would. It also
removes a whole class of codec bugs from a tranche that already has a novel capture
path. Revisit only if rhydra ever runs somewhere a WAN budget matters.

**Self-describing on every frame.** The rate and channel count travel with the samples
rather than being negotiated once. It costs six bytes per frame and means a device
change mid-session cannot desynchronise the two ends — the failure it prevents is
silent wrong-speed playback, which sounds like a bug in something else entirely.

## 4. The outbox: strict priority, and why `Slot` cannot be reused

Today the aux channel's outbound side is `auxchan::Slot` — depth-1, keep-latest. That
is exactly right for a clipboard: a payload superseded before it was sent was never
the clipboard's current content, so dropping it is correct rather than tolerated.

It is exactly wrong for audio. Keep-latest on a continuous stream discards most of the
signal and delivers chop.

The replacement is one **`Outbox`** holding both:

- `audio`: a bounded FIFO, drop-**oldest** on overflow. Oldest because when we are
  behind, stale audio is worthless and the listener wants to catch up, not hear the
  past. Depth is bounded so a stalled link cannot grow memory without limit.
- `clipboard`: the existing keep-latest slot, unchanged in behaviour.

`take()` drains **all** pending audio before any clipboard payload. That is Arthur's
priority decision (video critical, audio continuous, clipboard bursty bulk) applied
within the channel.

**A caveat that must be stated rather than implied:** video (9500) and aux (9503) are
separate TCP connections but share one ssh tunnel, so ssh interleaves them and aux
traffic *can* delay video at the transport layer. Strict priority inside the aux
channel does not change that. The real mitigation is that audio is bounded at
~1.5 Mbps, and that should be **measured** against the video tail, not assumed.

## 5. Host capture

`win::audio::LoopbackCapture`, behind a `AudioSource` trait so the pipeline is
testable without WASAPI:

- Activate the default render endpoint, `AUDCLNT_STREAMFLAGS_LOOPBACK`, shared mode.
- Convert the device's mix format (typically 32-bit float) to interleaved PCM16.
- On **no endpoint**: report once, publish the fact in the stats header, and idle.
  Never poll in a tight loop; never treat it as an error.

**Silence is not sent.** WASAPI reports silent loopback buffers with
`AUDCLNT_BUFFERFLAGS_SILENT`; those frames are dropped rather than encoded, so an idle
desktop costs nothing on the wire. This matters more than it looks: without it, a
silent session pays the full 1.5 Mbps forever, next to a video stream we have promised
not to back up.

A `--audio-source tone` mode generates a 440 Hz test tone instead of capturing. It
exists because the wire path must be provable on hosts that cannot capture — which is
currently *all of them* — and it doubles as a diagnostic for "is audio reaching the
client at all", which is a question the health ladder should be able to answer.

## 6. Client playback

Almost free. `src/audio.rs` already carries `AudioRing`, `AudioPlayback` (cpal),
PCM16 → f32 decode, channel reconciliation and linear resampling, all built for the
RDP path and all independently tested.

The native path adds only: decode the frame header, convert to the device's rate and
channel count with the existing helpers, and `ring.push()`. No new audio machinery,
and the underrun accounting comes along for free.

## 7. Clock drift — the soak risk

The host's capture clock and the Mac's playback clock differ by ppm and diverge over
hours. This is the audio face of product requirement 3 (latency degrades the longer a
session runs), and it is the thing a short test cannot see.

`AudioRing` already writes silence on underrun. The missing half is over-fill: if the
ring is persistently above a high-water mark, drop a frame to catch up rather than
letting latency grow without bound. Both events are counted and surfaced, because an
audio path that silently self-corrects is one nobody can diagnose.

## 8. Acceptance criteria

Each is written as an executable check. AC1-AC5 are runnable tonight; AC6 needs an
endpoint and is honestly out of reach until one exists.

- **AC1 — a tone reaches the client.** With `--audio-source tone`, the client's ring
  receives samples at the expected rate, and the session reports a non-zero frame
  count. Proves the whole path end to end.
- **AC2 — priority is real.** With the outbox holding both, a large clipboard payload
  queued behind pending audio does not delay the audio: every audio frame is taken
  first. Asserted on the outbox directly, not inferred from timing.
- **AC3 — the FIFO drops oldest, bounded.** Overflowing the audio queue keeps the
  newest frames, drops the oldest, counts the drops, and never grows past its bound.
- **AC4 — no endpoint is a supported state.** With no render endpoint the host reports
  it once, sends nothing, consumes no measurable CPU, and the session stays healthy
  for its full duration. This is the one that must be true on quench today.
- **AC5 — silence costs nothing.** A silent source produces zero audio bytes on the
  wire.
- **AC6 — real capture** *(blocked: needs a render endpoint)*. Audio played on the
  host arrives intelligibly at the Mac. Cannot be discharged on either fleet host as
  configured; will be recorded unproven rather than skipped.

## 9. What this deliberately does not do

- **No virtual audio device driver.** That is the real fix for headless hosts and it
  is a separate, larger piece of work with signing implications. This tranche is built
  so that driver, when it exists, needs no change here.
- **No microphone / capture redirection.** Out of scope, staying out.
- **No Opus, no compression.** See §3.
- **No negotiation handshake.** Frames are self-describing; there is nothing to
  negotiate and therefore nothing to get wedged.
