# PLAN — tranche 6 audio: unpark via VB-Cable

**Decision (Arthur, 2026-08-20): give each rhydra host a virtual audio render endpoint
by installing VB-Audio's VB-CABLE.** No extra hardware, no jack plug, no kernel code of
our own. This document is the implementation plan for a team that was not part of the
discussion; it is self-contained.

Parents:
- `wrk_docs/2026.08.19 - HLD - rhydra tranche 6 audio.md` — the transport design, built
  and landed; capture never executed.
- `wrk_docs/2026.08.19 - PARK - tranche 6 audio needs a render endpoint on the host.md`
  — why there is no endpoint, and the option analysis this decision closes.

## 1. Why this route (condensed from the 2026-08-20 review)

A headless Windows box keeps every physical render endpoint `unplugged`/`not-present`
(HD-audio jack sense), so nothing can render and WASAPI loopback has nothing to attach
to. Microsoft's RDP avoids this by *supplying* a per-session virtual "Remote Audio"
endpoint — a **user-mode** DLL (`rdpendp.dll`-style, export
`GetTSAudioEndpointEnumeratorForSession`) — but Windows only consults that hook for
sessions owned by a Remote Desktop **protocol provider**. The console session, which
rhydra owns by design, can never get one. The user-mode route therefore requires
becoming a protocol provider (an architectural fork, parked), and a kernel-mode virtual
audio driver of our own cannot load under Secure Boot without Microsoft attestation
signing (EV certificate, ~£250+/yr — ruled out on cost; see
`lessons_learnt.md` "virtual AUDIO device" entry for why the IDD's self-signing trick
cannot transfer). Borrowing a signed third-party endpoint is how the rest of the field
solves this (Sunshine borrows Valve's Steam Streaming Speakers; Parsec guides users to
VB-Cable). VB-Cable is the clean borrow: signed, ~1 MB, no resident software,
redistribution of the base cable explicitly permitted.

**Licence:** donationware; professional/company use requires a paid licence (one-off,
€2.50–€21/unit by volume). Arthur pays when company use begins. Bundling is permitted
only if the end user can see it is VB-Audio's product and can donate/license — keep
that visible in any deploy output. The premium variants (CABLE A+B, C+D) may NOT be
bundled; use only the base VB-CABLE.

## 2. Scope

**In:** provisioning quench (then temper) with VB-Cable; first real execution and fix-up
of the WASAPI loopback capture path; endpoint format pinning; doctor/health rung; deploy
support; soak-class validation of real audio.

**Out:** the Remote Desktop protocol-provider fork; per-session audio isolation (the
accepted system-mix compromise stands — tranche-6 HLD §review); any wire-format change
(the transport landed and is proven against the synthetic source); Opus.

## 3. Work items, in order

### P0 — provision quench (no mdrdp code)

1. Download the VB-CABLE driver pack from vb-audio.com. Record version and SHA-256 in
   the evidence file. Do not fetch from mirrors.
2. Verify the package signature before install (`Get-AuthenticodeSignature` on the
   .cat/.sys — expect VB-Audio + Microsoft countersignature). This is the check that the
   Secure Boot claim is true; it was asserted from reputation, not observed.
3. Install as admin (`VBCABLE_Setup_x64.exe -i -h` silent, or `pnputil /add-driver` on
   the INF). Note: an sshd session is elevated for admins on quench; if the installer
   needs an interactive session, use the Interactive scheduled-task pattern from
   `lessons_learnt.md`. A reboot may be requested; get Arthur's word before rebooting.
4. **Pin formats:** set BOTH endpoints (render "CABLE Input", capture "CABLE Output") to
   48 kHz / 16-bit / stereo. A mismatch makes VB-Cable resample internally — the classic
   source of clicks and drift, and it would pollute every later latency/drift number.
5. Re-run `C:/mdrdp/audio-probe.exe`. Expect: 1 ACTIVE render endpoint, default =
   "CABLE Input". Save output to a `wrk_docs/evidence/` file alongside the 2026-08-19
   probe for the before/after.

Acceptance: audio-probe shows an ACTIVE default render endpoint; a native app on quench
can play a WAV without error (e.g. PowerShell `Media.SoundPlayer` in the console
session).

### P1 — first execution of the capture path

`tools/latency-spike/server/src/win/audio.rs` states in its header that it has never
executed one instruction and that the first person to run it should expect to find
something. Budget for findings; that is the point of this phase.

1. Run rhydra on quench with `--audio-source loopback`, connect from the Mac viewer.
2. Play the two-tone reference (440 Hz left / 660 Hz right — see
   `tools/latency-spike/server/src/audio_source.rs` for why two tones) **as a real WAV
   through the endpoint** in the console session; verify both tones, correct ears, at
   the Mac end with the existing detector. This proves endpoint → mix → loopback →
   wire → ring → playback, which the synthetic source deliberately could not.
3. Fix what surfaces at the layer it lives at. Likely first candidates, from the code's
   own caveats: mix-format assumptions (float32 vs PCM16), buffer-period timing,
   silence reporting (`AUDCLNT_BUFFERFLAGS_SILENT` vs elided packets feeding
   `capture_pos`).
4. Regression: the `Captured::Unavailable` path must still hold — disable the CABLE
   device in Device Manager mid-session and confirm the session stays healthy, reports
   audio unavailable, and does not spin. Re-enable; capture should return (document
   whether re-open is automatic or needs reconnect — the HLD expects a supported state,
   not a wedge).

Acceptance: two-tone verified end-to-end on real hardware; unplug/replug behaviour
recorded; every claim carries host + build profile per repo validation rules.

### P2 — default-device policy (small, do after P1 green)

Copy Sunshine's refinement: when a client connects, if the configured/virtual sink is
not the default render endpoint, switch the default to it and restore the previous
default on disconnect. Windows has no documented API for this; Sunshine uses the
undocumented `IPolicyConfig`. Implement behind a setting (default ON only when the sink
is a CABLE device), fail soft (log + continue capturing whatever is default). On today's
fleet this is a no-op safety net; it becomes load-bearing the day a host has speakers.

### P3 — visibility and deploy

1. **Doctor rung** (tranche-4 ladder): "no active render endpoint — audio unavailable;
   fix: install VB-Cable (`mdrdp deploy` can do it)". The rung must name the fix, not
   just the absence. `tools/audio-probe` logic is the check; fold it in rather than
   shelling out.
2. **Deploy:** teach `src/deploy.rs` to provision VB-Cable like it provisions the IDD:
   detect (endpoint present? driver package present?), install from a pinned-hash
   download, verify signature first, print the VB-Audio identity/donation line (licence
   condition). Do NOT commit the installer binary to the repo; pin URL + SHA-256.
3. Provision temper the same way once quench is green.

### P4 — soak (discharges the requirement, not a unit test)

Soak-class evidence per repo rules: a multi-hour session with periodic real audio.
Measure with the existing `audio::AudioStats`/stagelog counters: ring depth over time
(clock-drift accumulation — the HLD names persistent over-fill policy as the open soak
risk), frames lost vs silence elided (via `capture_pos`), underruns. Quote
distributions, n, and conditions. One session on quench, hours, is the bar.

## 4. Risks / open points

- **First-run unknowns in `win/audio.rs`** — planned for in P1; do not treat findings
  as scope creep.
- **VB-Cable adds internal buffering** (~10–20 ms class). Measure added latency in P4
  and record it; do not assume zero.
- **Installer interactivity over ssh** — may need the scheduled-task pattern; known,
  documented, not a blocker.
- **Reboot** — possibly requested by the installer; needs Arthur's go on a fleet box.
- **Licence** — Arthur pays the VB-Cable licence at the point of company use; note is
  in §1 so the implementing team doesn't need the history.
- **Isolation** — unchanged: system-mix capture, no per-session separation. Accepted.

## 5. What "done" looks like

Tranche 6 moves from "transport proven against a synthetic tone" to "real Windows audio
audible on the Mac": P0–P1 green on quench with evidence files, P2–P3 landed, P4 soak
recorded, temper provisioned. The PARK document gains a closing addendum pointing here.
