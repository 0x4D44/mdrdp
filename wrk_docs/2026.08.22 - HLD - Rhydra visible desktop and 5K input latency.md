# Rhydra visible desktop and 5K input latency

Status: SELF-APPROVED

## Intent

Make a 5K Rhydra session show the Windows desktop where applications actually open, and keep mouse and keyboard handling responsive during sustained full-motion video.

## Scope

- Fix `MDR-BUG-FLU-00035`: provision the Rhydra IDD as the primary display at `(0,0)`.
- Fix `MDR-BUG-FLU-00036`: stop tiled video damage and long presentation work from starving the macOS event loop and native network thread.
- Preserve 5120×2880, 200% Windows scaling, tiled H.264 reference correctness, the raw-rect path, local cursor ownership, clipboard, and audio.
- Do not move individual application windows. Correct display topology is the product policy; blanket `EnumWindows` repair would hide topology faults and interfere with deliberate multi-monitor layouts.
- Record distinct server-review defects separately. Do not bundle unrelated socket, clipboard, codec-fallback, and lifecycle hardening into this interactive fix.

## Evidence

- Quench's server log reports the captured IDD at physical origin `(1920,0)`.
- An interactive-session window/monitor snapshot showed physical `DISPLAY1` primary at `0..1920`; Command Prompt, File Explorer, Media Player, and other application windows were on it. The 200%-scaled IDD was secondary at logical `1920..4480`, so Rhydra captured neither those windows nor the primary taskbar.
- The agent currently reconciles only width, height, refresh, and scale. Its mode setter never requests primary status or `(0,0)` placement.
- A 5K logical frame is two H.264 tiles. The client currently increments the shared surface and wakes the UI once per tile, allowing two full 5K redraw requests for one frame.
- The macOS redraw path holds `SurfaceStore` while it converts all 14.7 million pixels. The native network thread needs the same mutex to accept the next decoded tile. The event-loop thread that performs this conversion also receives keyboard and mouse events.
- Current live client telemetry reports 58.3 ms median input-to-paint latency at 5K. Arthur observed multi-second visible input delay during YouTube playback. The Windows input injector is a separate thread, so a responsive injector can coexist with delayed visible feedback.

## Approach

### 1. Reconcile display placement as part of display health

- Extend the platform boundary with a small placement observation: whether the IDD is primary and its physical origin.
- A display is ready only when mode, scale, primary status, and origin all match the requested session.
- On Windows, enumerate every attached desktop display and preserve its current `DEVMODEW` as rollback state. Stage the non-IDD displays to the right of the IDD without applying them, then stage the IDD at `(0,0)` with the requested mode and `CDS_SET_PRIMARY`. Use `CDS_UPDATEREGISTRY | CDS_NORESET` for every device and one null-device call to commit the multi-display change, as the Win32 API requires. Restore the staged registry values on a pre-commit failure.
- Re-read every display's position and primary flag after the commit; never claim success from return codes alone.
- Restart the server after a successful correction because capture and absolute-input mapping cache the IDD origin at server start.
- Include placement in the display rung's failure detail. This makes a future regression diagnosable without an interactive inspection.

### 2. Coalesce one logical tiled frame into one UI wake

- Continue decoding every tile and maintaining each tile's reference state.
- Wake the UI only when all advertised tiles for a capture sequence have arrived. A single-tile stream still wakes once.
- A decoded tile suppressed as already exact still counts as an arrival. Track whether any tile changed the canvas separately, so a sequence with one suppressed tile and one newly painted tile wakes exactly once, while an entirely redundant sequence does not wake.
- Keep raw-rect wakes unchanged. Preserve incomplete-sequence eviction and exactness rules.

### 3. Bound damage notifications and shorten the surface lock

- Let at most one `Damaged` user event remain outstanding. A pending notification represents “the store may have changed”, so additional identical notifications carry no information.
- Clear the pending bit as the event loop starts handling the notification, so damage concurrent with handling schedules the next pass.
- Copy the current presentation surface into a reused snapshot while holding `SurfaceStore`, then release the mutex before scaling, channel conversion, overlays, and presentation. The extra copy is bounded to one frame and turns a long scalar-conversion critical section into a memory copy.
- Redraw always uses a complete immutable snapshot for that generation. Producers can decode and composite newer frames while the UI presents it.

### 4. Bound 5K presentation cadence

- Decode every access unit to preserve H.264 reference correctness, and keep compositing the newest complete canvas.
- At resolutions above 2560×1440, present at most one canvas generation every 33 ms. Damage inside that interval replaces the pending generation rather than scheduling another redraw. This deliberately caps 5K glass cadence near 30 fps so the event loop has time to service input instead of accumulating redraw work.
- Drive the deferred redraw from the existing event-loop deadline mechanism; do not sleep on the UI thread. Lower resolutions retain the existing change-driven cadence.

## Acceptance criteria

1. When a physical display is present, the agent makes the Rhydra IDD primary at physical `(0,0)` before the server is considered ready.
2. Correcting placement restarts a running server so its capture and input origin are current.
3. Command Prompt, File Explorer, and Media Player launched normally intersect the captured IDD work area on Quench.
4. Two tile AUs completing one capture sequence cause exactly one UI damage wake; incomplete sequences cause none; one-tile streams still wake once.
5. Repeated producer damage while one notification is pending queues only one event, without losing a later generation.
6. Full-frame scaling/presentation no longer runs while holding the shared surface mutex.
7. Bursty 5K damage requests at most one redraw per 33 ms and always presents the newest available generation; the UI thread never sleeps to enforce this.
8. Existing tiled exactness, raw-rect, cursor, clipboard, audio, colour-order, and 5K/200% tests remain green.
9. A release build on integrated `origin/main` deploys to Quench. Interactive 5K YouTube playback no longer makes mouse or keyboard response accumulate seconds of delay.

## Decision log

- Make the IDD primary instead of moving windows. The desktop users see and the desktop Rhydra captures must be the same desktop by construction.
- Treat primary/origin as health, not a one-time deploy script. Device recreation and console attachment can change topology later.
- Preserve decode/reference correctness and drop redundant presentation work only after logical-frame completeness.
- Use a bounded snapshot before introducing a GPU-native shared-surface redesign. It isolates the proven lock inversion with much less surface area.
- Cap 5K presentation at 30 fps. Smoothness above that is not useful when it prevents the event loop from accepting input; transport decode remains complete and only stale glass updates are skipped.
- Keep the client and server release unit together because Arthur's acceptance test is end-to-end visible input response, but land the two bug fixes as separate green commits where practical.

## Review journal

### Adversarial review

Surviving findings folded into the design:

- Setting the IDD primary needs a staged multi-display commit, not a single overlapping position call.
- Suppressed/stale tile AUs must count toward logical-frame arrival or one-sided updates can lose their only wake.
- The pending-damage flag must clear at handler entry, before the generation read, and recover when proxy delivery fails.
- Snapshotting shortens producer contention but does not itself bound UI-thread work. A 5K presentation cadence bound is therefore part of the fix.
- Input/aux listener lifecycle, partial-record wedges, global orphan cleanup, HEVC fallback level, clipboard allocation bounds, converter-pool growth, control-line bounds, and delivery telemetry are real but distinct server defects. They will be tracked separately rather than bundled.

Refuted or rejected:

- Moving individual windows was rejected because it hides the wrong topology and breaks intentional placement.
- Treating per-tile wakes alone as proven cause was rejected; the code proves a starvation path, while the release acceptance test must establish end-to-end causality.

### Cross-family review

The single Claude/Fable read-only pass was invoked with a 20-minute hard timeout and closed stdin. It produced no output for ten minutes and consumed no CPU, so the hung process was stopped. No retry or substitute review was run, as required by the light flow.

Residual risk: external review did not run. The independent three-reviewer adversarial pass and refutation completed; live Quench acceptance remains the decisive integration check.
