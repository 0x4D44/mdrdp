# Activate changed native display driver

Status: SELF-APPROVED

## Scope

Make deployment install the cursor-capable IDD build instead of accepting a healthy
runtime whose active driver package is older. This covers MDR-BUG-FLU-00026 and the
missing package-identity change in MDR-BUG-FLU-00030. It does not replace the existing
versioned driver contract with content hashing or redesign driver-store cleanup.

## Approach and file impact

- Bump `tools/latency-spike/idd/driver/mdrdp-idd.inf` from 0.3.0.1 to 0.3.0.2 because
  the cursor-ownership work changed the shipped DLL.
- In `src/deploy.rs`, calculate the active/staged driver match before the fast path and
  require it as part of `exact_stack`. A same-size runtime with a stale package then
  takes the existing full-deploy path, which already signs and installs the driver.
- Bind the active-version probe to present IDD instance IDs. Multiple present instances
  are accepted only when they report one unambiguous version; ghost rows cannot decide.
- After the agent is stably green, re-run the uploaded probe and require the active driver
  version to equal the artifact version. Add focused plan and verification regressions.

## Acceptance criteria

1. A healthy, same-size, same-runtime-version host with active driver 0.3.0.1 and
   desired driver 0.3.0.2 cannot take the fast path and plans driver installation.
2. The same evidence with active driver 0.3.0.2 remains an idempotent fast path.
3. Formatting, focused deploy tests, Clippy, the Windows cross-check, and IDD build pass.
4. Integrated deployment installs 0.3.0.2 on Quench, retains 5120x2880/240/200 through
   the agent/driver restart, and ends with every health rung green.
5. A healthy agent whose live device remains on the old driver fails final verification.

## Decision log

- Driver package version is the existing deployment identity. Content hashing would
  widen the protocol and still would not make Windows select a same-version package.
- Keep the runtime at Rhydra 0.5.0. The changed wire contract is already compatible;
  only Windows driver selection needs a distinct package identity.
- Keep the INF date at 2026-08-20 and advance the version. Windows ranks date before
  version, so future package dates must never move backwards.
- Runtime executables still use size plus runtime version as their deployed identity.
  The general same-length runtime-artifact gap is real but outside this driver fix.

## Reviews

Two independent reviewers challenged the design and then refuted each other's findings.
Three findings survived: final green health does not prove package activation; the stale
regression must establish every other fast-path condition; and the active-driver query can
select an unrelated ghost row. All are incorporated above. Proposed extra no-device tests
were rejected as correctness requirements because a green agent already requires a present
device; staged-package-without-WDK already stops before mutation.

The single Claude/Fable review agreed with the direction. Its useful findings added the
post-deploy active-version oracle, monotonic INF-date rule, exact regression fixture, and
explicit same-length runtime residual. Its note about an absent agent leaving a device
present is retained as a live deployment risk: `pnputil /install` must update that device,
and the new final oracle will fail if it does not.
