# AVC444 responsive refinement presentation

Status: SELF-APPROVED

Bug: MDR-BUG-FLU-00124

## Goal

Keep fresh AVC444 picture content responsive during continuous motion while still hiding a standalone late chroma refinement until it settles.

## Scope

- Preserve the existing LC1/LC2 decode and colour reconstruction rules.
- Preserve the 100 ms settle window for quality-only LC2 updates after the visible picture is current.
- Make fresh-picture urgency survive later LC2 commits and coalesced window damage until one snapshot containing that fresh content is successfully presented.
- Keep existing frame atomicity, reveal behaviour, and large-canvas cadence.

Out of scope: RDP transport fairness, mouse event encoding, codec reconstruction, resolution negotiation, and changing the 33 ms large-canvas cadence.

## Root cause

`SurfaceStore` records only the latest generation's deadline. LC1 clears that deadline, but a later LC2 restores it. `DamageGate` deliberately coalesces notifications, so the window thread can observe only the final LC2 generation and never learn that fresh LC1 content arrived in between. Repeated LC2 commits then move the deadline forward throughout a drag.

## Approach

Add a small fresh-content epoch handshake:

1. `SurfaceStore` increments a `fresh_content_epoch` whenever an immediate visible generation commits. Deferred chroma-only generations retain the epoch.
2. `PresentationSnapshot` carries the epoch of the pixels it copied.
3. `SessionApp` remembers the epoch of the last snapshot that was successfully presented.
4. Every scheduling and copying decision uses a small `PresentationStamp { generation, fresh_content_epoch }` read under the store lock. A refinement deadline applies only when the store epoch equals the last-presented epoch. If they differ, fresh content is pending and only the refinement term is bypassed; the existing 33 ms large-canvas cadence still applies.
5. After a successful present, the app advances its presented stamp from the snapshot. A subsequent quality-only LC2 is again eligible for settling. A wrapping generation alone therefore cannot make a different fresh epoch look current.
6. Split active-frame deferral from retained aborted/suppressed state in `PresentationCopy`. If a redraw finds an active frame, do no rendering and retry after 33 ms through the existing redraw deadline. Do not retry an aborted frame: its partly mutated pixels are deliberately unpublishable until the session rebuilds presentation state.
7. If a platform present fails transiently, keep the stamp unacknowledged and retry after 33 ms. Mark platform/frame retries explicitly so timer dispatch does not discard a resize or reveal retry merely because the store stamp is unchanged. This preserves the existing roughly frame-paced failure policy; `Busy` keeps its existing faster compositor-backpressure retry.
8. Keep the last-presented stamp as an `Option` and update it only after a successfully presented `Copied` or `Empty` snapshot. Presenting a retained old/blank snapshot cannot manufacture an acknowledgement at the zero value.

This keeps urgency state beside presentation state, while the presenter owns the acknowledgement. It adds no queue, feature flag, or protocol state; both new liveness retries reuse the event loop's existing single redraw deadline.

## File impact

- `src/surface.rs`: fresh-content epoch state, snapshot propagation, deadline query, focused state tests.
- `src/window.rs`: last-presented epoch acknowledgement and end-to-end presentation-deadline tests.
- `wrk_journals/2026.08.26 - JRN - AVC444 responsive refinement presentation.md`: evidence and decisions.
- No expected changes under `vendor/` or in transport/input code.

## Acceptance criteria

1. Separate LC1 then LC2 commits coalesced before a redraw are immediately presentable and copy the latest refined pixels in one presentation.
2. Repeated LC2 commits cannot defer an unpresented fresh-content epoch.
3. After that epoch is successfully presented, a later LC2-only commit waits until its 100 ms settle deadline.
4. A frame containing any immediate visible mutation remains immediate; a refinement-only frame remains deferable.
5. Reveal still cancels an obsolete settle deadline and does not manufacture a generation or epoch change.
6. Existing large-canvas cadence, frame atomicity, and non-AVC presentation behaviour remain green.
7. A fresh epoch on a 5120×2880 canvas still waits for the 33 ms large-canvas cadence while bypassing only chroma settling.
8. An active-frame deferred copy and a transient platform failure each retain the pending stamp and arm a 33 ms retry; an aborted frame does not spin.
9. The regression test is observed failing against the current 0.1.237 behavior and passing with the fix.

## Decision log

- Keep the settle window. Removing or shortening it would trade the new starvation bug for the original chroma flicker.
- Do not fix this only in `SessionApp`. Once damage is coalesced, the window cannot reconstruct whether an LC1 occurred; the store must carry one durable bit of ordering information.
- Use an epoch rather than comparing wrapping presentation generations. Equality between producer and successful-present epochs is sufficient and avoids serial-number ordering rules.
- A successful platform present, not merely a store copy, acknowledges fresh content. Copying can precede compositor backpressure or a failed present.
- Treat generation and fresh epoch as one equality stamp at the presentation boundary. This is cheap formal wrap hygiene and makes every wake predicate express the same invariant.
- Retry only an active retained frame. An aborted transaction has mutated live pixels without rollback, so publishing or polling it would violate frame atomicity.
- Retry transient platform errors without acknowledgement. Otherwise an idle server can leave the last fresh epoch permanently unpresented.
- Represent the producer/presenter handshake as one stamp type rather than parallel loose values. Keep `generation()` for decode statistics, but use the full stamp for every presentation equality check.
- Use a 33 ms rate-limited active-frame poll rather than adding a producer-side frame-commit counter to session notification state. It keeps the edge local to presentation, does no rendering while the frame is active, and cleanly distinguishes terminal aborts through `PresentationCopy`.
- A retained presentation never acknowledges a stamp. This avoids treating a default blank snapshot as producer state that reached the platform.

## Adversarial review record

Two independent reviewers traced the design through the store, session wake, damage gate, copy, and platform-present paths, then each tried to refute the other's findings against the code.

Surviving findings folded into the approach:

- Critical: applying the epoch only inside `copy_presentation_when_due` is too late because `request_damage_redraw` can first arm the raw LC2 deadline. The effective refinement deadline must be epoch-aware at both scheduling and copying.
- Critical, narrowed on refutation: consuming a damage event during an active frame can retain the old snapshot and lose the wake if the frame ends without a generation change. A bounded active-frame retry is required. The proposed retry after every retained result was rejected for aborted frames because those pixels are intentionally unsafe to publish and would spin forever.
- Significant: resize, frame-acquisition, or present errors clear the only redraw deadline. Retry transient failures without acknowledging the pending stamp.
- Useful: freshness bypasses only chroma settling, not the pre-existing large-canvas cadence. Cover the combined case.
- Useful: include the epoch in generation-equality wake checks. Generation wrap is operationally implausible, but the full stamp is simpler and formally correct.

Held under refutation: frame commit ordering, snapshot coherence under the store lock, reveal clearing an obsolete refinement deadline, and `Busy` retry behaviour.

## External review record

A single read-only Claude/Fable pass approved the core epoch design with no critical unresolved issue.

Accepted:

- Specify retry cadence. Both active-frame and transient-error retries use 33 ms; `Busy` retains its 2 ms compositor retry.
- Distinguish active-frame deferral from aborted/suppressed retention in `PresentationCopy`, so the latter cannot poll forever.
- Use an optional coherent stamp and acknowledge only a successfully presented copied/empty snapshot.
- Name and test every scheduling, copy, deferred-service, and successful-present equality boundary.

Rejected:

- Add a producer-side frame-commit counter and teach `session.rs` to wake on it. That avoids polling, but widens one presentation edge into session notification and stats bookkeeping; a 33 ms active-only retry is smaller and remains idle for aborted state.
- Require the liveness edges to land as unrelated fixes. They may be separate green commits, but both are part of making successful-present acknowledgement live and are covered by this design and bug.

Residual risk: deterministic tests can prove state and deadlines, but only a built client against a real AVC444 server can confirm the subjective full-screen drag result.
