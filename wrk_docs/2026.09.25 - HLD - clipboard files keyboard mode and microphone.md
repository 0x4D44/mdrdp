# Clipboard files, Mac keyboard mode, and microphone

**Status: SELF-APPROVED**

## Scope and acceptance

Deliver three features for the ordinary RDP transport on macOS and Windows. Keep the
existing positional keyboard mode as the default. Do not change the native Rhydra
transport, add drive redirection, or add new dependencies without a separate decision.

1. A local file copied in Finder or Explorer can be pasted in remote Explorer, and a
   remote file copied in Explorer can be pasted locally. Multiple files and folders are
   included. Text and image clipboard transfers and
   clipboard direction policy keep working. File names, paths, and bytes never enter
   logs. Invalid remote paths, unbounded counts/sizes, stale responses, and partial
   transfers cannot escape a private staging directory or wedge later clipboard use.
   Check receive policy before requesting remote bytes. `arboard` needs real paths, so
   remote copy downloads eagerly even if nobody pastes locally. Set a clear total-size
   cap and show a visible failure when it is exceeded.
2. Settings offers **Mac keyboard mode**, off by default. With it on, printable keys
   and dead-key compositions send layout-resolved Unicode; navigation, editing keys,
   and Ctrl/Cmd/Alt chords keep scancodes. Press/release pairs, repeats, and focus-loss
   cleanup remain balanced. With it off, existing scancode behavior is unchanged.
3. With microphone capture enabled for a session, the default local input device is
   offered to the RDP host, and recorded PCM reaches a Windows recording application.
   Capture starts only after channel negotiation, stops on disconnect, and handles
   device denial/loss without stalling desktop input or audio playback. The setting
   defaults off so connecting does not activate a microphone unexpectedly.

Focused tests must fail once against the pre-change behavior, then pass. Verify both
platform builds, and verify each wire feature against a real Windows host; no mock-only
claim of protocol success. A failed or skipped live check remains an explicit risk.

## Approach and file impact

- `src/clipboard.rs`, `src/session.rs`: enable IronRDP's stream-file capability and
  wire its file-list, range, lock/unlock, and timeout callbacks into the existing
  epoch-based bridge. Call `Cliprdr::drive_timeouts()` from the session pump and send
  its resulting PDUs. `arboard` already reads and writes OS clipboard file lists on
  both target platforms. Snapshot local file identity and metadata for each clipboard
  generation and lock; open files lazily for bounded `SIZE`/`RANGE` requests and verify
  identity so path replacement cannot redirect an old request. For remote files, validate
  descriptors, fetch bounded chunks into a private per-transfer staging directory,
  check stream ID/index/offset/size/epoch on every response, and publish the complete
  file list atomically only after all files finish. Reject traversal, reserved Windows
  device names, alternate-stream colons, NULs, path/case collisions, symlinks, and
  unbounded counts or sizes before writing. Keep staged paths alive while the OS
  clipboard refers to them. A per-process staging root and lock prevent one session
  from deleting another live session's data. Startup cleanup touches only abandoned,
  aged roots that the OS clipboard does not reference; hold the same lock across the
  clipboard-reference check and deletion. Preserve text/image behavior
  and direction policy. Advertise a valid temporary directory to CLIPRDR.
- `src/input.rs`, `src/window.rs`, `src/settings.rs`, `src/shell/settings_ui.rs`: add a
  per-session RDP input mode and a key ledger that remembers which wire representation
  each physical key used. Use `KeyEvent.text` for ordinary printable presses and
  `Ime::Commit` for composed text, with explicit ownership to avoid duplicate emission.
  Enable IME only for RDP windows using this mode. Suppress keypress text while a
  composition is active; emit only committed text and clear composition on focus loss.
  Add a `Unicode { unit, down }` variant to the shared `InputEvent` but create it only
  in RDP windows when the setting is on; the native sender rejects it explicitly.
  Emit UTF-16 units through IronRDP fast-path; pair releases with the press units and
  release held units on focus loss. Keep scancodes for shortcuts. Session startup
  reads the stored toggle; do not add a command-line flag.
- `src/audio.rs`, `src/connect.rs`, `src/settings.rs`, `src/shell/settings_ui.rs`: use
  existing `cpal` for local capture and IronRDP's DVC plumbing. The installed IronRDP
  release has no MS-RDPEAI audio-input channel, so add the small local channel codec
  and state machine Arthur approved.
  Register the listener before MCS setup; a server-created DVC controls format
  negotiation and starts capture only after `OPEN`. Keep PCM conversion and capture
  off the session thread, with bounded queues and explicit stop on `CLOSE`/disconnect.
  The session writer must drain encoded audio without starving input or graphics. A
  new dependency is not planned.
- Update `README.md` to state the new support and correct its stale claim that
  favourites cannot be edited or removed. Keep a running implementation journal in
  `wrk_journals/`.

## Decision log

- Use the existing `arboard`, `cpal`, and IronRDP channel dependencies where possible.
- Keep the keyboard mode opt-in because the existing positional behavior is documented
  and used for server shortcuts.
- Keep microphone opt-in because enabling capture changes local privacy behavior.
- Arthur approved a small local MS-RDPEAI channel and both files and folders on
  2026-09-26. These were the two architectural/scope decisions held at the checkpoint.
- Adversarial review confirmed that file capabilities/callbacks and IronRDP's own
  timeout drive must be in scope. It also confirmed filename validation, lock-scoped
  source snapshots, exact stream correlation, and staged-file lifetime as correctness
  conditions. The keyboard path must keep Unicode out of the native transport and
  use a single source for each committed character.
- One Claude review confirmed that startup cleanup must respect other live sessions,
  and that remote file copy is necessarily eager with `arboard`. Its direction-policy
  finding is accepted: check before fetching bytes. Its lazy-open suggestion avoids
  pinning many handles. Its macOS microphone permission point is a live-validation
  risk: the repo currently ships a bare binary, so capture must be tested in that
  launch shape and any required packaging change becomes a separate design decision.
- The single targeted re-review found the cross-session cleanup correction sufficient
  and required the same lock to cover publication and the cleanup check/delete step.
