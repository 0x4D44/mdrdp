# DECISION — Phase 0 forks resolved

## Fork 1 — scoreboard-first becomes per-dimension

**Decision: option C.** The charter's rule that the measurement harness is proven against
Microsoft's client before anything it judges now applies **per dimension, at the moment
that dimension is first judged** — not globally, up front.

Option A (build the full reference A/B harness across every graded dimension before any
other work) would block the entire project behind measurement infrastructure we cannot
yet exercise: several dimensions can only be measured against a running mdrdp session,
which does not exist. It would also front-load a large build against requirements we
understand least.

The substance of the rule is preserved exactly: **no part is judged without its
dimension's reference baseline existing first.** What is dropped is only the demand that
every baseline exist before any part is built. A critic evaluating P5's clipboard
reliability still needs the reference client's clipboard behaviour measured first — it
just does not need P8's audio baseline to exist at the same time.

**This is a charter amendment**, and it is the second one. Both are recorded rather than
silently applied.

## Fork 2 — critic-owned soaks, but only where time is the requirement

**Decision: refine, don't accept wholesale.** A Gauntlet critic must own the experiment —
start the binary, fix the seed, hold the artifact — for parts whose requirement is
*inherently temporal*. That is P4 (latency drift, ≥4 h) and P5 (clipboard, ≥8 h). For
those, the wall-clock cost is unavoidable: the defect being tested only appears over
hours, so there is no shorter honest experiment.

**P6 does not need a soak at all, and my plan mis-specified it.** The window-policy
requirement is not "survives eight hours"; it is "survives a display-configuration
*event*" — sleep, monitor power-off, lock/unlock, wake. Those are events that script in
minutes, and a randomised sequence repeated many times is *better* evidence than one long
wait, because it samples the transition repeatedly rather than once. Reclassified from
soak to scripted event sequence.

That reduces the cost of Fork 2 from three long-running parts to two, and improves P6's
evidence at the same time.

## Direction — P2 is next

The critical path is now genuinely unblocked:

- A credential exists in the keychain, and P1b confirmed the account authenticates as a
  bare `user@example.com` with no domain prefix.
- P1a confirmed `ironrdp-connector` handles the Early User Authorization Result PDU that
  HYBRID_EX requires, so the connector should drive this host without custom work.
- P0a is integrated, so the protocol and statistics primitives exist and are tested.

**P2 — authentication and connect** is therefore the next part: keychain → TLS with
trust-on-first-use pinning → CredSSP → MCS → licensing → capability exchange, ending at
Demand Active / Confirm Active, then through connection finalization and Save Session Info
(which P2b's reconnect work depends on for the auto-reconnect cookie).

**P2c follows immediately** and is where the codec question is finally settled: our own
`RDPGFX_CAPS_ADVERTISE` / `CAPS_CONFIRM` exchange over drdynvc, showing what `temper`
returns to *IronRDP's* offer rather than FreeRDP's.

## Standing note on evidence

P1b established that raw FreeRDP traces are ~1.1 MB of session content and do not belong
in the repo. The same applies to anything P2 produces: evidence is a payload-free protocol
event trace — PDU type, negotiated flags, timings, sizes, build identity — never a
capture of the session itself.
