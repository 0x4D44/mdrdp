# HLD — rhydra tranche 2: `mdrdp deploy`

## 1. What this tranche delivers

`mdrdp deploy <host>` — one idempotent command that takes a Windows host from
"reachable over SSH" to "rhydra agent installed, healthy, and reporting",
replacing the hand choreography currently spread across `idd/deploy.ps1`,
scp'd binaries, and ad-hoc schtasks calls. It is the opt-in that makes tranche
3's auto-detect safe: rhydra exists only on hosts Arthur has deployed to.

Also in scope, because deploy's verify step needs them: on `rhydra-agent`, a
`status [--wait <secs>]` verb and three `uninstall` robustness fixes; on the
control protocol, a `version` field in `StatusReport` (schema 2).

Out of scope: `--native` connect (tranche 3), health rungs beyond agent status
(tranche 4), any host mutation of credentials/logon config, reboots (none are
needed — see §2 Driver).

## 2. Shape

### CLI

```
mdrdp deploy <host> [--user <ssh-user>] [--artifacts <dir>] [--dry-run] [--force]
```

- The `deploy` branch is **the first statement of `run()`** — before the
  `--help`/`--version` scan, before the flag loop, and before
  `detach::should_detach` (a detached deploy would strand ssh prompts on a
  null stdin). Deploy owns its own arg parse and help. A favourite literally
  named `deploy` is reachable via the existing `mdrdp -- deploy` escape hatch.
- `--user` here is the SSH login (defaults to ssh config's); it never touches
  the RDP keychain. Same flag name, disjoint parse — documented in help.
- `--artifacts <dir>` points at the cross-built outputs (default: located
  relative to the repo checkout). Missing artifacts is a hard, instructive
  error naming the two `build.sh` scripts; deploy never builds.
- `--dry-run` prints the preflight evidence, the chosen branch, and the exact
  action list, then stops.
- `--force` overrides the live-session refusal (below).

### Remote layout — versioned, per parent §5

```
C:\mdrdp\
  v<version>\   rhydra-agent.exe, rhydra-server.exe, mdrdp-idd-create.exe,
                driver\ (mdrdp_idd.dll, mdrdp-idd.inf), scripts\ (uploaded .ps1)
  logs\
```

Copy lands in a fresh `v<version>\` directory and **never collides with
running images**; the onlogon task registered by that directory's
`rhydra-agent.exe install` is the "stable pointer". Previous version
directories are kept (rollback = re-run that version's `install`). A failed
copy leaves the old agent running and untouched.

### Phases (each phase re-probes; decisions are pure functions of evidence)

**A. Preflight (read-only, all gates up front — nothing mutates until it
passes).** Gathered over SSH, every non-trivial probe an uploaded `.ps1` run
via the absolute interpreter path (`C:\Windows\System32\WindowsPowerShell\
v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass -File …`) so the
login-shell identity is irrelevant; each script prints a `RHYDRA-OK` sentinel
and an explicit exit code, and deploy requires both. Evidence collected:

1. Reachability + elevation (`whoami /groups` must show High Mandatory Level
   — verified live on quench 2026-08-18: Windows OpenSSH grants admin users a
   full token).
2. Interactive console session present, and its user matches the SSH user
   (the onlogon task binds to the installing principal; mismatch is a stop
   with explanation, not a silent misregistration).
3. Agent state: `v<current>\rhydra-agent.exe status` where present; when the
   control port answers nothing, who holds 9502/9500 (name the holder — a
   rig-era server or foreign process is a stop-and-say, never a silent kill).
4. Driver/device evidence, gathered **before any quiesce** (the device dies
   with the creator, so this is the only moment it is observable): device
   present per the running agent's `device_present`, or driver staged at the
   artifact's `DriverVer` (typed check via `Get-PnpDevice`/`Get-WindowsDriver`
   JSON — never parsed pnputil prose).
5. Local: artifacts present and complete; their version string.
6. Live-session guard: if the agent reports a running server, refuse without
   `--force` and say the deploy will drop the virtual display and any native
   session.

**B. Copy** — `scp` into the fresh `v<version>\` tree; sizes verified after
copy. (Byte-identical fast path: if the target version directory already
exists with matching sizes and the agent answers healthy at that version,
skip C–E entirely and go to F — the true no-op.)

**C. Driver (only when preflight says absent/stale).** No testsigning gate
and no reboot path: mdrdp-idd is **UMDF**, and user-mode driver policy loads
it on the certificate chain alone — proven live on quench 2026-08-18
(testsigning OFF in bcdedit, driver serving DISPLAY8 all evening; cert
`CN=mdrdp latency spike` in machine root + trustedpublisher, expires
2027-08-17). The arm runs the productised install script (cert create/reuse,
`Inf2Cat`, `signtool`, `certutil` trust, `pnputil /add-driver`), gated in
preflight on `Inf2Cat.exe`/`signtool.exe` presence. `DriverVer` is the
identity: same-version re-adds are reported "current", a dll change without a
DriverVer bump is a loud authoring error.

**D. Quiesce (after copy, before install).** Unconditional whenever any
`rhydra-agent.exe` exists on the host, keyed on presence, never on the
control port answering. Uses the agent's own `uninstall`, hardened this
tranche: (a) `schtasks /delete` "task not found" counts as success; (b) the
no-port arm also kills other instances of the agent image (PID-excluded
filter) — a wedged or starting agent no longer survives; (c) the clean arm
polls until the port refuses/process exits (bounded ~15 s) instead of a
blind 2 s sleep.

**E. Install** — `v<version>\rhydra-agent.exe install` (registers the onlogon
task at the new path, starts it now).

**F. Verify — stable green, not first green.** `rhydra-agent status --wait
<secs>` (new verb, poll loop lives in the agent client, not deploy's runner):
green means `device_present && mode_ok && server.running` **in two samples
≥3 s apart with identical `server.restarts` and `last_exit_code`** — a
crash-looping server shows one green tick per cycle and must not pass.
Additionally the reported `version` must equal the deployed version (else the
old agent survived and the deploy lied). Bound ~30 s (2 s ticks, first
bring-up measured well inside). Failure diagnosis names the console-session
precondition first — the known environmental cause.

**G. Report** — what deploy itself consumed and concluded: elevation, console
session/user, driver state, agent version + health. The wider posture
checklist (auto-logon, lock policy) is tranche 4's, when something consumes it.

### `rhydra-agent status [--wait <secs>]`

Connects to `127.0.0.1:9502`, polls `{"cmd":"status"}`. Without `--wait`: one
sample, print the line, exit 0 green / 1 not-green-yet (prints the `stuck`
step) / 2 no answer. With `--wait`: poll until stable-green (the two-sample
rule) or deadline; same exit codes. Exit 1 is explicitly "not green yet", not
"broken" — bring-up walks through `stuck: creator → device → display-mode →
server` by design.

## 3. Code shape and testability

- `src/deploy.rs` (portable, no `cfg`): arg parse; `Evidence` (preflight
  facts, deserialized from the probe scripts' JSON); pure decision functions
  `fn branch(&Evidence, &Artifacts) -> Result<Vec<Action>, Stop>` where
  `Action` is **closed at `Run(remote command)` / `Copy(local, remote)`** —
  no control-flow variants, ever; a thin runner that shells `ssh`/`scp` and
  stops on first failure; embedded `.ps1` sources as string constants.
  Unit tests: expected-input/output over the decision functions (given
  "agent wedged / driver current / session absent", assert the exact action
  list or stop), parser fixtures from real quench JSON, arg-parse table.
- Verify and the byte-identical fast path are their own functions consuming
  fresh probes — deliberately *not* `Action`s; `--dry-run` prints evidence,
  branch, actions, and names the later re-probe points honestly.
- Server crate: `control.rs` `StatusReport.version` (schema 2, filled from
  `CARGO_PKG_VERSION`), a small blocking `query_status(addr)` client helper
  (portable, testable); `bin/agent.rs` gains the `status` verb and the three
  `uninstall` fixes.
- `src/main.rs`: the early `deploy` branch, nothing else.

## 4. Acceptance criteria

1. `mdrdp deploy quench --dry-run` prints evidence, branch, and action list
   with zero side effects — asserted by decision-function tests, observed live.
2. Live deploy to quench lands `v<version>\`, registers the task, and verify
   passes the stable-green rule with the new version string — observed live.
3. Immediate re-run takes the byte-identical fast path: no quiesce, no
   display drop, verify-only — observed live (a true no-op, not "no-op-shaped").
4. Deploy over a running agent replaces it without manual intervention
   (quiesce proves itself) — observed live.
5. `status` exit codes 0/1/2 and `--wait` stable-green semantics — unit tests
   plus live observation of a bring-up walking stuck steps to green.
6. Verify provably rejects a crash-looping server: unit test drives the
   stable-green rule with a restarts-incrementing status sequence and
   asserts failure. (The live analogue is not manufactured on quench.)
7. Preflight stops, mutating nothing, on: missing artifacts; no console
   session; foreign 9502/9500 holder; live server without `--force` — unit
   tests over the decision functions; the `--force` arm observed live.

## 6. Decision log

1. Deploy never reboots and never writes credentials/logon config; all gates
   are preflight, so a stopped deploy has mutated nothing.
2. Artifacts are prerequisites, not build targets.
3. Versioned host directories (parent §5 restored after review): copy is
   collision-free, rollback exists, quiesce shrinks to the install window.
4. Agent lifecycle stays the agent's own verbs, hardened rather than
   bypassed; deploy adds no second lifecycle mechanism.
5. `status`/`--wait` lives in the agent client so deploy's runner stays a
   dumb action executor.
6. Driver needs no testsigning: UMDF + trusted cert, proven live on quench.
7. Remote execution: uploaded scripts by absolute interpreter path, sentinel
   + exit code both required; no pnputil/bcdedit prose parsing anywhere.
8. Posture reporting cut to what deploy consumes; the rest arrives with the
   consumer (tranche 4).
9. `Action` enum closed at Run/Copy; decisions are pure functions; verify is
   not an action. Ceremony trimmed to exactly the dry-run's needs.
